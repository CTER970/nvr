## 5.1A · VI/ISP/VENC/RTSP的位置、输入和输出

源码：`edgefusion_vision/sample/sample_rtsp/sample_rtsp.c:1273-1319,1327-1524`，只看函数调用名与顺序  
时间盒：10分钟四模块 + 10分钟主/子码流 + 5分钟表格 + 5分钟闭卷

### 最小脚手架

```text
MIPI CSI图像 → VI采集通道 → ISP图像处理
→ VENC硬件H.264/H.265编码 → RTSP服务发出压缩码流
```

### 引导问题

1. VI、ISP、VENC、RTSP每个模块的输入/输出数据形态是什么？
2. VENC是RISC-V CPU上的软编码函数，还是独立硬件引擎由CPU配置？
3. `AW_MPI_SYS_Bind(ViChn, VeChn)`建立了哪两个通道的数据关系？
4. 主码流、子码流和延时摄影码流是同一个码流吗？哪些结构字段表明它们独立？
5. 这一遍为什么不需要搞懂`AW_MPI_VI_SetVippAttr`每个SDK参数？

### 通过标准

- 能闭卷画出四段数据流，每条箭头标“原始图像/处理图像/压缩码流”。
- 能准确说“RISC-V CPU核运行应用与配置，VENC硬件引擎承担编码”。

## 5.1B · `main()`生命周期与`getVencStreamThread`数据交付

源码：`sample_rtsp.c:982-1268,1273-1723`  
时间盒：15分钟准备/创建 + 15分钟启动/取流 + 15分钟停止/逆初始化 + 15分钟闭卷

### 阅读分块

```text
参数/配置
→ SYS初始化
→ 为各码流创建VI/ISP/VENC并Bind
→ Enable VI + Start VENC + rtsp_open + 启动取流线程
→ GetStream → 识别I/P帧 → rtsp_sendData → ReleaseStream
→ 等待退出
→ join → stop/destroy channel → stop ISP/SYS → rtsp_close
```

### 引导问题

1. 创建、启用、开始接收图像是三个不同阶段吗？对应调用是什么？
2. `getVencStreamThread()`中`GetStream/ReleaseStream`如何类比V4L2的`DQBUF/QBUF`？类比的边界是什么？
3. SPS/PPS在哪里获取？I帧时为什么要考虑将它们交给RTSP客户端？
4. 取流线程读到的是YUV原始帧还是H.264/H.265压缩包？
5. 为什么停止时先设退出标志并join，再销毁VENC/VI资源？
6. 初始化和反初始化的顺序是否大致逆序？找一对证据。
7. 源码有大量厂商参数，哪些属于本阶段必须理解的生命周期边界？

### 必交与通过

- 交启动与停止对称图，及主线程/取流线程泳道图。
- 能闭卷复述`GetStream → rtsp_sendData → ReleaseStream`，说清buffer使用期。
- 不需要默写任何eyesee-mpp结构体字段。

## 5.1C · 端/边/云边界闭卷验收

## 6.3 · 5个改进点与项目边界

时间盒：20分钟候选清单 + 30分钟论证 + 20分钟排序 + 20分钟口述

### 改进卡固定格式

| 字段 | 要求 |
| --- | --- |
| 现状证据 | 真实源码行/日志/测试 |
| 风险 | 对数据、延迟、稳定性、安全或可维护性的影响 |
| 改法 | 组件、线程、数据结构或API级方案 |
| 代价 | CPU/内存/延迟/依赖/复杂度 |
| 验证 | 正常、异常、负载下的可测量标准 |

候选优先从已审计证据中选：AVCC解析、RTSP慢客户端、JPEG快照一致性、Packet写入码率统计、Web短写、Range 416、异步启动结果、配置目录fsync、云AI退避/去重。

### 通过标准

- 5项均有现状、风险、改法、代价、验证；不得只说“加锁/加队列/做优化”。
- 能根据岗位相关性、风险和实现成本排优先级。

## 6.5 · Ubuntu/板端工程证据包

此任务在Ubuntu主机或IMX6ULL上执行；Windows本机只能准备命令和检查证据，不能伪装编译通过。

### 必收集证据

| 类别 | 证据 |
| --- | --- |
| 工具链 | 编译器版本、Make命令、完整成功/失败日志 |
| 产物 | `file/readelf`证明ARM ELF架构、动态依赖 |
| 启动 | 配置路径、进程/线程、关键初始化日志 |
| 视频主链 | RTSP连接、MP4段产生、断流重连、录像可播 |
| 媒体输出 | MJPEG预览、Range 206、本地RTSP转发 |
| 事件 | 云失败降级、成功事件、SQLite、快照、GPIO禁用/触发 |
| 资源 | CPU、RSS、磁盘增长、连续运行时间，附采样方法 |

### 必做异常测试

1. 中断RTSP源后恢复，记录发现、等待、重连时间。
2. token空或端点错误，验证录像和预览仍工作。
3. 客户端中途断开MJPEG/MP4/RTSP，检查进程仍存活且fd不持续增长。

### 通过标准

- 每个结论有命令、时间戳、原始输出/截图和一句结论。
- 将“未执行”、“失败”、“静态完成”、“板端通过”明确区分。
- 不隐藏失败日志；失败也是工程证据，但不计为通过。
