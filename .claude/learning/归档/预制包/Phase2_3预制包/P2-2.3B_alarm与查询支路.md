## 1. 任务目的（四层）

① C2 的 while 谓词/signal 在此逐行落地，并回答「同一事件为什么走两条支路」（即时订阅报警 vs 延后查询展示）。② 项目背景：alarm 是「回调只登记、线程消化」模式的完整样板；web 查询支路证明事件总线是「拉」不是「推」——两者合成链路 C 的末端。③ 岗位背景：「GPIO/外设控制放哪个线程」「回调里能做什么」是嵌入式实做题；SQLite 分页查询是全栈小标配。④ 学完本卡，Phase 2 三模块闭环，2.5 总验收材料齐。

## 2. 数据流坐标

支路1（推）：`publish(锁外)→on_event(发布者线程)：类型+置信度过滤→锁内置 g_pending→signal` → `alarm_thread(报警线程)：wait→取走→GPIO高→sleep N 秒→GPIO低`。
支路2（拉）：`浏览器 GET /api/events → web客户端线程 → event_bus_query_filtered(锁内查) → JSON 返回`；`/api/event/<id>`+`/snap/evt_<id>.jpg` 同理。

## 3. 锚点（已实测）

**web.c**：serve_events 450-509（limit/offset/type 参数解析 454-471、`event_t evs[64]` 栈数组 473、循环拼 JSON+realloc 扩容 477-505）/ serve_event_detail 513-531 / serve_snapshot 535-569（`sscanf("evt_%ld.jpg")` 白名单校验 542）。

## 4. 卡内前置（铁律 21/22）

- **GPIO**（1 分钟）：芯片引脚电平输出，Linux 用户态经 `/sys/class/gpio`（export→direction→value）；`-1`=该路禁用（conf 默认即 -1，c:75-76）。
- 词源：`sysfs`（内核对象映射到文件系统的接口）；`pending`（待处理）；`strtok`（string tokenize 按分隔符切串——会破坏原串，所以先拷到 buf c:65）。
- 迁移：单槽 vs 队列（Phase 1 最新帧同款选型）；「拉 vs 推」对照 stream_receiver 三分发（那是逐包推）。

## 5. 引导问题（手册精选）

1. on_event 为什么不直接 sleep+操作 GPIO？（跑在发布者线程——拖 AI 采样；C2 全落地）
2. g_pending 是队列、计数器还是单槽？连续事件逐个保留吗？（单槽取最近 active_s，c:81——报警期间的合并语义）
3. GPIO 延时期间又来事件会怎样？（pending 再置数；当前周期结束重新拉高=接续报警）
4. alarm 的 GPIO=-1 时：不建线程还是 gpio_set 无操作？（照建线程照订阅，仅写值被 c:44 挡——设计统一性）
5. Web 事件列表是推送还是查询？证据？（HTTP 请求到来才查库；无任何反向通知通道）
6. serve_snapshot 为什么要 sscanf 校验名字？（防路径穿越——与 web.c:141/384 的 `..` 防护同族）
7. 一次 /api/events 在 event_bus 锁内做什么？谁可能正在持有那把锁？（查询期间发布者/其它查询被挡——2.3A 审计①回响）

## 6. 产出与通过标准

四泳道时序图补全（AI/报警/web 客户端/主线程）、event_t 有效期表（栈对象到回调返回为止）、条件变量伪代码默写。通过=区分「即时订阅支路 vs 延后查询支路」+ 对着代码说出 while 两个条件各自用途。cond 理论以 C2 为准，本卡不重复验收 V2。

## 7. 闭卷与变式（已过深度滤网）

- 闭卷：默写 alarm_thread 循环骨架+每秒 sleep(1) 而不是 sleep(wait_s) 的原因（可中断退出，≤1s 停止延迟）。
- V1：GPIO=-1 时线程还在吗？（在；只是 gpio_set 被 c:44 挡——设计统一性）
- 提升池：on_event 无锁读配置（审计⑤，一句话）；strtok vs strstr 子串误配；gpiod 新接口。

## 8. 预制时审计发现（核实后用）

⑤on_event 无锁读配置（c:79 vs reload c:157-164）；⑥g_pending 单槽合并（c:81）；alarm_stop join 等待 ≤~1s（c:106 每秒查 running）——与 cloud_ai stop（可达 30s）成对出题，预埋 2.4。

## 9. 快问快答

1. 报警期间 g_running=0，蜂鸣器会响完吗？（不会——sleep 循环每秒查，复位在循环外 c:107-108 由线程自己执行；stop 之后再强制复位一次 c:149-150 双保险）
2. 为什么 signal 要在锁内？（C2-V3 落地：防「查完谓词到睡下」窗口丢失）
3. alarm_reload 改阈值，正在等待的线程需要通知吗？（不需要——下次事件自然用新值）
4. /api/events?limit=200 实际返回多少条？（evs[64] 截断——c:473-475 配置意图 vs 实然）
5. 事件 JSON 的 snapshot 字段哪来的？为空说明什么？（jpeg_path 文件名；快照失败或无图）
