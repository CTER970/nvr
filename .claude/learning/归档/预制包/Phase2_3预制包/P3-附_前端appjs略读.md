## 1. 任务目的（四层）

① 前端是所有 HTTP 卡的「另一半」：谁在轮询、谁发的 Range、快照失败浏览器显示什么——后端卡的问题在前端有直观回声。② 项目背景：单页管理界面（hash 路由）+纯轮询，零框架零构建——`serve_static` 的存在意义和 4096B/短写等边界的受益者。③ 岗位背景：全栈沟通语言；「前后端怎么配合定界」在 NVR 面试里常被顺带一问。④ 学完闭环链路 D 的完整视图（浏览器→HTTP→各模块→屏幕）。

## 3. 引导问题（3 问即可）

1. 前端怎么「知道」流断了？断线后靠什么恢复？（轮询 status 的 connected；重挂 img src——注意这是**前端自愈**，与后端无推送）
2. 点开一个历史录像，Range 请求是谁发起的？（浏览器 video 标签——3.3 的客户端发起者在前端找到实体）
3. 事件卡片上的「无图」什么时候出现？（onerror=快照文件缺失/快照失败——把 2.3B「DB 成功快照失败」矩阵补上前端表现列）

## 4. 与后端卡的五个呼应（本卡核心价值）

1. `<img src="/stream">` ↔ 3.2 multipart：MJPEG 的消费端就是一行 HTML。
2. `v.src='/rec/'` ↔ 3.3 Range：拖动进度条时 video 自动发 `bytes=a-b`。
3. `onerror` 无图 ↔ 2.3B 快照失败：降级路径终于到屏幕。
4. FormData 整表单 ↔ 3.5 审计⑩：GET 回显的掩码值原样 POST 回去=token 被污染的完整事故链。
5. 4s 轮询 ↔ C4 无状态：没有 websocket/推送，页面新鲜度=轮询周期。

## 5. 通过标准（L1）

能口述「页面切换靠 hash、数据靠轮询、媒体靠原生标签」三句话 + 五呼应任指三个说出对应后端行为。不读 style.css、不逐行读 DOM 拼接。

## 6. 快问快答

1. 前端改了配置但没生效，先查哪三个地方？（POST 是否 200 / 字段是否在热更新五项 / 消费者是否重读——2.4 法则前端版）
2. 为什么 app.js 带 `?v=3`？（静态资源缓存破坏——与 mime_type/Cache-Control c:171 同议题）
3. 页面打开多久能发现后端挂了？（≤4s 轮询失败+img 断流）
