## 1. 任务目的（四层）

① 回放体验的机制核：大 MP4 分段拉取+进度条拖动全靠 Range——链路 A（录像）的出口。② 项目背景：fMP4 段文件（Phase 1）+ Range 服务器=完整回放方案；「Range 与 MP4 内部索引（moof）是不是同一层」是本卡最值钱的概念分界。③ 岗位背景：Range/206/416 是 HTTP 高频题，手算 Content-Range 是硬通货；「seek 为什么快」连接存储与协议两层。④ 学完手工走 3 个样例，3.4 socket 卡收尾后 Phase 3 媒体面完整。

## 2. 数据流坐标

链路 A 出口：`浏览器拖动进度条 → GET /rec/<name> + Range: bytes=a-b → serve_file：open→fstat→解析→lseek(start)→循环 read/send(32KB)→close`。

## 4. 卡内前置（铁律 21/22）

- **HTTP Range**（卡内讲）：请求头 `Range: bytes=1000-1999`（闭区间，字节偏移）；响应 206+`Content-Range: bytes 1000-1999/5000`+`Content-Length: 1000`；客户端未带 Range→200 全文；标准里越界应 416。
- 词源：`partial`（部分的）；`Accept-Ranges`（服务器声明自己支持 Range 的头）；`lseek`（locate seek，把文件读写指针定位到偏移——对照 V4L2 的流偏移 ioctl 家族）。
- 关键分界（预答手册 Q7）：Range=**传输层**字节切片（对任何文件都成立）；MP4 moof/stss=**内容层**索引（哪一秒在哪个字节）。拖动时两者接力：播放器先用 moof 算出目标时间≈字节位置，再发 Range 去取。

## 5. 引导问题（手册 7 问照用）

1. 无 Range 返 200 还是 206？带 `bytes=1000-1999` 时 start/end/length 各多少？（演算）
2. Content-Range / Content-Length / Accept-Ranges 各怎么写？（三头分工）
3. 为什么 lseek 而不是从头读再丢弃？（O(n)→O(1)——大文件拖动毫秒 vs 秒）
4. 只给 start 不给 end / end 超文件 / start 超文件——代码各怎么处理？（end 保持 total-1 / 钳到 total-1 / **重置 0**）
5. start 越界重置为 0 而非 416，客户端如何解读？（收到 0-end 全文当作有效响应——语义错位：想跳 90% 却从头播；标准浏览器遇到 200 会自己再切——一句话）
6. 循环怎么不越过请求范围？处理短写吗？（want 钳制；send<0 break——短写不重发，审计⑦同病）
7. Range 与 MP4 内部索引是否同一层？（见前置「关键分界」——学生先答再对）

## 7. 闭卷与变式（已过深度滤网）

- 闭卷：默写 Range 解析四分支（无头/有头无end/end越界/start越界）与各自响应码。
- V1（演算变式）：文件 10000，请求 `bytes=-500`（后缀式，最后 500 字节）——当前代码结果？（strtol("-…")=0→start=0、dash 后无数字→end=9999→全文 206——标准语义应 9500-9999；实现与标准的偏差，审计素材）
- V2（连接 3.2）：为什么 MJPEG 不需要 Range 而 MP4 需要？（流无终点无历史；文件有限可索引）
- V3（连接 Phase 1）：fMP4 的 frag 结构为什么让 Range 拖动更友好？（frag 自带索引密度高→播放器定位快——一句话连接，不重学）

## 8. 预制时审计发现（核实后用）

start 越界重置 0（c:406）非标准 416；后缀 Range `bytes=-N` 未实现（V1）；短写不处理（c:442）；多区间 `bytes=0-1,5-9` 只取第一段（strtol 语义，一句话）。

## 9. 快问快答

1. Content-Length 在 200 和 206 里分别等于什么？（total / e-s+1）
2. 为什么响应要主动带 Accept-Ranges？（告知客户端「可以拖」——浏览器据此启用进度条 seek）
3. 同一文件并发两个 Range 请求，文件会被读乱吗？（各自独立 fd+偏移——fd 即游标，C3 呼应）
4. read 返回 0 意味着什么？此时 sent<content_len 说明什么？（EOF；文件在会话中途变小/被清理——半截响应）
