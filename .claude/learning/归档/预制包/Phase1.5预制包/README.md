## 审计层五项缺陷·一句话结论(处置修订指定掌握;各块「重逢绑定」按需引用,原文档 Phase1.5 手册)

1. **RTCP 仅端口骨架**:c:452/457/462/469–472 建 udp_rtcp_fd、bind、记录对端地址,全文件无任何 RTCP 收发——「支持 RTCP」应表述为"预留端口对、无反馈逻辑"。
2. **AVCC 声称支持实未实现**:注释 c:49–50 声称解析 avcC,实现 c:70–92 偏移与规范错位(numSPS 规范在 byte5、首个长度在 byte6–7,代码读 byte4/byte5 起),真实 avcC 输入必解析错;本项目 RTSP 源 extradata 实为 Annex B,该分支基本不触发。
3. **SPS/PPS 硬编码缺省**:c:145–146(缺省 base64);extradata 提取失败时 SDP 携带与真实流不匹配的参数集→客户端解码失败;且只收首组(c:123)、只在启动收集一次(stream_receiver.c:134 `!g_rtsp_inited` 守卫),分辨率中途变化不会更新。
4. **无 PTS 回退恒 0**:c:301–303,pts=NOPTS 时 ts 恒 0,客户端失去播放节奏依据(注释 c:302 声称"ssrc 基址+自增"但代码就是 0;ts_base 字段 c:168 存在未用)。
5. **慢客户端持锁阻塞**:on_packet 持 g_mtx(c:309)期间对 TCP 客户端走阻塞 send_all(c:190–199)→慢 TCP 客户端拖住拉流线程;fail_count>3(c:320–325)只处理已返回错误、防不了阻塞中,且只置 playing=0 不 close 不摘链表;rtsp_server.h:16「非阻塞发送」注释与实然矛盾。

附加观察(非五项,顺手记录):deinit c:597–598 连续两行重复 `if (!g_running) return;`(死代码);handle_client c:380–383 先 set_nonblock 再立即恢复阻塞(绕一圈,注释自述"阻塞更简单");MAX_CLIENTS=8 定义未使用(客户端数量无上限,靠系统资源兜底)。
