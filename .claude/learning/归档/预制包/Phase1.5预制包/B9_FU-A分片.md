## 1. 任务目的与意义(四层)

① **为什么存在**:一个 IDR 帧 NALU 常有几十 KB,而单个 UDP 包受 MTU 限制(以太网约 1500B)——**应用单元远大于传输单元**,必须分片。不做应用层分片,IP 层会替你分,但 IP 分片"一片丢、全片丢"且不可控;FU-A 让每片独立成包、单片可容忍。这是组四的终极问题,前面四块全部为它铺路。
② **项目背景**:本项目完整实现了 FU-A(c:237–277)——indicator 继承 F/NRI(c:239)、原 type 进 FU header(c:255)、S/E 置位(c:256–257)、尾片才置 M(c:248)。面试讲"自研 RTP"时,这一段是最硬的细节证据;答得出"为什么要跳过原 NAL 头"直接证明真读过。
③ **岗位/面试**:「大 NALU 怎么发?FU-A 结构?为什么要跳过原头?」是 H.264/RTP 岗位高频题,也是本阶段手册钦点的 RFC 直读点。
④ **学完能做**:手工把 4000B NALU 切成 FU-A 序列并标每包 S/E/M/seq/ts;讲清接收方重组过程;组四收官。

## 2. 前置概念声明(铁律21)

本块机制=**分片-重组(fragmentation/reassembly)**:应用单元>传输单元时的通用解法——发方切+标序、收方拼。同族:TCP 分段、IP 分片;差异:应用层分片(本块)每片独立、自带重组信息,IP 分片无应用语义。新机制点:**传输层附加头**(FU indicator/FU header 共 2 字节)——放在 RTP 载荷开头、由 PT 约定解释(RFC 6184 定义了单 NAL/STAP-A/FU-A 几种"载荷格式",FU-A 是其一)。

## 3. 标识符词源解析(铁律22)

- **FU-A** = Fragmentation Unit type A。Fragmentation=分片,Unit=单元,type A=A 型(FU-B 允许交错已弃用);RFC 6184 §5.8 定义。
- **MTU** = Maximum Transmission Unit,最大传输单元:链路层单帧载荷上限(以太网 1500B);IP 头 20+UDP 头 8 后,UDP 可用约 1472B;项目取 1400 留余量(c:26)。
- **FU indicator** = 分片指示器:1 字节,结构同 NALU 头(F/NRI/type=28)。
- **FU header**:1 字节,S=Start(首片)、E=End(尾片)、R=Reserved(保留,0)、低 5 位=**原 NALU type**。

## 4. 类比锚点

FU-A=**大件拆包裹**:一张 2 米的书桌(大 NALU)拆成 3 个小包裹(FU 包)寄快递;每个包裹贴 2 字节小票——第 1 字节"这是一件拆开的大家具、原优先级 3 星"(indicator,F/NRI 继承+type28),第 2 字节"第 1/中/最后一件 + 原来是书桌"(FU header,S/E+原 type)。收货人拼完 3 件,重写一张原始面单(重组出头)。(B3 陷阱 2 回收:0x7C 不是新货物,是拆件标签。)

## 5. 五件套草稿

- ① 一句话:NALU 大于单包上限→跳过原 1 字节头,载荷分片;每包 = 12B RTP 头 + 1B FU indicator + 1B FU header + 片载荷。
- ② 设计动机:控制每个 RTP 包 ≤ MTU,避免 IP 层分片;每片独立可容忍(丢一片只废这个 NALU,不是这个传输块)。
- ③ 结构:indicator=(原头&0xE0)|28;FU header=S|E|R|原type;同 NALU 所有片 ts 相同、seq 连续、M 仅尾片且仅当该 NALU 是 AU 尾(B8)。
- ④ 项目落点:c:209 上限判定 `nal_len<=max_payload`(1388);c:238–239 indicator 生成(0x65→0x7C);c:240 `offset=1` 跳原头;c:244 `frag ≤ max_payload-2`(1386,给两个传输头留位);c:245 `last` 判定;c:255–257 原 type+S/E;c:248 M=last&&marker。
- ⑤ 面试变体:「大 NALU 怎么发?」「FU-A 两字节头各放什么、为什么要跳过原 NAL 头?」

## 6. 字节样例库(2 正常+2 陷阱;分片数字按代码参数手算)

- **正常 1(4000B 手工分片,纸笔主操作)**:IDR NALU 4000B(头 0x65+3999B 载荷)>1388 → FU 路径。载荷 3999B 分 3 片:1386+1386+1227。每包标:
  | 片 | seq | ts | indicator | FU header | M |
  | 1 | n | T | 0x7C | 0x85(S=1,type=5) | 0 |
  | 2 | n+1 | T | 0x7C | 0x05 | 0 |
  | 3 | n+2 | T | 0x7C | 0x45(E=1) | 1(若该 NALU 是 AU 尾)
- **正常 2(小 NALU 对照)**:100B NALU → 单包直发(c:209),indicator/FU header 概念都不出现——**FU 只对大 NALU 生效**,别把两字节头当成 RTP 常驻结构。
- **陷阱 1(设计目的:NRI 继承)**:indicator 必须继承原头高 3 位(c:239 `&0xE0`)——丢了 NRI,网络拥塞时"可先丢"的优先级信息就错了;而原 type 被换成 28,**真 type 只存在于 FU header 低 5 位**。问:indicator 和 FU header 各丢什么信息不得?(indicator:优先级;FU header:单元边界+原始身份。)
- **陷阱 2(设计目的:重组侧视角)**:接收方拼装:见 S=1 开新缓冲→按 seq 收片→E=1 收尾→**去掉 2 字节传输头、用 indicator 高 3 位+FU header 低 5 位重建原 1 字节头**(0x60|0x05=0x65)→完整 NALU 交付。丢中间一片→整个 NALU 作废(半张书桌拼不出),丢片影响=回到 B1 的坏包因果(花屏到下个 IDR)。
