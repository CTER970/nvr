## 1. 任务目的与意义(四层)

① **为什么存在**:客户端在拿到第一帧之前,怎么知道这路流是什么编码、什么时钟、参数集是什么?SDP 就是"开演前的节目单"——一次交代清楚,客户端准备好解码器再收流。B2 埋的 sprop-parameter-sets 在这里正式登场(概念层闭环点)。
② **项目背景**:`build_sdp`(c:133–147)是本项目 SDP 的全部——10 行 snprintf 模板,SPS/PPS 占位来自启动时收集(c:549–556)或硬编码缺省(c:145–146,审计 #3);DESCRIBE 时原样发出(c:414–420)。
③ **岗位/面试**:「SDP 是什么?sprop-parameter-sets 放什么?」与 B2 两问互为表里;RTSP 岗 JD 里常见的"会看 SDP"就是指能逐行读懂这 10 行。
④ **学完能做**:逐行标注项目真实 SDP;说清每个字段谁消费、干什么;概念层 13 块收官,具备进 P 卡(实现层)的全部概念前置。

## 2. 前置概念声明(铁律21)

本块机制=**会话描述(元数据)**:数据之外的"关于数据的信息"。同族:V4L2 的 `v4l2_format`(先描述格式再传数据)、MP4 的 moov(索引元数据)、B2 的参数集——"先给说明书、后给货"在每一层都出现。SDP 只描述、不传输、不控制:描述是 SDP、传输是 RTP、控制是 RTSP(三角关系)。

## 3. 标识符词源解析(铁律22)

- **SDP** = Session Description Protocol(会话描述协议,RFC 4566)。
- 行首单字母=字段名(协议的极简命名风格):**v**=version、**o**=origin(来源:谁创建/会话 id/版本)、**s**=session name、**c**=connection(连接地址)、**t**=timing(时间)、**m**=media(媒体行)、**a**=attribute(属性行,可多行)。
- **sprop-parameter-sets** = s**tream** **prop**erty parameter sets(流属性参数集):base64 编码的 SPS/PPS,逗号分隔——B2 说明书全文印在节目单上。
- **packetization-mode** = 打包模式:1=单 NAL/非交错模式(本项目与 B9 一致)。
- **rtpmap** = RTP mapping:把动态 PT(96)映射到"编码名/时钟频率"(H264/90000)——B6 陷阱 1 的承诺在这里兑现。

## 4. 类比锚点

SDP=**节目单**:开演前发的册子——哪个频道(m=video)、什么制式(H264/90000)、怎么对台(rtpmap)、随机附赠的说明书全文(sprop)。节目单不演戏(那是 RTP 的事)、也不管你按遥控器(那是 RTSP 的事)。

## 5. 五件套草稿

- ① 一句话:SDP=文本会话描述(单字母行),由 DESCRIBE 响应携带,客户端据此准备解码。
- ② 设计动机:收流前先知格式/时钟/参数集,免得"收到才试";与控制/传输职责分离。
- ③ 结构:项目 10 行逐行表(§6 正常 1)。
- ④ 项目落点:build_sdp c:133–147;SPS/PPS 来源:c:549–556 启动一次性收集(流内首组 type 7/8,经 sdp_collect_cb)+ 失败则缺省 c:145–146(审计 #3:与真实流不匹配→客户端解码失败;且永不更新——c:123 只收首组+stream_receiver.c:134 只 init 一次)。
- ⑤ 面试变体:「SDP 是什么?」「sprop-parameter-sets 放什么?」

## 6. 字节样例库(2 正常+2 陷阱;样例即代码模板)

- **正常 1(项目真实 SDP,纸笔主操作)**:build_sdp 模板(c:135–146)逐行标注"客户端拿去干什么":
  `v=0`(版本)/`o=- 0 0 IN IP4 0.0.0.0`(来源占位)/`s=EdgeFusion NVR`(会话名)/`c=IN IP4 0.0.0.0`(连接占位)/`t=0 0`(永久)/`m=video 0 RTP/AVP 96`(视频、端口占位 0、PT 96)/`a=control:track0`(控制 URL 后缀,SETUP 用)/`a=rtpmap:96 H264/90000`(96↔H264、90kHz——B6/B7 兑现)/`a=fmtp:96 packetization-mode=1; sprop-parameter-sets=<SPS_b64>,<PPS_b64>`(打包模式+说明书全文,B2 兑现)。
- **正常 2(base64 回收)**:解码缺省 PPS `aM48gA==` → `68 CE 3C 80` → type 8(B2 纸笔原题重演,收官自证)。
- **陷阱 1(设计目的:占位语义)**:`m=` 行端口 0、`c=` 的 0.0.0.0 都是**占位**——真实收流地址/端口由 SETUP 协商决定(c:473–476)。别把 SDP 当"连接信息表",它是**能力描述表**:连"怎么连"都不管,只管"流的规格"。
- **陷阱 2(设计目的:参数集双保险与过期)**:SPS/PPS 流里有(B4 样例)且 SDP sprop 也有——双保险,流内丢了 sprop 救场;但本项目 sprop **定格在启动首组**(c:123+c:134 守卫),流中途换参数集(变分辨率)则 sprop 过期、新客户端按旧说明书初始化→解码失败(审计 #3 的完整因果,B2 陷阱 2 的收口)。
