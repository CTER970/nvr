## 1. 任务目的（四层）

① 「改配置不重启」是 NVR 卖点句③的机制核：哪些字段能热、怎么热、热的代价（停止延迟），全在这张卡。② 项目背景：reload 三分支+stop 的 join 语义，与 alarm stop（秒级）形成同项目内对照——面试讲「线程停止的几种阻塞点」有双例。③ 岗位背景：热更新边界、「API 返回成功≠业务生效」「join 不是杀线程」是高级常考；状态表 00/01/10/11 是工程思维展示。④ 学完产出降级矩阵，Phase 2 闭卷（2.5）五场景题直接从这里拼。

## 2. 数据流坐标

链路 D→C 交界：`POST /api/config(web客户端线程) → conf_save → conf_apply_hot → cloud_ai_reload / alarm_reload / set_target_fps / set_segment_seconds`；主循环停机：`web_stop→cloud_ai_stop→receiver_stop→alarm_stop→event_bus_deinit`（main.c:174-178，与 1.7A 已学一致，本卡核实）。

## 3. 锚点（已实测）

- **reload 350-380**：锁内算 `was_enabled=ai_enable&&token非空`（c:353）→ 复制五个热字段（c:355-363：enable/fps/timeout/prompt/model/base_url）→ 算 now_enabled → 解锁 → 三分支（c:370-379：0→1 stop+start / 1→0 stop / 不翻转仅热重载）。token **不**随 reload 更新（保留原值，c:354 注释）。
- **stop 383-390**：g_running=false → `pthread_join`（等线程自然退出——正在 curl 里要等返回，上限 ai_http_timeout_s=30s 默认）→ curl_global_cleanup。
- **ai_thread 289-317**：早退分支（未启用直接 return，**g_running 残留 true**）+ interval_us 一次性（c:302）。
- **get_status 337-347**：`st->running=g_running`；`enabled=配置允许&&running`。
- **对照 alarm_stop 140-152**：signal 唤醒 + sleep 循环每秒查 running → join ≤~1s。
- conf_apply_hot（conf.c:296-304）：**五项**=log_set_level / alarm_reload / cloud_ai_reload / frame_grabber_set_target_fps(web_mjpeg_fps) / stream_receiver_set_segment_seconds。

## 4. 卡内前置（铁律 21/22）

- 迁移：g_cfg=模块私有副本（1.7A）；「复制了≠生效了——看消费者是否重读」（08-22 手册口径修正 5，本卡逐字段验证）。
- 词源：`reload`（重新装载）；`join`（汇合——等待线程终止并回收，**不是 kill**）；`volatile`（禁止编译器缓存到寄存器——多线程标志位的最低保障，但**不保证原子性/可见性完备**，一句话）。

## 5. 引导问题（手册 7 问照用）

1. 「配置允许」「g_running=true」「线程实际存活」是同一状态吗？（三分化：早退例）
2. enable=0 或 token 空时线程早退，status 还报 running 吗？（报——c:343 读残留 true；预制审计③）
3. reload 复制了 ai_fps，11 分支下它立即生效吗？（否——interval_us 局部变量一次性 c:302；预制审计②）
4. g_running=false 能中断已进入的 curl_easy_perform 吗？join 可能等多久？（不能/最长 timeout 30s）
5. token/DNS/CA/curl/HTTP/JSON 失败时：录像、MJPEG、RTSP 转发、事件、报警各如何？（全不受录像主链影响——旁路隔离；事件/报警停更）
6. event_bus_init 失败（main.c:140-142 仅 WRN）后订阅回调还能收到云事件吗？（publish 入口 !g_db→-1，事件丢弃；alarm 订阅仍在但无来源）
7. GPIO=-1：不建线程还是写值无操作？（后者，2.3B 已学，此处收口）

## 7. 闭卷与变式（已过深度滤网）

- 闭卷：reload 三分支+各自线程后果。
- V1：运行中 token 从空变有效走哪支？（was=false→now=true→stop(空转)+start——线程重起拿新 token；顺带解释 start 为何能解决 fps 生效问题）
- V2：热更新边界判定法一句话（消费者重读才算生效——interval_us 一次性 vs set_target_fps 每帧读副本）。
- 提升池：pthread_cancel 换 join 的利弊；volatile 不保证原子性/可见性完备。

## 8. 预制时审计发现（核实后用）

②interval_us 一次性；③早退 running 残留；④stop 延迟上限 30s（curl 无中断回调——对照 Phase 1 V3 的 AVIOInterruptCB 家族：标准解是进度回调/低超时轮询，本项目未用=审计观察）。
