## 0. 开块审查

`grep -n "build_request_body\|call_cloud\|parse_openai\|extract_json" cloud_ai.c`。注意用户若修过码率恒0（recorder.c）不影响本卡。

## 1. 任务目的（四层）

① 这是全项目唯一的外部服务调用点，「一张 JPEG 变成一个结构化事件」的变换链；它的失败分层是 2.4 降级矩阵的原料。② 项目背景：OpenAI 兼容端点+多模态模型，自研 base64+JSON 组装与双层解析（响应 JSON→content 里再嵌一层模型输出的 JSON 子串）——面试讲「和云大模型怎么对接」就靠这卡。③ 岗位背景：HTTP 客户端的四层失败（传输/HTTP码/协议结构/业务语义）是通用排查能力题；curl easy 三步是嵌入式常见考法。④ 学完交失败矩阵，2.3A 事件入库、2.4 降级直接拼装。

## 2. 数据流坐标

## 4. 卡内前置（铁律 21/22）

- **base64**：二进制→64 个可打印字符的文本编码（邮件/URL 安全），长度膨胀 4/3；为什么图片要编码：JSON 是文本协议，JPEG 字节里有无引号/控制符/0x00，直接塞会破坏 JSON 结构。
- **JSON 树**：对象{}键值/数组[]/字符串——嵌套即树；本项目响应 content 内还嵌一层 JSON 字符串=「树里挂着一棵要再解析的树」（双层解析）。
- **curl easy API** 三步：`curl_easy_init` 造句柄 → `curl_easy_setopt` 配参 → `curl_easy_perform` 执行；`write_cb` 是库调你的回调（C1 重逢）。
- 词源：`data URL`（内联数据的伪 URL 方案）；`Bearer`（持有者令牌，HTTP Authorization 头的一种方案）。

## 5. 引导问题（手册 6 问照用）

1. process_one_frame 有哪些阶段？每阶段失败后还会发布吗？（都不会——逐 return）
2. 图片位于请求 JSON 哪条路径？数据形态？（见上 data URL）
3. curl 失败/HTTP非200/响应结构不对/内容不是 JSON——分别属于哪层？（传输/HTTP/协议结构/业务语义）
4. `none` 在 cloud_ai 还是 event_bus 过滤？其他发布者能发 none 吗？（cloud_ai c:276；能——不是总线规则）
5. enable_thinking=false 的正确归属？（提供方扩展）
6. b64/body/resp/model_text/json_str 的 free 是否在提前返回中配对？（是——练习用控制流而非肉眼信任）

## 6. 产出与通过标准

## 7. 闭卷与变式（已过深度滤网）

- 闭卷：口述六阶段管道+每层一个失败例子。
- V1（变式）：模型返回 content="好的，结果如下：```json {...}```"——哪两个函数处理了什么？（extract 剥围栏找 {}，c:120-140；若模型说了两段 JSON 只取第一段）
