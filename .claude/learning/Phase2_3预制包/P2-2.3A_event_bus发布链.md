# P2-2.3A · event_bus 发布链精读（60min，L3 核心）

> 原 2.3 前半：publish 主链+锁策略；时间盒 15min发布+20min回调/锁+10min闭卷
> 前置：C1（回调/发布订阅）必备

## 0. 开块审查

`grep -n "event_bus_publish\|sqlite3_prepare\|cbs\[i\]" event_bus.c`（110-180）。快照目录来源 main.c:136-137（storage_dir/../snapshots）。

## 1. 任务目的（四层）

① event_bus 是链路 C 的「心脏」：一次 publish 串起入库、快照、广播三件事，锁策略是全项目最精的一处——C1 学的「锁内拷贝解锁回调」在此落到逐行。② 项目背景：这是作者自研的迷你「持久化+观察者」中间层，也是 NVR 事件可追溯（SQLite 证据链）的落点；读透它=能讲「为什么不用消息队列」。③ 岗位背景：「回调与锁」「临界区里该放什么」直接对应面试「锁粒度」题；SQLite 最小 CRUD 也是嵌入式存储常客。④ 学完交 publish 分段图，2.3B 查询支路只是它的镜像。

## 2. 数据流坐标

链路 C 中枢：`AI线程栈上 event_t+JPEG字节 → publish → [锁内:INSERT→id 回填→写快照→UPDATE 回填路径→清理旧快照] → [锁内拷订阅数组] → [解锁] → [逐个同步回调] → 返回 id`。

## 4. 卡内前置（铁律 21/22）

- **SQLite**（迷你三件套，L1）：库=单文件；表=行列结构；句柄=sqlite3*。五步套路 `prepare→bind→step→finalize`（预编译防注入）；`SQLITE_DONE`=写语句完成、`SQLITE_ROW`=查到一行。
- 词源：`AUTOINCREMENT`（自动递增主键）；`rowid/last_insert_rowid`（刚插入行的 id）；`TRANSIENT`（bind 时让 SQLite 拷一份数据而非引用调用方内存）。

## 5. 引导问题（手册精选+C1 落地）

1. 事件 id、快照文件名、jpeg_path 按什么顺序产生？（先 INSERT 拿 id→再用 id 命名文件→UPDATE 回填路径——为什么文件名不能先生成？）
2. 回调执行时 g_lock 释放了吗？证据行？（c:174 vs c:176-178）
3. 为什么要「锁内拷贝订阅数组」而不是直接在锁内回调？（回调慢→锁持有时间被放大；回调里再调 event_bus_* 查询会死锁）
4. DB 成功、快照失败（磁盘满/写半）时：回调还发生吗？Web 列表显示什么？（照常回调；列表有事件但 snapshot 字段为空串，前端无图）
5. AI 线程栈上的 ev 指针被回调保存到以后用会怎样？（悬垂——publish 返回即失效；C1-V2 落地）
6. cleanup_snapshots 为什么在锁内调用合适/不合适？（设计题：它做 statvfs+scandir+unlink 全是慢 I/O——见审计点①）

## 6. 产出与通过标准

publish 四段时序图（锁区间要明确画出）、事件三字段生成顺序表、发布结果矩阵（DB败/快照败/订阅空）。通过=闭卷说出「回调与发布者同线程且同步，但调用时已不持 g_lock」+ 三字段顺序因果。

## 7. 闭卷与变式（已过深度滤网）

- 闭卷：默写 publish 骨架（含锁的起止行号量级）。
- V1（锁粒度变式，Phase 1 V1 迁移）：把快照写挪到锁外，需要多付出什么？（jpeg 缓冲所有权/一致性——jpeg 是调用方的，锁外写其实安全；但 UPDATE 又要重新拿锁；学生辨「哪些步骤真需要锁」）
- V2（订阅时机）：publish 时订阅表为空会怎样？（事件入库但无人响应——「持久化了但没通知」与「通知了没持久化」是两种不同故障，矩阵素材）
- V3（审计①）：快照 I/O 在锁内，慢 TF 卡上 web 查询 /api/events 会怎样？（查询抢同一 g_lock——event_bus.c:228——被拖慢；一句话结论级，修法留动手池）

## 8. 预制时审计发现（核实后用）

①快照 I/O+cleanup 全程持锁（c:145-167）——拖 web 查询与其它发布者。②c:115 `if (ev->jpeg_path[0]==0) ev->jpeg_path[0]=0;` 无操作疑似残留（「注释/语句不是证据」小例）。③c:181-194 row_to_event 用 strncpy 不补 \0？——memset 先清零（c:185）+ strncpy(size-1) 安全，可让学生自查防呆。

## 9. 快问快答

1. publish 返回 -1 的两种情形？（未 init / INSERT 失败——快照失败不返回错误）
2. ev->id 在函数入口为什么先置 -1？（失败时调用方能识别「未入库」）
3. 两个发布者并发 publish 会怎样？（串行化在 g_lock 上——单写者简化）
4. 快照为什么用触发帧而不是重新抓帧？（证据一致性：报警画面=分析画面）
5. MAX_SUBS=8 溢出会怎样？（静默不注册——订阅丢失无告警，一句审计）
