## 第 2 讲 · 模块地图与四条链路（2026-09-07，口述进行中）

**口述交付情况**：热更五项全对✓；三模块输入输出对（均挑已学区 cloud_ai/event_bus/frame_grabber+alarm）；「C 挂 A 在」方向✓；画图以口述走图替代（速讲允许）。

**卡点登记**：
1. **转发腿第三次漏**（第 1 讲×2 + 本讲）：记忆法=说「三分发」掰三根手指——录像 remux／抽帧／转发透传。rtsp_server 是自研协议含金量话术载体。
2. **必须重启项答错**（答成 cloud_ai_reload，实为热更五项之一）：正确=源 RTSP 地址/监听端口/存储目录。⚠️「源地址不热更」=简历历史错误（×3）同族第四犯，个人高频雷，已单独重讲。
3. 「封装进 mp4 结构体」术语错：MP4 是容器/文件格式，非 C 结构体。
4. 「C 挂 A 在」机制表述虚（"数据流直接封装所以无影响"）→ 正解：独立旁路线程+取拷贝+失败不回灌（2.1 存货）。
5. D 链口述过虚（"包含 post api 等内容"）→ 改用降层话术（MJPEG 预览/Range 回放/事件+配置 API）。
6. 学生提问「旁路是否复制一份 packet」→ 已直讲：packet 纯借用零复制；clone 在 A 腿（write_frame 掏空包）；拷贝在 JPEG 交接两处（memcpy 进缓存/malloc 出口）。口径「包是借的，JPEG 才拷」。

**待补口述**：①转发腿一句 ②重启项一句 → **均已交付且超线（2026-09-07）**：三分发 c:157/164/168 行号核实全对（"一份 packet、三条腿、三种格式"口径成型）；重启项答出两层结构（web.c:825 代码自认 + 对照 conf.h 推不进五路：rtsp_url/transport/timeout、路径类、rtsp_server_port、mqtt 全家、log_file），引用全部核实属实。

**收口残留微修**（第 5 讲彩排复查）：
1. 「转发给预览客户端」措辞与源码注释 c:166 一致（无错），但面试加定语「RTSP 客户端（如 VLC）」以免与浏览器 MJPEG 预览腿混淆。
2. 「因为三个模块处理都很快速」因果要翻转：快是**前提**不是保证——同步串行的**代价**是任一消费者变慢拖住泵（慢 TCP 客户端持锁 send 是已知风险），换来零队列内存+顺序保证+天然背压。取舍话术，不是免费午餐。
