## 脊梁段 1 · event_bus 函数功能层(2026-09-08,过闸)

**口述交付情况**:9/9 函数分四批交付,每函数「做什么/输入输出/出口类型」齐;③框架④why 通过。实质错误仅 1 处措辞级(AUTOINCREMENT),当场精修。

**卡点登记**:
1. 微修:「回调须快速返回」契约出处= **event_bus.h:18**(回调 typedef 的注释),口述说成「alarm.c 的注释」——引用位置错,因果无误。
2. AUTOINCREMENT 措辞精修:普通 INTEGER PRIMARY KEY 分配 id 用 max+1,**删最大行后 id 会复用**;AUTOINCREMENT 查 sqlite_sequence 记的**历史**最大,永不回退。

**超线亮点(应答卡素材,表达课复用)**:
- 「总线只传不攒——攒了才要队列,要队列才要线程」(event_bus 为什么 0 线程)
- 「延迟记在谁头上,谁才知道疼」(被动库借调用方线程)
- get 三出口同返 -1 =「三种世界」:系统故障 vs 合法的查无此件,web 侧只能糊成一个失败;规范解法 0/-1/-2 学生自答
- BLOB 反对理由两条:「高频小查询给低频大图陪葬」(行肥索引瘦)+ 从库取图=大块搬运进 g_lock 临界区,与「锁内只做快事」相撞
- NULL 语义链:SQL NULL(带类型标记的无值)≠ 空串;column_text 无字节可指只能给 C NULL;数值列 NULL→0 是 sqlite 定义的宽容转换

**通过判定**:publish 五步✓ / 查询家族真干活与转调✓ / 框架(0 线程+锁保护对象)✓ / why(BLOB vs 文件,查询+web 两角度)✓ → **段 1 过闸,主线 L1 观察级免重做**。

## 脊梁段 2 · alarm 函数功能层(2026-09-08,过闸)

**口述交付情况**:8/8 函数四批交付,**零实质错误**(两段首次全对通关);过闸两问(回调 why+订阅侧上下文)通过。

**卡点登记**:无实质卡点。口头提醒一条:c:63 空串返回 false 的「没配触发类型=安全态永不响」语义口述中未主动复述,彩排时留意别丢。

**超线亮点(应答卡素材)**:
- 「等待没有消失,只是被挪到了唯一以等待为业的线程上」(判定在回调、动作在线程;生产者发信号/消费者专职等)
- 响铃期间新事件命中 on_event 仍秒回(覆盖刷新 g_pending)——阻塞永远只在报警线程一侧
- #13「锁白上了一半」独立定位到变量粒度:on_event 只有 g_active_s 在锁内读,trigger_types/min_conf 都在 c:79 锁外
- strtok 毁副本:不拷贝则「第二个类型永远匹配不上,报警在第一个事件后静默残废」;多线程需 strtok_r
- usleep(100ms)=等内核异步建 sysfs 节点,「没有完成通知,时间换确定性,不是协议保证」
- stop 顺序三逻辑:标志先行(两循环唯一退出条件)/锁内 signal 防「查完谓词还没睡下」丢唤醒(落空无害,秒级轮询兜)/join 等死透;GPIO 复位在 join 后(交错:线程刚过 c:101 检查、你复位、它再拉高)
- 写法不对称第三例:init strncpy(c:119)不补 \0 靠 BSS 零初始化,reload(c:162)显式补——同文件对比法

**通过判定**:交接链✓ / int-not-bool✓ / 框架(1 线程对照 0 线程)✓ / 回调 why✓ / 订阅侧一句话✓ → **段 2 过闸;主线 2.3B 的 L1 压缩为核对订阅者名单(alarm.on_event)**。

## 脊梁段 3 · C 链路走查(2026-09-08,过闸)

**口述交付情况**:数据形态①–⑥+三去向首答交齐;none 过滤/同步转交判据/cloud_ai 整体框架追问后补交全对;alarm 框架主动完整复述零错。实质错误:零(一处精修)。

**卡点登记**:
1. 形态①初答只给了「AVPacket→AVFrame」,漏第二跳「AVFrame(YUV)→JPEG」——feed 站是两连跳,旁路存的那份是 **JPEG 非 AVFrame**(旁路代价=每帧完整解码+编码,不是拷指针)。当场精修。

**超线亮点(应答卡素材)**:
- 「先库后文件,不然不知道叫什么名」(快照文件名=行 id 的跨函数顺序因果)
- 「快速返回契约的来源=回调借发布者的栈跑」(契约↔执行上下文)
- 「publish 返回时库里有行、盘上有文件,但物理世界还没任何变化」(同步 vs 转交的判据)
- 方法论金句:「同步=同一栈帧链做完;转交=过了共享变量+signal 的接力点,时间轴换主」
- get_jpeg=「冻结快照/生命周期解耦」+ realloc 搬家+原地覆写(c:160-164)
- ai_thread **拉模式** vs feed 推模式;节流=「上限节流,不是精确 fps」(单次调用可耗时数秒)
- none 受害面两层:events 表暴涨拖慢 web 历史查询 + 无事 evt_*.jpg 塞目录靠 cleanup 收

**通过判定**:整线函数名+数据形态不断链✓ / 三分叉+同步转交判据✓ / cloud_ai+alarm 整体框架✓ → **段 3 过闸,脊梁 3/6;面试题「挑一条链路从进讲到落」C 链路全套就绪**。
