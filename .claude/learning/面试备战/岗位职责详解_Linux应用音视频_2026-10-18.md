## 第一部分 · 岗位职责(JD 原文 + 白话翻译)

### JD 原文怎么写

**海康威视 2027 校招·软件开发工程师(应用方向)**——四条职责原文:
1. 负责嵌入式应用软件**设计、实现和维护**工作;
2. 负责软件**需求和设计分析**,编写软件需求和设计文档;
3. 负责软件**编码、调试和验证**,设计测试方案和用例;
4. 负责**疑难问题跟进解决和系统性能调优**。

**萤石网络·嵌入式软件开发工程师(基线,杭州)**:
- 嵌入式 Linux 平台应用软件开发,包括**需求分析、功能设计、编码实现、联调测试、疑难问题跟进**;新技术预研和落地;
- 任职要求原文:**"具有组件开发思维,有良好的软件架构能力和接口设计能力"**。

**星宸科技·嵌入式软件开发工程师(Linux 应用方向)**:
- 分析市场需求规格,完成相应的**软件方案设计、开发、验证和 debug**(如 AOV APP、V4L2 场景集成、FFmpeg 集成);Linux 系统性能分析和优化;FAE 反馈问题的分析、调试并解决。

**瑞芯微平台·Linux 应用开发工程师(社招)**:
- 应用软件开发(新产品功能研发+老产品迭代维护);**算法集成**;**系统联调**(视频流卡顿、算法延迟、交互响应等应用层问题);**性能优化**(内存占用、CPU 负载、启动时间、视频帧率)。

### 归纳:职责五块(白话翻译)

| 块 | JD 词汇 | 实际含义 |
|---|---|---|
| A 功能开发与维护 | 设计、实现、维护/新功能研发、老产品迭代 | **主体工作**。给产品加功能(新录像策略、新告警联动)、改 bug、维护老版本——注意"维护"占很大比重,产品是长期跑的 |
| B 需求与设计 | 需求和设计分析、设计文档、接口文档 | 把产品经理的**业务语言翻译成技术语言**:"支持回放拖动"→HTTP Range+MP4 索引;"低功耗待机"→哪些线程该停、唤醒后怎么恢复。写设计文档、过评审 |
| C 编码调试验证 | 编码、调试、验证、测试方案和用例 | 写 C 代码、自己设计测试用例自测、板端部署验证 |
| D 疑难问题跟进 | 疑难问题跟进解决、FAE/客户反馈 | **最见真功夫的一块**。现场/测试报来的怪问题(偶发崩溃、内存缓慢上涨、某客户的环境下卡顿),复现→定位→修复→验证闭环 |
| E 性能调优 | 性能调优、性能分析 | CPU/内存/帧率/启动时间/延迟,用数据说话:先测量、再优化、再验证 |

### 这个岗位的本质(一句话)

**音视频组件(采集/编码/传输/存储/AI)是原料,应用工程师把原料组装成稳定的产品功能,并保证它在客户现场长期稳定运行。** 你的产出不是"某个算法、某个协议栈",而是"这个功能上线了、这个崩溃修掉了、这个指标达标了"。

## 第二部分 · 日常工作内容(完整工作流程六阶段)

> JD 里的流程词(需求分析→功能设计→编码实现→联调测试→疑难问题跟进→性能调优)不是走一遍就完的瀑布,而是**每个需求/每个 bug 都走一遍的小循环**,日常在循环之间切换。

### 六阶段展开(含时间占比估算,新人视角)

| 阶段 | 干什么 | 典型动作 | 占比 |
|---|---|---|---|
| ① 需求分析 | 搞清"要做什么、做到什么程度算好" | 读 PRD;和产品/测试对齐边界条件(码流断了怎么办?磁盘满了几路的行为?);把业务语言翻成技术语言 | 10-15% |
| ② 功能设计 | 搞清"怎么做" | 模块划分、接口设计、**数据流设计**(几个线程、数据怎么流、谁持有谁释放)、状态机;写设计文档过评审 | 15-20% |
| ③ 编码实现 | 把设计变成代码 | C 编码、自测、提交代码评审(新人代码被 review 是日常)、修 review 意见 | 30-40% |
| ④ 联调测试 | 证明"做对了" | 设计测试用例;和驱动/硬件/云平台/APP 各方联调;板端部署、串口日志、回归验证 | 15-20% |
| ⑤ 疑难问题跟进 | 修掉"没想到的" | 复现→缩小范围→定位根因→修复→验证闭环;工具=日志/coredump/gdb/strace | 10-20%(不可预期) |
| ⑥ 性能调优 | 让它"跑得好" | 先测量(top/perf/分段计时/P95)再动手;CPU、内存、帧率、启动时间、延迟 | 按需 |

### 一天的样子(新人第一年典型)

早上站会(昨天进展/今天计划/有没有卡点)→ 看 bug 单,复现昨晚测试报的问题 → 串口日志定位 → 改代码、自测 → 提交评审 → 下午和驱动同事联调一个花屏问题(各自拿日志对时间戳)→ 傍晚把改好的版本部署到板子跑长稳 → 写/改文档。**新人前一年大多在 ③④⑤ 三段里转**,①②随着信任度增加逐步参与。

### 关键认知(和"基座"的关系)

日常工作里,采集、编码、封装、传输这些**基座组件通常已经存在**(自研的或原厂 SDK 的),你的工作是:**调用它们、组合它们、在它们之上做产品逻辑、以及它们出问题时跨层定位**。所以 JD 要求你"了解"基座(视音频基础是"优先项"不是硬性项),但**考察重心是你的集成与工程能力**——这正是你的定位。

## 第四部分 · 与我背景的匹配分析

### 核心定位(先说结论)

**你的定位与这个岗位是同构的**:你的两个项目就是"Linux 应用工程师把音视频基座组件集成成产品"的完整样本——NVR 边侧网关把拉流/录像/预览/AI/Web/告警六个组件缝成一个守护进程;采集终端把 V4L2/显示/上传三路缝成一个稳定流水线。**面试自我定位一句话:"我是把音视频组件集成成稳定产品的 Linux 应用工程师,基座四层(采集/编码/封装/传输)我都摸过,其中封装和流媒体有一手实现。"**

### 三个半缺口(按优先级)

1. **量产/长稳维度**:看门狗喂狗策略、OTA 升级与回滚、日志系统设计(客户现场死机怎么留证据)——B2 批海康二面题单几乎整页考这个。**准备方式**:不是去补实现,而是准备好"如果是我会怎么设计"的思路(日志分级落盘+关键状态快照+看门狗绑任务健康)。
2. **调试工具链深度**:gdb/coredump/valgrind/strace 目前是 P1#38 一句级。板端跑通 D1-D6 时顺手用 valgrind 过一遍内存,故事就有一手了。
3. **硬件联调经验**:实习有板端部署但偏浅。面试话术:承认边界+展示排查思路(分层定位:先日志再 strace 再抓包,不瞎猜)。
4. (半个)**量产流程感**:JD"从需求到交付"校招不苛求,用实习的回归验证/文档交接流程接。

### 面试叙事策略(基座与主线的切换)

- **投 JD-4(应用工程)/JD-3(流媒体)**:主线是主角——架构/所有权/性能/工程化四板斧;基座层每段一句话证明"摸过、懂原理",不展开。
- **投 JD-1(采集)/JD-2(编码封装)岗**:基座层讲成主角(V4L2 所有权设计/remux 掉电安全决策),应用层退为背景——同一个项目,换个讲法。
- **通用兜底句**(被问"你为什么觉得自己适合这个岗位"):"我做的两个项目就是这个岗位的日常:把 V4L2、ffmpeg、RTSP、HTTP 这些组件,用多线程架构和清晰的所有权纪律集成成一个在板子上稳定跑的守护进程,并且用分位数数据去度量它的表现——需求和设计、编码、联调、疑难问题、性能调优这条链我在项目里完整走过。"
