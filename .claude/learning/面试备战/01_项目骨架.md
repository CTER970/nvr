# 01_项目骨架(一页纸,L3 素材总源)

> 更新:2026-08-19。面试讲项目的"底稿",所有 L3 项目实证从这里出发。

## 一句话定位

边侧智能 NVR 网关:在无视频硬解能力的 IMX6ULL(Cortex-A7)上,用 C 多线程守护进程实现"RTSP 拉流 → 无转码录像(fMP4) + 抽帧上云 AI + Web 预览/回放 + 自研 RTSP 转发"的完整监控链路;端侧 V821(RISC-V+VENC)只做 H.264 推流,云端为大模型 API 服务。

## 架构(文字版,面试可白板默画)

```
V821(编码推流) ──RTSP──▶ IMX6ULL 拉流线程 ──一次 av_read_frame 的 packet 三分发──▶
                          (单线程同步)  ├─▶ recorder:remux→fMP4 段→磁盘循环回收   (链路A 主路)
                                        ├─▶ frame_grabber:解码→缩放→JPEG→最新帧缓存(链路B 旁路)
                                        │      ├─▶ Web: multipart MJPEG 预览
                                        │      └─▶ cloud_ai 线程:上云→event_bus→alarm(条件变量+GPIO)/SQLite→Web 事件列表
                                        └─▶ rtsp_server(自研): 信令+RTP/FU-A→本地转发     (链路E 旁路)
Web server:一客户端一线程(HTTP API/MJPEG/Range 回放/静态页/配置)                       (链路D)
7 类线程:主(sigaction)+拉流+Web监听+Web客户端(每连接)+RTSP监听+AI+报警
```

## 已知缺陷/改进清单(arch-04 弹药)

**自研协议栈五缺陷**(Phase 1.5 审计层结论级):①RTCP 仅端口骨架无收发;②AVCC packet 声称支持实未实现;③SPS/PPS 提取失败用硬编码缺省(与真实源不匹配则客户端无法解码);④无 PTS 时时间戳恒 0;⑤慢 TCP 客户端持锁 send 可能拖住拉流分发。
**亲审计 bug(rec 系)**:⑥`out->size` 在 `av_interleaved_write_frame` 掏空 packet 后读取→码率统计恒 0(独立推完整因果链);⑦时基未传 recorder(写死 1/90000 的脆弱假设);⑧I-05 写头失败后非关键帧可成段首帧;⑨I-06 磁盘满时 err_count 被非关键帧 return 0 清零→熔断不触发;⑩Web 侧短写未处理/Range 越界返 200 不返 416;⑪目录 fsync 缺口(原子替换不等于完整掉电安全);⑫token 掩码回写风险。
详细定位:`学习掌握档案.md` 错误台账/审计发现、`memory/code-quality-todo`。

## 分层定位(在技术栈哪一层)

嵌入式 Linux **应用层**开发:不碰驱动/内核,核心技能=FFmpeg 库使用与审计、手写应用层协议(RTSP/RTP/HTTP)、pthread 并发模型、边缘设备工程约束(无 VPU→remux、掉电→fMP4+原子保存、磁盘有限→循环回收)。与 video2lcd(采集/显示/FB 层)互补,共占"嵌入式 Linux 音视频应用"完整栈。
