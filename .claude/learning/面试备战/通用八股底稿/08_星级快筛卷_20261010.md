## 点 1 · 三次握手为什么是三次 ★★★

**C1.** 建立 TCP 连接要用三次握手。两次不够，主要是因为：

- A. 两端端口号必须分三次才能协商完。
- B. 两个方向的初始序号都要被对端确认。停在两次时，服务端还不能确认自己的初始序号已被客户端收到。
- C. 第三次报文专门用来携带第一块应用数据，没有载荷连接就不能用。
- D. 窗口大小和 MSS 只能出现在第三次报文里。

**J1.** 判断：三次握手主要是为了分三次把两端的端口号协商完，初始序号只是报文里的附带字段。

## 点 2 · 四次挥手为什么是四次 ★★★

**C2.** 挥手在协议模型里按四步来设计，原因是：

- A. 最后一步必须空等 2MSL，所以比握手多出一步。
- B. 挥手时双方要重新协商一组初始序号。
- C. 连接是全双工。收到对方的 FIN 只说明对方不再发送，本端可能还有数据要发，所以「确认对方的 FIN」和「发出本端的 FIN」是两件独立的事。
- D. 被动关闭方从收到 FIN 起就被禁止再发送数据，必须连发两个 FIN 把缓冲区冲掉。

**J2.** 判断：四次挥手在报文层也必须是四个 TCP 段，协议不允许把 ACK 和 FIN 放在同一个段里。

## 点 3 · TIME_WAIT 和 2MSL ★★★

**C3.** TIME_WAIT 是哪一种状态？

- A. 主动关闭方发完最后一个 ACK 之后进入的状态，持续时间是 2MSL。
- B. 被动关闭方等待本端应用把剩余数据读完的状态。
- C. 双方同时进入、各等 1 个 MSL 的状态。
- D. 三次握手还没完成时，连接在半连接队列里的状态。

**J3.** 判断：主动方在 TIME_WAIT 等待 2MSL，是为了确认应用层数据已经被对端应用程序读完。

## 点 4 · CLOSE_WAIT 是本端没关闭 ★★★

**C4.** 本端套接字处于 CLOSE_WAIT，表示：

- A. 本端已经调用 close，正在等对方的 ACK。
- B. 本端已经发完最后一个 ACK，正在等 2MSL。
- C. 三次握手还没完成，连接尚未进入 ESTABLISHED。
- D. 本端已经收到对方的 FIN 并回了 ACK，但本端应用还没有 close，因此本端的 FIN 还没发出去。

**J4.** 判断：系统里堆积大量 CLOSE_WAIT，说明本端已经 close，正在等对方把 FIN 发过来。

## 点 5 · 粘包 / 拆包和定帧 ★★★

**C5.** TCP 里说的粘包和拆包，指的是：

- A. IP 层把数据报切开或拼合。IP 头的 DF 置 1 之后，应用层自然就有了消息边界。
- B. TCP 是字节流，不保留每次 write 的边界。一次 read 可能拿到几次 write 拼在一起的数据，也可能只拿到一次 write 的前半段。消息边界要应用层自己定帧。
- C. 只有发送缓冲区写满才会发生。缓冲区足够大时，write 和 read 一一对应。
- D. 打开 TCP_NODELAY 之后这种现象消失，因为 Nagle 算法是唯一原因。

**J5.** 判断：TCP 的拆包就是 IP 分片。把 DF 置 1，应用层就不必再定帧。

## 点 6 · TCP 与 UDP 怎么选 ★★★

**C6.** 下面哪一种选择理由成立？

- A. 要内核负责可靠、有序和重传时用 TCP。能容忍丢包、更在意时延，或者重传节奏要自己控制时用 UDP。
- B. 视频只能走 UDP，控制消息只能走 TCP，协议上没有第三种摆法。
- C. UDP 没有拥塞控制，所以同一条链路上 UDP 的有效吞吐一定比 TCP 大。
- D. TCP 和 UDP 的差别只在端口号范围。

**J6.** 判断：同一条 TCP 连接上，中间一个段丢失时，后面先到达的段也不能先交给应用。这就是队头阻塞。

## 点 7 · MTU 与 MSS ★★

**C7.** MTU 和 MSS 的关系，哪一句对？

- A. 二者是同一个数。以太网上都是 1500。
- B. 常见以太网 MTU 1500，是一帧能装下的 IP 数据报最大长度。无选项的 IPv4 上，TCP 的 MSS 通常是 1460，只计算 TCP 载荷，不含 IP 头和 TCP 头。
- C. MSS 由路径上的路由器逐跳改写，两端不能在 SYN 里通告。
- D. MSS 把 IP 头和 TCP 头都算进去，所以它比 MTU 大 40 字节。

**J7.** 判断：路径中间某一跳的 MTU 更小也没有关系。TCP 的 MSS 只看本机网卡，报文到了中间设备也不会装不下。

## 点 8 · TCP 头：序号、确认号、窗口、标志位 ★★

**C8.** 这四个字段，哪一组是对的？

- A. 序号是报文的个数；确认号是已经收到的最后一个字节；窗口是发送方的拥塞窗口 cwnd。
- B. 序号是本段数据第一个字节的编号；确认号是期望对方接下来发送的字节编号；窗口是本端当前还能接收的字节数；SYN、ACK、FIN、RST 是标志位。
- C. 确认号是本端下一个要发送的字节；序号是对方已经确认过的字节。
- D. 窗口字段在 IP 头里。TCP 头只有端口号和校验和。

**J8.** 判断：确认号里填写的是已经连续收到的最后一个字节的序号。

## 点 9 · select / poll / epoll，LT / ET ★★★

**C9.** 关于 select、poll、epoll 和两种触发方式，哪一组是对的？

- A. 三个接口的返回值语义相同，差别只在函数名。EdgeFusion 网关的 Web 接入用的是 epoll 边缘触发，所以不会一连接一线程。
- B. epoll 只能监听 UDP，select 只能监听 TCP。
- C. select 和 poll 每次把关注集合交给内核再扫描。epoll 把 fd 登记在内核里，返回就绪的 fd。水平触发在条件仍成立时继续通知；边缘触发在状态变化时通知，正确用法通常是非阻塞一直读到 EAGAIN。
- D. 边缘触发是 epoll 的默认方式，并且必须配合阻塞 read。

**J9.** 判断：epoll 使用边缘触发时，只要接收缓冲区里还有没读完的数据，内核就会因为「缓冲区里还有数据」这个原因立刻再次通知你。

## 点 10 · 非阻塞与 EAGAIN ★★

**C10.** 非阻塞套接字上出现 EAGAIN，表示什么？

- A. 这次调用若继续做下去就会阻塞。应当稍后重试。它不是对端复位，连接并不因此断开。Linux 上 EAGAIN 和 EWOULDBLOCK 是同一个值。
- B. 对端已经发送 RST。应当立刻 close。
- C. 非阻塞表示调用一定会成功，内核会在后台把这次读写做完。
- D. 只有 UDP 会返回 EAGAIN。TCP 非阻塞读不会返回这个错误。

**J10.** 判断：非阻塞套接字上 read 返回 EAGAIN，应当按对端已经关闭来处理，马上 close。

## 点 11 · 进程和线程 ★★★

**C11.** 进程和线程的关系，哪一句对？

- A. 每个线程有自己独立的堆。一个线程 free 掉的块，另一个线程的 malloc 看不到。
- B. 创建进程比创建线程轻，服务端默认应该用多进程。
- C. 同一进程里的线程不能共享全局变量，只能用管道通信。
- D. 同一进程的线程共享地址空间，包括堆、全局变量和文件描述符表，各自有自己的栈和寄存器。不同进程之间地址空间隔离。

**J11.** 判断：同一进程里的线程共用一张文件描述符表。其中一个线程 close 了某个 fd，其他线程再使用这个 fd 是错误的。

## 点 12 · 互斥锁保护什么、死锁四条件 ★★★

**C12.** 死锁的四个必要条件是：

- A. 互斥、原子性、可见性、有序性。
- B. 互斥、占有且等待、不可剥夺、循环等待。
- C. 互斥、饥饿、优先级反转、丢失唤醒。
- D. 互斥、占有且等待、可剥夺、循环等待。

**J12.** 判断：互斥锁只约束同样去拿这把锁的代码。另一条路径不拿锁就改同一份共享数据，仍然会把数据改坏。

## 点 13 · 条件变量为什么用 while ★★

**C13.** 用条件变量等待时，为什么要把谓词放在 while 里，而不是 if？

- A. pthread_cond_wait 返回以后谓词一定为真，用 if 包一层就够了。
- B. 等待可能被虚假唤醒；被唤醒并重新拿到锁时，谓词也可能已经被别的线程改掉。所以要 while 再查一次。
- C. while 只是少拿一次锁，和正确性无关。
- D. 有了条件变量就可以不再使用互斥锁。

**J13.** 判断：pthread_cond_wait 在入睡前会放开那把互斥锁，被唤醒并重新拿到这把锁之后才返回。

## 点 14 · volatile 不是锁 ★★★

**C14.** C 语言里的 volatile 起什么作用？

- A. 它要求编译器按源码实际去做这些读写，不要把访问优化掉。它不提供互斥，也不保证多线程之间的原子性和内存顺序。
- B. 变量加上 volatile 就等于有了一把互斥锁，多线程对它做 i++ 是安全的。
- C. 只有 C++ 认识这个关键字，C 编译器会把它忽略掉。
- D. 它让变量常驻寄存器，并关闭缓存一致性协议。

**J14.** 判断：volatile int 的 i++ 是原子操作，因为 volatile 会让每次加减都直接访问内存。

## 点 15 · 优先级反转 ★★★

**C15.** 优先级反转指的是：

- A. 高优先级线程主动把 CPU 永久让给低优先级。把所有线程设成同一优先级，现象就从定义上消失。
- B. 它就是死锁的另一个名字，四个必要条件缺一个都不会发生。
- C. 低优先级持有锁，高优先级在等这把锁，中优先级反复抢占低优先级，高优先级因此被拖住。常用对策是优先级继承或优先级天花板。
- D. 它只发生在单核上。多核时高优先级换一个核运行，就不会发生。

**J15.** 判断：优先级继承是在持锁期间，把持锁线程的优先级临时抬到当前等待者里最高的那个，解锁后收回。它不是把正在等待的高优先级线程降下来。

## 点 16 · 内存分区 ★★★

**C16.** 函数里的局部变量、malloc 返回的块、未初始化的全局变量，分别在哪？

- A. 堆；栈；代码段。
- B. 栈；栈；data。未初始化全局变量会保留源码里没有写明的垃圾值。
- C. 寄存器；只读常量区；堆。
- D. 栈；堆；BSS。BSS 在程序加载时被清零。

**J16.** 判断：字符串字面量 `"hi"` 存放在栈上，离开当前函数之后就不能再使用。

## 点 17 · 对齐的原因 ★★

**C17.** 结构体里为什么会出现填充字节？

- A. 为了省内存，把结构体压得更小。
- B. 为了让每个成员的地址满足它的对齐要求。有的 CPU 访问未对齐的地址会故障，允许未对齐的平台上也可能拆成多次访问。
- C. 编译器随意插入，不按成员类型计算。
- D. 填充只改变 sizeof 的数字，生成出来的读写指令和没有填充时完全一样。

**J17.** 判断：结构体末尾也可能有填充。这样组成数组时，下一个元素的第一个成员仍然是对齐的。

## 点 18 · 栈和堆的生命周期 ★★★

**C18.** 栈对象和堆对象的生命周期，哪一句对？

- A. 两边都要程序员调用 free。return 只是栈专用的 free 写法。
- B. 函数返回时，这个函数里 malloc 的块会自动释放，所以短函数可以不写 free。
- C. 局部变量分配在堆上，malloc 分配在栈上，因为栈更大。
- D. 栈对象在它所属的函数返回时结束。malloc 的块从分配活到 free，进程结束时由系统回收。把局部变量的地址返回给调用者，调用者拿到的是悬空指针。

**J18.** 判断：栈上安排一个局部变量，主要是移动栈指针。malloc 要走堆分配器，现有空闲块不够时还会向内核申请。

## 点 19 · static 的三种用法 ★★★

**C19.** C 语言里 static 的三种常见作用，哪一组是齐的？

- A. 函数内局部变量改为静态存储期，并且只初始化一次；文件作用域的变量限制在本翻译单元；函数也限制在本翻译单元。
- B. 局部变量变成线程私有；全局变量改到堆上分配；函数变成内联函数。
- C. 三种写法都只表示「放进静态存储区」，链接范围和初始化次数没有进一步的差别。
- D. static 只能修饰全局变量。函数和局部变量不能写 static。

**J19.** 判断：写成 static 的函数，仍然可以被另一个 .c 文件用 extern 声明之后正常链接、调用。

## 点 20 · const 指针的两种读法 ★★

**C20.** 下面哪一句把两种写法都读对了？

- A. `const int *p` 不能改变 p 的指向，但是可以通过 p 修改对象。
- B. `int * const p` 不能通过 p 修改对象，但是 p 可以改指向别处。
- C. `const int *p` 不能通过 p 修改对象，p 本身可以改指向；`int * const p` 不能改指向，但是可以通过 p 修改对象。
- D. 两种写法完全等价，const 写在星号哪一侧都一样。

**J20.** 判断：`const int *p` 里的 const 锁住的是指针 p 本身，所以 p 不能再指向别的对象。

## 点 21 · 虚拟内存为什么存在；缺页是什么 ★★★

**C21.** 虚拟内存和缺页，哪一组是对的？

- A. 虚拟内存就是磁盘上的 swap 分区。没有配置 swap 时，进程直接使用物理地址。
- B. 发生缺页说明指针一定越界了，内核应当立刻杀掉进程。
- C. 虚拟内存让每个进程有独立地址空间，页可以当前不在物理内存里。合法缺页由内核装入页面或分配页框；非法访问才表现为段错误。
- D. 打开虚拟内存之后，程序里的指针值就是物理地址，外设 DMA 可以直接拿这个值用。

**J21.** 判断：虚拟内存的含义就是把暂时不用的页换到 swap。系统没有配置 swap 时，进程就没有独立的虚拟地址空间。

## 点 22 · 大小端 ★★★

**C22.** 在小端机器上，32 位数值 0x12345678 放在内存里，从低地址到高地址的四个字节依次是：

- A. 12 34 56 78
- B. 12 78 34 56
- C. 78 12 56 34
- D. 78 56 34 12

**J22.** 判断：在小端机器上，把 16 位端口从主机序变成网络序需要交换这两个字节。htons 做的就是这件事。

## 点 23 · sizeof 和 strlen ★★★

**C23.** 有定义 `char a[] = "abc";`。哪一句对？

- A. sizeof(a) 和 strlen(a) 都是 3。
- B. sizeof(a) 和 strlen(a) 都是 4。
- C. sizeof(a) 要运行到这一行才知道，strlen(a) 是 4。
- D. sizeof(a) 是 4，strlen(a) 是 3。

**J23.** 判断：函数写成 `void f(char s[])` 时，函数里面的 `sizeof(s)` 等于调用方那个数组的总字节数。

## 点 24 · strcpy / strncpy 的危险 ★★★

**C24.** strcpy 和 strncpy 的风险，哪一句说对了？

- A. strcpy 不看目标缓冲区有多大，源串更长时就写越界。strncpy(dst, src, n) 在源串长度大于等于 n 时不补 `'\0'`，不能把它当成一定会带结尾的安全拷贝。
- B. strncpy 一定会补上 `'\0'`，所以 `strncpy(dst, src, sizeof(dst))` 总是安全的。
- C. strcpy 在目标写满时会停止，并返回错误码通知调用者。
- D. 两个函数都会读取源字符串自带的容量字段，容量不够就失败返回。

**J24.** 判断：源字符串比 n 短时，strncpy 会用 `'\0'` 把目标一直填到 n 个字节。因此它的工作量可能跟着 n 走，而不只跟着源字符串的长度走。

## 点 25 · 野指针和悬空指针 ★★

**C25.** 这两个词怎么区分？

- A. 野指针是 free 之后没有置 NULL；悬空指针是声明后还没赋值。
- B. 野指针是还没有初始化就拿来用；悬空指针曾经指向一个有效对象，对象释放或离开作用域之后，旧地址还留在手里。
- C. 两者都是 NULL 的别名。写成 NULL 就是野指针。
- D. 悬空指针只存在于 C++。C 语言里只有野指针。

**J25.** 判断：`free(p)` 之后只要不再写入 `*p`，p 就仍然是一个有效指针。

## 点 27 · fork 拷贝了什么 ★★

**C27.** fork 之后，父子进程的关系是：

- A. 父子共享同一份地址空间。一边改全局变量，另一边立刻看见，和线程一样。
- B. fork 不复制内存。子进程从 main 重新开始执行。
- C. 子进程拥有自己的地址空间。Linux 上使用写时复制，还没写过的页先与父进程共享物理页。文件描述符是各自的一份，但指向同一个打开文件，文件偏移是共享的。
- D. 多线程进程调用 fork 后，父进程里的每一个线程都会出现在子进程里。

**J27.** 判断：多线程的进程调用 fork 之后，子进程会继续运行父进程的每一个线程。

## 点 28 · 管道、本地套接字、共享内存 ★★

**C28.** 这三种本机通信方式，哪一句对？

- A. 匿名管道是字节流，用于继承了管道两端的亲缘进程。本地套接字用于本机进程，可以双向。共享内存是同一块物理内存，并发同步要应用自己做。
- B. 共享内存由内核替应用串行化所有写入，所以不用再加锁。
- C. 匿名管道可以跨主机传输，语义和 TCP 相同。
- D. 三者都要经过网卡。差别只在系统调用的名字。

**J28.** 判断：本地套接字的数据在本机内核里交接，不会送到网卡上再做 IP 路由。

## 点 29 · 信号：异步安全 ★★

**C29.** 信号处理函数里可以做什么？

- A. 可以调用 printf、malloc 和 pthread_mutex_lock，它们都是普通库函数。
- B. 只能调用异步信号安全的函数。常见做法是只改一个 `volatile sig_atomic_t` 标志，回到主流程再做其余的事。
- C. 信号处理函数和普通函数调用一样，可以使用全部 libc。
- D. 处理函数一旦开始执行就不会被另一个信号打断，所以没有重入问题。

**J29.** 判断：信号标志用 `volatile int` 就够了，不必用 `sig_atomic_t`。volatile 已经保证了多字节读写的原子性。

## 点 30 · UART / SPI / I²C / 485 ★★★

**C30.** 一面够用的总线对照，哪一组是对的？

- A. UART 自带时钟线；SPI 只用两根线、靠地址选设备；I²C 给每个从设备一根片选；两线 485 是全双工。
- B. UART、SPI、I²C 都是主从同步总线，差别只在线的数量。
- C. UART 异步、没有单独的时钟线、通常点对点，收发可以同时进行。SPI 由主设备提供时钟，常用独立片选挂多个从设备，收发可以同时进行。I²C 是 SDA 加 SCL 两线、开漏、靠地址挂多个设备，数据线半双工。两线 485 是差分半双工。
- D. SPI 的从设备可以在主设备不提供时钟的时候，主动把数据写进主设备。

**J30.** 判断：I²C 和 SPI 都能挂多个从设备，所以两者都靠每个从设备单独一根片选来选中。

## 点 41 · 编译四阶段与静态/动态链接 ★

**C41.** 从 C 源文件到可执行文件，四个阶段各做什么？

- A. 预处理展开宏、头文件和条件编译；编译把源码翻译成汇编；汇编得到带符号的目标文件；链接解析符号并把目标文件、库合成可执行文件或共享库。
- B. 预处理直接生成机器码；编译负责运行程序；汇编负责优化；链接只做语法检查。
- C. 四个阶段都由链接器完成，编译器只负责检查括号是否配对。
- D. 编译阶段就把多个 `.c` 收成最终可执行文件，汇编和链接可以省掉。

**J41.** 判断：动态链接会把库的机器码拷进可执行文件，所以文件更大，运行时不再依赖外部的共享库。
