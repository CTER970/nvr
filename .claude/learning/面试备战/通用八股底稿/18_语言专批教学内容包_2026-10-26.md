### #43 函数指针与回调 ★★★

- **层次声明**：讨论语言语义 + 工程用法；不讨论编译器底层优化（内联/尾调用）。
- **主轴句**：「函数指针 = 把"函数"当成值存起来、传出去；回调 = 我把我的函数交给你、你来调我——**谁调用不由调用链决定，由事件决定**。」
- **一张图**（数据流图）：
```
[注册] 你的代码 --把函数地址+上下文--> 框架的登记表
                                    |
[触发] 事件发生(数据到了/时间到了/线程启动)
                                    |
[回访] 框架从登记表取出地址 --> call --> 你的函数执行(带着上下文)
```
- **一张表**（回调三要素=判断框架）：

| 要素 | 谁做 | 存哪 | 注意 |
|---|---|---|---|
| 注册 | 使用者，先于事件 | 框架的登记表（数组/结构体成员） | 指针类型必须匹配 |
| 触发 | 框架/库/OS | — | 时机不由你控制 |
| 上下文 | 使用者递进去 | void *user_data 原样带回 | 没有它，回调里"不知道自己在处理谁" |

- **教学正文**（四层讲）：
  1. **痛点开场**：库/框架的作者写代码时，根本不知道将来用他的人要干嘛——qsort 不知道你要按姓名还是按年龄排序，pthread_create 不知道你线程里跑啥。他不可能把所有可能性都写死，于是留一个口子：**你把自己的函数作为"值"传给他，事情发生时他反过来调你的函数**。这个"把函数当值传"的语言能力就是函数指针，这个用法就是回调。
  2. **生活类比（餐厅前台叫号）**：你去餐厅吃饭，把手机号留给前台（**注册**）；菜好了前台打你电话（**触发**）；电话接通后前台说"您是 12 号桌的那份黄焖鸡"（**上下文 user_data**）——他不说这句，你接到电话根本不知道在叫哪一桌。整个过程谁打给谁，不是由你排队时的顺序决定的，而是由"菜做好了"这个事件决定的。
  3. **机制映射（对照术语）**：
     - 函数指针变量 = 前台手里那张写着你手机号的小纸条；`void (*fp)(int)` 读作"fp 是张纸条，能贴一个'收 int、不返东西'的函数地址"。工程里一律 typedef 起类型名，不然每个声明都长得像乱码。
     - 回调 = "留纸条给前台"这件事本身；函数指针只是能存地址的变量，是**机制**；回调是拿这个机制实现"框架调你"，是**用法**（影石那道本质区别题就在这）。函数指针还能干别的：线程入口（pthread_create）、跳转表（按编号查表调函数，代替一长串 switch）。
     - `void *user_data` = 前台回电时报的桌号。C 的回调函数是全局函数，它不知道自己在处理哪个对象，注册时塞进去的那个 `void*` 就是解决这个的。
     - std::function + lambda 比裸函数指针慢一层：因为 lambda 能捕获变量，前台不光存你手机号，还得记你随身行李（捕获量），拨号前多翻一道——类型擦除 + 可能堆分配 + 间接跳转；裸指针就是一个 call。小米那道性能题的答案就在这半句。
  4. **新手三问预埋**：
     - Q：回调在谁的线程里跑？A：**前台打你电话时用的是前台的时间线**——回调在触发者的线程上下文里同步执行，所以回调里不能久留、不能做重活，重活丢自己的线程。
     - Q：qsort 的比较函数算回调吗？A：算，库不知道你要怎么比，留个口子让你塞。
     - Q：函数指针和普通指针有啥区别？A：它指向的不是数据，是代码段里的指令地址；调它就是跳过去执行。
- **真题锚**：大华「函数指针的应用场景、你写过哪些」／影石「函数指针和回调的本质区别」／小米「std::function 和函数指针的性能差异及原因」。
- **机制演示**：event_bus 的 callbacks 数组——publish 时遍历数组逐个调用（开卡时出彩色调用链图）。
- **项目桥**（1 句）：项目 event_bus.c 的 callbacks[] 注册表 + publish 遍历调用，就是"注册—触发—上下文"三要素的现成实例。
- **考察三问**：
  Q1 函数指针有哪些应用场景？你实际写过哪些？
  Q2 函数指针和回调的本质区别是什么？
  Q3 你注册给框架的回调函数执行时，是在谁的线程里跑？这意味着回调里不该做什么？

### #44 struct/union/位域 ★★

- **层次声明**：讨论语言语义 + 内存布局；对齐填充的原理归 #17，本点只管"union 怎么叠、位域怎么切、怎么重排"。
- **主轴句**：「struct 是每人一间房，union 是所有人挤同一间房、同一时刻只有一个人在——所以 union 大小 = 最大成员（再按对齐补齐）；写一个成员再读另一个 = 同一块内存换个方式解释。」
- **一张图**（结构图）：
```
struct S { char c; int i; short s; char d; }
 [c|垫3|i i i i|s s|d|垫1]  依次排、各自垫 → 12 字节

union U { int i; short s; char c[8]; }
 [同一块 8 字节]  i / s / c 全部从偏移 0 叠放 → 大小=8（最大成员）
```
- **一张表**：

| 维度 | struct | union |
|---|---|---|
| 每个成员 | 独占自己的偏移 | 全部从 0 叠放 |
| 同时有效 | 全部 | 只有一个（最后写的） |
| 大小 | 各成员+填充 | 最大成员（按最大对齐补齐） |
| 典型用途 | 数据聚合 | 一块内存的多种视图 |

- **教学正文**（四层讲）：
  1. **痛点开场**：你写寄存器驱动时，一个 32 位寄存器既要能"整 32 位读写"（比如一次写 0xFFFFFFFF），又要能"只改其中某一位"（比如只把 enable 那一位翻成 1）。用 struct 写两份内存？那每次整字写和按位读之间还得手工移位换算，又慢又容易错。
  2. **生活类比（酒店房间）**：
     - struct = 标准楼层，每个客人独立一间，A 房装 B 房互不干扰，所以 struct 总大小 = 各房加起来（中间还有走廊浪费=对齐填充）。
     - union = 总统套房，所有人挤**同一间房**，同一时刻只住一波客人；你这波走了下一波进来，床还是那张床但人换了。所以 union 大小 = 最大那波客人需要的空间（=最大成员，再按最大对齐补齐）。
     - 写一个成员再读另一个 = 同一张床换个人睡，床垫位置没变，但"睡在上面的人"换了。
  3. **机制映射**：
     - **union 为什么适合寄存器映射**：`union { uint32_t raw; struct { uint32_t enable:1; ... } bits; }`——同一块 32 位内存，raw 视图让你整字写，bits 视图让你按位看，**零转换成本**。struct 做不到（两份内存，还得手工移位）。
     - **位域**：`unsigned a:3` = 把房间再切成"3 个比特这么大的隔断"。**边界（标准只保证存在，不保证顺序）**：隔断在字节里从哪边开始排，编译器说了算，跨平台/跨编译器别假设——读芯片手册按手册写。
     - **重排省内存（字节原题）**：入住登记时把大个子（int）排在一排，小个子（char）塞缝里，走廊浪费最少。`{char,int,short,char}`=12 → `{int,short,char,char}`=8。口算方法归 #17/#24。
  4. **新手三问预埋**：
     - Q：union 怎么知道当前哪个成员有效？A：**C 不管，靠程序员自己在外面配一个"判别字段"记着**（variant/ tagged union 套路）。
     - Q：union 判大小端咋回事？A：看同一张床，字节从床左边躺还是右边躺——`union{int i;char c;}`，c 读到的是 i 的最低字节就是小端（S-16 有完整卡，互链）。
     - Q：union 里放个带构造的类行不行？A：行，但那是 C++ 的事，C 侧不展开。
- **真题锚**：中兴「struct 和 union 区别」／影石「union 在寄存器映射里的应用、为什么比结构体更合适」／字节「给了个结构体让算大小、怎么重排省内存」。
- **项目桥**：不配（本项目为应用层，无寄存器映射实例，不硬凑）。
- **考察三问**：
  Q1 struct 和 union 的区别？
  Q2 union 在寄存器映射里怎么用？为什么比 struct 更合适？
  Q3 给你一个结构体定义，怎么算它的大小？怎么重排能省内存？

### #45 malloc/free 底层 ★★

- **层次声明**：讨论应用层 + glibc 分配器的常见实现（ptmalloc）；不讨论内核伙伴系统/页分配器（邀约线）。
- **主轴句**：「malloc 不是系统调用，是用户态的二手内存批发商——小块从手里囤的堆里切，大块直接找内核 mmap；free 把块还给批发商进空闲链，只有大块才真正退还内核。」
- **一张图**（堆布局图）：
```
   堆（brk 逐段伸展）                     独立 mmap 映射区
 [已分配|空闲(挂bin/tcache链)|顶]        [大块 ≥128KB(默认阈值,可调)]
    free → 进空闲链等复用                   free → munmap 立即还内核
```
- **一张表**（判断框架）：

| 判断 | 小块（< 阈值，默认约 128KB） | 大块（≥ 阈值） |
|---|---|---|
| 从哪来 | brk 伸展的堆里切 | 单独 mmap 一段 |
| free 去哪 | 进空闲链（tcache/bin），等下次复用 | munmap，立即还内核 |
| 典型后果 | 反复交错产生碎片 | 无碎片问题，但 mmap/ummap 有系统调用开销 |

- **教学正文**（四层讲）：
  1. **痛点开场**：你每次 malloc 都直接陷入内核？那一次小分配要做一次系统调用，比用户态慢几十倍，程序没法跑。glibc 的 malloc 不是系统调用，它是个"内存批发商"——手里囤着从内核批量批来的货，你要小块他直接切给你，你还回来他存保鲜柜下次复用。
  2. **生活类比（菜市场批发商）**：
     - 你（程序）买 1KB 白菜 → 批发商（ptmalloc）仓库（brk 堆）里有现货，称给你。
     - 你要买 1MB 白菜 → 批发商仓库没这么多现货，他自己开车去农田（内核 mmap）直接拉一车专送你；用完这车直接退给农田（munmap），不进他仓库。
     - 你把菜还回来（free）→ 批发商放进保鲜柜（tcache/bin 空闲链），下次有人要同款直接拿，不立刻退农田。
     - 批发商发菜时在袋子外头贴张小纸条写着"这袋多重"（块头元数据）；你 free(p) 时他看一眼纸条就知道这袋该倒回保鲜柜哪个位置。
  3. **机制映射（保留判断表的事实）**：
     - **free 为啥知道块多大**：块头在你拿到的指针**前面**藏着。这解释两件事：①越界往前写会踩坏纸条，下一块就废；②free 一个不是 malloc 来的指针，读到张乱七八糟的纸条，直接崩。
     - **碎片怎么产生**：你今天要 1KB、明天还 1KB、后天要 2KB……保鲜柜里一堆小袋，总空着不少，但凑不出一个连续的 2KB 大袋——这就是碎片，也是"嵌入式避免 malloc"的机制根（完整五句归 #42，互链）。
     - **大块直接 mmap（大华原题）**：阈值默认约 128KB、可动态调整；大块 free 时 munmap 立即还内核，小块进空闲链等复用。
     - **2M 物理 malloc 10M（TP-Link）**：批发商口头答应给你 10M（虚拟地址），不真备货；你用到哪页他临时去农田收哪页。农田真没货又没 swap → OOM 杀进程（挂 #21）。
  4. **新手三问预埋**：
     - Q：free(NULL) 行不行？A：合法，空操作。
     - Q：malloc(0) 返回啥？A：标准允许返回 NULL 或一个可 free 的唯一指针，常见实现给后者——别依赖它。
     - Q：C 里为啥大家宁愿自己开池复用也不反复 malloc/free？A：保鲜柜虽快，但碎片和锁竞争在高频路径上要命；frame_grabber 只存最新帧、启动分配一次循环复用就是这个思路（项目桥）。
- **真题锚**：讯飞「malloc 底层实现」／大华二面「malloc 和 mmap 区别、何时用 mmap」／TP-Link「2M 物理内存申请 10M」／字节「free 之后还能不能访问」（已并入 #42 边界一）。
- **项目桥**（1 句）：frame_grabber 只存最新一帧、缓冲复用不反复 malloc/free，就是"启动分配+循环复用"思路的实例。
- **考察三问**：
  Q1 malloc 的底层实现讲一下？free 是怎么知道该释放多大的？
  Q2 malloc 和 mmap 有什么区别？什么时候分配器自己会用 mmap？
  Q3 板子只有 2M 物理内存，malloc(10M) 会发生什么？

### #46 二级指针 ★（P1 结论级）

- **层次声明**：语言语义；一句话+一个例子即收。
- **主轴句**：「想让函数改掉'指针本身'，就得传指针的地址——改谁就传谁的地址：改 int 传 int\*，改 int\* 就得传 int\*\*。」
- **一张表**：

| 你想改什么 | 必须传什么 | 例子 |
|---|---|---|
| 变量的值 | 变量的地址（一级指针） | void set(int *p) |
| 指针本身（让它指向别处） | 指针的地址（二级指针） | void alloc(char **out) |
| 指针指向的值 | 一级指针就够 | void fill(char *buf) |

- **教学正文**（四层讲）：
  1. **痛点开场**：C 里函数改调用方的变量，靠传地址——这是你已经熟的。那问题来了：如果调用方手里拿的不是一个 int，而是一个指针变量，函数想让这个指针"指向另一个地方"，光把指针的值传进去够吗？不够——函数拿到的只是指针值的副本，改副本改不到调用方那个变量本身。
  2. **生活类比（钱包和抽屉）**：
     - 你想让朋友兜里的 int 变 42 → 给他看钱包地址（一级指针 int*），他从钱包里掏钱出来换成 42。
     - 你想让朋友"把钱包换个抽屉放"（改指针本身，让它指向新 malloc 的地址）→ 光让他看钱包没用，他看完钱包不能替你决定放哪个抽屉。你得告诉他**抽屉在哪**（二级指针），他才能把新钱包塞进去。
  3. **机制映射**：
     - 规律一句话：**改谁就传谁的地址**。改 int 传 int*；改 int* 本身就得传 int**。
     - 典型场景一（输出型接口）：`int get_jpeg(char **out)`——函数内部要 malloc 一块新缓冲，再让"调用方手里那个 char*"指向它。只能传它的地址（二级指针），函数里 `*out = malloc(...)` 才真正改到调用方的变量。项目里 frame_grabber_get_jpeg 就是这么干的（项目桥）。
     - 典型场景二（链表头插）：`void push(Node **head)`——头指针本身要从旧节点换成新节点。
     - **变式（宇视原题）**：一级指针指向的值变了，二级指针存的"一级指针的地址"**不变**——抽屉位置没变，抽屉里钱包的内容换了；通过二级指针解引用两次，读到的是新值。
  4. **新手三问预埋**：
     - Q：那三级指针 int\*\*\* 啥时候用？A：很少；知道"想改谁就传谁地址"的规律就行，工程里二级顶天了。
     - Q：用返回值返回新指针不行吗？A：行，但 C 函数只能返一个值；你还要顺带返错误码，就用输出型二级指针。
     - Q：二级指针和二维数组一样吗？A：不一样，一个是"指针的地址"，一个是连续二维内存，别混。
- **真题锚**：字节「二级指针什么时候用、举个实际场景」／宇视「一级指针指向的值改变后二级指针是否改变？」。
- **项目桥**（1 句）：frame_grabber_get_jpeg(char **buf) 就是二级指针的输出型接口实例。
- **考察**（两句级）：Q 二级指针什么时候必须用？举个实际场景。

### #47 宏与预处理 ★（P1 结论级）

- **层次声明**：预处理阶段（编译之前）；"宏 vs const/inline"三差归 #20，本点只补 ## 与展开隐患。
- **主轴句**：「宏只是编译前的文本替换——没有类型、不求值一次、不受优先级保护；所有坑都能从'文本替换'四个字推出来。」
- **一张表**（隐患从"文本替换"推导）：

| 文本替换的直接后果 | 长成的坑 |
|---|---|
| 参数被原样贴进去 | 重复求值：MAX(i++, j) 自增两次 |
| 不加括号 | 优先级：#define SQ(x) x*x → SQ(a+1) 展开成 a+1*a+1 |
| 无类型检查 | 传什么都贴，错了编译期不报（运行期炸） |
| 多条语句无作用域 | if-else 被粘死 → 用 do{}while(0) 包起来 |

- **教学正文**（四层讲）：
  1. **痛点开场**：宏为啥这么反直觉？因为它**根本不是代码，是编译前的文本复印**。预处理器在编译器还没读懂代码之前，就把稿子上写着 `MAX(...)` 的地方原样贴成别的文本，它不算数、不看类型、不帮你加括号——你稿子写成啥样它印成啥样。所有的坑都能从"文本替换"四个字推出来。
  2. **生活类比（复印店）**：你递一张稿子进复印店，说"凡是看到 SQ 这个记号，就替换成后面括号里那段字"。复印店不管那段字数学上对不对、有没有优先级，**原封不动复印**：
     - 稿子上 `SQ(a+1)` → 印出来是 `a+1*a+1`（你以为是 (a+1)²，其实不是，因为复印店不帮你加括号）。
     - 稿子上 `MAX(i++, j)` → 印出来 i++ 出现两次，i 自增两次。
     - 稿子上 if 后面跟三条日志语句，复印店把三条都印上去，中间分号让 else 被顶飞。
  3. **机制映射（从文本替换推坑）**：
     - `#x` = 复印店把参数那段字**加个引号**印出来（调试打印宏常用）。
     - `x ## y` = 把两个词**拼成一个词**（批量生成函数名/变量名，小米那道 ## 题就在这）。
     - `do{}while(0)` = 把多条语句装进"一个印章框"里，复印店整体算一段，不然 if-else 会被中间分号顶开。
     - 三句防坑：参数永远带括号 `#define SQ(x) ((x)*(x))`、避免重复求值（别传带 ++ 的参数）、多语句包 do{}while(0)。
  4. **新手三问预埋**：
     - Q：宏和 const/inline 谁好？A：三差归 #20 卡，结论=宏没类型检查、不求值一次；const/inline 是正经 C 语句。
     - Q：宏有啥不可替代？A：条件编译（#ifdef）、跨平台开关、#x 字符串化、## 拼接——这些是真函数做不到的。
     - Q：宏有类型吗？A：没有，传啥贴啥，错了编译期不报错，运行期才炸。
- **真题锚**：小米「宏里两个井号（##）是干嘛的」／影石「宏展开可能带来哪些隐患」。
- **项目桥**：不配（通用语法点，不硬凑）。
- **考察**（两句级）：Q1 ## 是干嘛的？Q2 宏展开有哪些隐患，分别怎么防？

### #48 多态与虚函数 ★★★

- **层次声明**：讨论语言语义 + 单继承下的对象内存布局；虚继承的菱形布局只标"知道存在、按公司深挖再展开"（大华二面层级）。
- **主轴句**：「虚函数 = 把"调哪个函数"从编译期挪到运行期——对象里多一个虚表指针，指向本类的函数表；父类指针装着子类对象，调用时查的是子类的表，所以调到的就是子类的版本。」
- **一张图**（对象+虚表指向图）：
```
 Base 对象            Derived 对象          Base *p = &d;
 [vptr]──→ Base 表    [vptr]──→ Derived 表      │
 [Base 成员]          [Base 成员]                └─ p->f() 走法：
                      [Derived 新增]               读 d 的 vptr → 查 Derived 表 → 跳到 Derived::f
        表内容: &Base::f              表内容: &Derived::f（覆盖版）
```
- **一张表**（三种深度三种答法）：

| 面试官问到哪层 | 问法长相 | 你答到哪 |
|---|---|---|
| 结论层 | "多态怎么实现" | 父类指针调虚函数，运行期按实际对象决定版本 |
| 机制层 | "虚函数表机制" | 每个类一张虚表，每个对象一个 vptr；调用=查表跳转（上图） |
| 布局层 | "对象模型/内存布局" | vptr 在对象头部（常见实现）；单继承子类共用一个 vptr；虚继承会引入额外结构（一句到边） |

- **教学正文**（四层讲）：
  1. **痛点开场**：假设你有个父类 `Animal`，派生出 `Dog` 和 `Cat`，都有个叫 `speak()`。你手里拿的是 `Animal*` 指针，可能指着 Dog 也可能指着 Cat。没有虚函数时，编译器只看你手里是 `Animal*`，**永远调 Animal::speak**——你拿着狗的绳子，牵出来的却是动物通用版的叫。这显然不对：调谁应该由"实际对象是谁"决定，而不是由"指针类型"决定。虚函数就是把这个决定从编译期推迟到运行期。
  2. **生活类比（员工工牌+岗位联系表）**：
     - 每个类有一张"岗位联系表"（虚表 vtable），写着这个岗位的人遇到 `speak()` 该拨哪个分机。
     - 每个对象出生时，胸口别一张工牌（vptr），背面写着"我这岗位的联系表在几号"。
     - 你是 Dog 对象，工牌背面就指向 Dog 的表；是 Cat 对象，就指向 Cat 的表。
     - 调用 `p->speak()` 时：编译器不知道你指的是 Dog 还是 Cat，但它知道动作很简单——**看对象胸口的工牌，翻到背面那张表，找 speak 那一格，拨过去**。所以实际调到的就是 Dog::speak 或 Cat::speak。
  3. **机制映射**：
     - vptr 在对象**头部**（常见实现）；单继承下子类和父类共用一个 vptr。
     - **构造函数为啥不能虚**：工牌是入职（构造）过程中发的——对象还没建好，工牌都没别上，你拿啥查？鸡生蛋问题。
     - **基类析构什么时候必须虚**：只要你可能"拿基类指针 delete 派生对象"——否则 delete 只按 Animal 的流程走，Dog 自己开的资源（文件/内存）没人还。**不打算被继承、或总是按具体类型删，就不必加**（一句边界）。
     - **纯虚函数** `=0`：在基类里"只定接口不给实现"，强制派生类填表；含纯虚的类=抽象类，不能实例化。虚函数=可选重写，纯虚=必须重写。
     - **代价一句**：每对象多一张工牌（一个指针），每次调用多翻一下工牌（一次间接跳转）——嵌入式性能敏感/确定性要求高的代码常因此禁虚函数。
  4. **新手三问预埋**：
     - Q：vptr 存在对象内存的哪个位置？A：对象头部（最先那个字段）。
     - Q：每个对象一张表吗？A：**不是**——每个类一张表（全局只读段），每个对象一个 vptr 指向它。
     - Q：虚继承/菱形继承啥区别？A：会引入额外结构，一句到边"知道存在"，按公司深挖再展开（大华二面层级）。
  5. **与 A5 卡 4 的关系**：A5 卡 4（虚函数表与虚析构）是 P1 最小集版本，已经讲过"工牌/查表"主线；本卡是进阶版，多补了"为什么需要它（痛点）"+纯虚+代价。两卡口径一致，面试以本卡四层讲法为主。
- **真题锚**：CVTE「虚函数原理；构造/析构能否是虚函数；纯虚函数作用」／大华二面「虚函数表对象模型；虚继承内存布局」／OPPO「运行时多态的具体实现」。
- **机制演示**：Base/Deduced 两对象同跑 `p->f()`，对比汇编级"一次间接跳转"（开卡时出彩色对比图）。
- **项目桥**：不配（项目纯 C；C++ 侧桥留给 #50 的话术句）。
- **考察三问**：
  Q1 虚函数是干什么的？运行时多态是怎么通过它实现的？
  Q2 构造函数和析构函数哪个能是虚的？基类析构什么时候必须声明成虚的，为什么？
  Q3 纯虚函数是什么、有什么用？有虚函数的类，对象在内存里比普通对象多了什么？

### #49 智能指针 ★★

- **层次声明**：库用法 + 引用计数机制；控制块内存布局、弱计数细节一句到边。
- **主轴句**：「智能指针 = 把'释放'写进析构函数（RAII：构造拿资源、出作用域析构自动还）——shared_ptr 靠引用计数决定谁最后还；unique_ptr 靠'所有权唯一、禁止拷贝'从根上免计数；weak_ptr 只观察不拥有，专破循环引用。」
- **一张图**（计数图 + 循环引用）：
```
 sp1 ──┐                正常: 计数 2 → sp2 离开作用域 -1 → sp1 析构 -1 → 0 → delete 对象
       ├──→ [对象|计数=2]
 sp2 ──┘
 循环引用: A ↔ B 各持对方 shared_ptr → 离开作用域计数仍各为 1 → 永不归 0 → 双双泄漏
 解法: 一侧换 weak_ptr → 不计数 → 链条断开
```
- **一张表**：

| | unique_ptr | shared_ptr | weak_ptr |
|---|---|---|---|
| 拥有权 | 独占 | 共有（计数） | 无（观察） |
| 拷贝 | 禁止（只能 move） | 允许，计数+1 | 允许，不计数 |
| 典型场景 | 默认选择、工厂返回 | 多处共享生命周期 | 缓存/观察者/破循环 |

- **教学正文**（四层讲）：
  1. **痛点开场**：C 里你 malloc 了一块内存，忘了 free 就泄漏。这种"谁申请谁释放"靠人记的纪律，在大项目里迟早出事。C++ 的思路是：**把"释放"这件事写进析构函数**——栈对象出作用域时语言保证析构被调，那把资源包进对象里，离开作用域自动还。这就是 RAII（资源获取即初始化）。
  2. **生活类比（酒店房卡）**：
     - **unique_ptr** = 单间客房，一张房卡一个人，你退房（对象出作用域）就立刻收拾房间。不能再发第二张卡（**禁止拷贝，只能 move 转让**）。
     - **shared_ptr** = 大套房，好几个人各拿一张房卡；前台（控制块）记着"现在还有几张卡在外"。每走一个人就 -1，**最后一个人退房时才真正收拾房间（delete 对象）**——A5 老卡那句话："最后一个走的人关灯"。
     - **weak_ptr** = 走廊监控摄像头，能看到房间里有没有人，但**不拿房卡、不计入卡数**。
     - **循环引用** = A 和 B 互相把对方的房卡揣兜里，两个人都觉得"还有别人持卡我不能走"，结果计数永远不归零，房间永不退。解法：其中一个人不拿房卡，装个监控（weak_ptr），环就断了。
  3. **机制映射**：
     - **为什么能自动释放（OPPO 原题）**：析构函数挂在作用域退出路径上，栈回退时语言保证调用——从"记得写 free"变成"离开花括号自动发生"。
     - **weak_ptr 怎么用（小米原题）**：不延长对象寿命；要用时 `lock()` 相当于去前台问一句"这房间还在吗"，在就升级成一张临时 shared_ptr 房卡，不在就拿到空。
     - **边界（必背的"但是"）**：引用计数的原子加减是线程安全的，但**它指向的对象本身不因此线程安全**——房卡计数器前台不会算错，但房间里两个人同时翻抽屉该上锁还得上锁。另一句：make_shared 把对象和控制块一次分配，少一次内存碎片。
  4. **新手三问预埋**：
     - Q：unique_ptr 为啥不能拷贝？A：拷贝就意味着两张房卡，违反"独占"语义；要转让只能 move（把房卡过户）。
     - Q：shared_ptr 线程安全吗？A：**计数本身原子安全，指向对象不安全**——别一句话答成"线程安全"。
     - Q：控制块是啥？A：前台那个小本子，记着 strong 计数和 weak 计数；布局细节一句到边，不展开。
  5. **与 A5 卡 5 的关系**：A5 卡 5 是 P1 最小集版，已经讲过"三兄弟/最后关灯/循环引用"；本卡补了痛点开场+房卡类比+线程安全边界。两卡口径一致，A5 里"#25 所有权随返回值转移"那句仍是关键桥接。
- **真题锚**：OPPO「智能指针的优势、为什么可以自动释放」／小米「weak_ptr 的使用场景、如何避免循环引用」。
- **项目桥**（1 句）：我们 C 项目里"谁分配谁释放、所有权随接口转移"的手动纪律，对应的就是智能指针用所有权规则自动化掉的那件事。
- **考察三问**：
  Q1 智能指针为什么可以自动释放资源？
  Q2 weak_ptr 的使用场景是什么？循环引用是怎么被它打破的？
  Q3 shared_ptr 的引用计数线程安全吗？它指向的对象呢？

### #50 C 与 C++ 的区别 ★★

- **层次声明**：话术层——一条主线讲完，不背语法清单。
- **主轴句**：「C 的哲学是内存和控制在程序员手里，C++ 的哲学是把套路交给语言——类管封装、构造析构管资源（RAII）、模板管泛型、引用和四种转换管类型安全；嵌入式常选 C 是要可控可预测，选 C++ 是工程规模大了要抽象。」
- **一张表**（四个维度=四个可背句）：

| 维度 | C | C++ |
|---|---|---|
| 抽象手段 | 结构体+函数 | 类/继承/多态/模板 |
| 资源管理 | 手动 malloc/free + 纪律 | RAII：构造拿、析构还（容器/智能指针） |
| 类型安全 | void* 强转靠自觉 | 引用、重载、四种 cast 各管一摊 |
| 选型理由 | 可控、可预测、工具链轻 | 大规模工程的抽象与复用 |

- **教学正文**（四层讲）：
  1. **痛点开场**：面试问"C 和 C++ 区别"，千万别背语法清单（C 有啥、C++ 多了啥）。要抓一条主线：**C 的哲学是内存和控制全在程序员手里，C++ 的哲学是把常见套路交给语言去管**。嵌入式选 C 是要"可控可预测"，工程规模大了选 C++ 是要"抽象和复用"。
  2. **生活类比（手动挡 vs 自动挡货车）**：
     - C = 手动挡货车，离合、换挡、油门全在你脚下，急刹车时刹车距离你能算出来；但塞车时你左脚踩得抽筋。
     - C++ = 自动挡货车，变速箱帮你换挡（RAII 自动回收、模板自动生成类型安全代码、类自动管初始化）；代价是你不知道它啥时候自己换了挡，极端情况下不可预测。
     - 嵌入式（IMX6ULL 这种）选 C：要的就是"每一步我都知道它在干嘛"，不能赌变速箱心情。
  3. **机制映射（四个维度=四个可背句）**：
     - 抽象手段：C 靠 struct+函数；C++ 靠类/继承/多态/模板。
     - 资源管理：C 手动 malloc/free 靠纪律；C++ 靠 RAII（构造拿、析构还，容器/智能指针都是它的产物）。
     - 类型安全：C 靠 void* 强转+自觉；C++ 有引用、重载、四种 cast 各管一摊。
     - 选型理由：C 可控可预测工具链轻；C++ 适合大规模工程的抽象复用。
     - **被追"C++ 多了哪些避免内存泄漏的方法（TP-Link）"**：RAII/智能指针（自动释放）+ 容器代替裸 new[]（vector 代替 new[]）+ 构造函数初始化（避免半初始化对象）——三条正好对应 #49/#51/#54。
     - **被追 C++11（华为）**：auto、右值引用与移动语义、智能指针三样各半句，不展开。
  4. **新手三问预埋**：
     - Q：那我们项目为啥用 C 不用 C++？A：边侧守护进程要可控、要小工具链、要和 FFmpeg 这套 C 库无缝对接；如实答，不装。
     - Q：C++ 是 C 的超集吗？A：不是，个别写法 C++ 更严格（比如 void* 不能随便赋给别的指针）。
     - Q：面试怎么答不超时？A：主线四句 + 选型收尾句，60 秒讲完，等追问再展开。
  5. **与 A5 的关系**：本点是话术层，和 A5 各卡是总分关系——被追问"具体怎么防泄漏"就落到 #49/#51/#54 三个具体卡上。
- **真题锚**：华为「C 与 C++ 的区别、C++11 用得多吗」／TP-Link 联洲「C++ 相对 C 多了哪些避免内存泄漏的方法」／大华「用 C 多还是 C++ 多」。
- **项目桥**（1 句）：如实答"项目是 C 写的，但 C++ 的 RAII 思想在 C 里对应我们'谁分配谁释放'的所有权纪律"——一句把缺口变成桥。
- **考察三问**：
  Q1 C 和 C++ 的区别，用一条主线讲清楚。
  Q2 C++ 相比 C 多了哪些避免内存泄漏的手段？
  Q3 你平时用 C 多还是 C++ 多？嵌入式为什么常选 C？

### #51 构造/析构 ★★

- **层次声明**：语言语义；虚析构的机制归 #48 第 2 条，这里管"何时、几种、空对象"。
- **主轴句**：「构造=出生时的初始化责任，析构=死亡时的清理责任，都在语言强制的时间点被调用——这是 RAII 的地基；空类占 1 字节是为了让每个对象有独一无二的地址。」
- **一张表**（虚析构判断框架）：

| 场景 | 基类析构要虚吗 |
|---|---|
| 可能用基类指针 delete 派生对象 | **必须**（否则派生部分不清理） |
| 总是按具体类型删/栈对象 | 不必（虚表开销白花） |
| 类不打算被继承 | 不必（可标 final 思想：不提供虚机制） |

- **教学正文**（四层讲）：
  1. **痛点开场**：C 里你 malloc 完一块内存，里面值是随机的，得自己手动初始化；C++ 把"初始化"这件事绑死在对象出生那一刻——构造函数。同理，释放资源绑死在死亡那一刻——析构函数。**这两个时间点由语言保证，不需要你记**——这就是 RAII 的地基。
  2. **生活类比（出生证与遗嘱）**：
     - 构造 = 人出生，医院办出生证，把该填的信息填齐（成员初始化）。
     - 析构 = 人去世，办死亡证明+遗嘱，把生前租的钥匙、借的书还回去（释放资源）。
     - **空类占 1 字节 why（宇视原题）**：酒店走廊上的房间门牌——哪怕房间是空的，也得有个门牌号；不然两个房间门牌号一样，客人（数组里的对象）会走错门。如果空类大小是 0，`A arr[10]` 里每个元素地址都一样，指针运算和"每个对象地址唯一"这个基本假设全崩。1 字节就是保证每个对象有独一无二的地址。
  3. **机制映射**：
     - **几种构造**：默认构造（无参）、拷贝构造（用同类另一个对象初始化）、移动构造（C++11，"偷"对方资源）、委托构造（让另一个构造函数先干一部分活）。一句级：不传参就默认、用别人对象初始化就拷贝/移动。
     - **顺序**：构造=基类→成员→本类体；析构严格反序（先本类体→成员→基类）。
     - **虚析构判断框架**（见上表）：只要可能"用基类指针 delete 派生对象"就必须虚；总是按具体类型删、或不打算被继承，就不必加。
  4. **新手三问预埋**：
     - Q：空类加了虚函数还是 1 字节吗？A：不是，多一张工牌（vptr），大小变成指针大小（挂 #48）。
     - Q：构造函数能有返回值吗？A：不能，连 void 都不写。
     - Q：析构函数能被显式调用吗？A：技术上能，但那是 placement new 的配套玩法，正常别用。
  5. **与 A5 卡 4 的关系**：虚析构的"必须/不必"判断两卡口径一致；本卡多补了空类 1 字节的门牌类比和四种构造。
- **真题锚**：宇视「C++ 中空对象占几个字节」／宇视「构造函数有哪几种？虚函数和纯虚函数区别？」／CVTE「析构何时声明为虚函数？」。
- **项目桥**：不配（项目纯 C，纯语义点不硬凑）。
- **考察三问**：
  Q1 空类为什么占 1 字节？
  Q2 构造函数有哪几种？分别在什么时候被调用？
  Q3 基类析构函数什么时候必须写成虚的？不写会怎样？

### #52 new/delete 与 malloc/free ★

- **层次声明**：C++ 语言层；底下内存还是 #45 那套堆，本点只管语言包装的差异。
- **主轴句**：「new = malloc 之后再干两件事——调构造函数、返回带类型的指针不用强转；delete = 先析构再 free。底下是同一套堆，只是包了语言这层皮。」
- **一张表**（三差 + 配对）：

| 维度 | malloc/free | new/delete |
|---|---|---|
| 构造析构 | 不管 | new 调构造、delete 调析构 |
| 返回值 | void*，要强转 | 正确类型指针 |
| 失败行为 | 返回 NULL | 抛 bad_alloc（可捕获） |
| 可重载 | 否 | 可按类定制 |
| **数组配对** | — | new[] 配 delete[]：编译器在块里记了元素个数，delete[] 才能逐个析构；用 delete 只析构第一个 |

- **教学正文**（四层讲）：
  1. **痛点开场**：malloc 给你的是一块裸内存，里面值随机。但 C++ 对象 = 内存 + 初始化状态——构造函数没跑，成员没初始化，vptr 没设。所以对 C++ 对象用 malloc，相当于**给了躯体没给灵魂**（A5 卡 1 原话）。new 干的就是"malloc + 把灵魂安上"。
  2. **生活类比（租房+摆家具）**：
     - `malloc(40)` = 房东交一把空钥匙，房里墙皮都没刮。
     - `new Obj` = 交钥匙 + 房东**顺便把家具摆好、挂好窗帘、把名牌写上**（调构造函数），返回带类型的指针不用强转。
     - `delete p` = 你走之前把家具搬空（调析构）再交钥匙。
     - `free(p)` = 直接交钥匙，家具全扔房里。
     - `new[]` = 租一整层楼 N 户；房东在楼下大堂挂个牌"本层共 N 户"（典型实现把元素个数存在块头）。
     - `delete[]` = 看到大堂牌子，逐户敲门通知搬家（逐个析构），再整层退租。
     - **错用 delete（该 delete[]）** = 只敲开第一户门说"你搬吧"，其他 N-1 户不知道要走，家具全扔里头（资源泄漏）；而且按一户的块大小去退租，和大堂牌对不上，堆元数据直接崩。
  3. **机制映射**（保留三差表）：
     - new 是关键字（编译器认识，可重载）；malloc 是库函数。
     - new 失败抛 bad_alloc（可 try/catch，或 `new (std::nothrow)` 拿 NULL）；malloc 返回 NULL 自己查。
     - new 自动算类型大小；malloc 手算字节数。
     - **配对铁律**：new/delete、new[]/delete[]、malloc/free 三对严禁混用。
  4. **新手三问预埋**：
     - Q：new 比 malloc 快吗？A：错——底层都走分配器，new 赢在语义完整不是速度。
     - Q：delete 完顺手 free 一下？A：双重释放，未定义行为。
     - Q：placement new 是啥？A：在已分配内存上直接调构造，知道存在即可（边界句）。
  5. **与 A5 卡 1 的关系**：A5 卡 1 是 P1 最小集，"给了躯体没给灵魂"那句话仍是答题金句；本卡补了 delete[] 为啥必须配对的大堂牌类比。
- **真题锚**：海康「delete [] 和 delete 的区别」／华为「C 中 malloc 和 C++ 中 new 的区别」。
- **项目桥**：不配（纯语义点）。
- **考察**（选答级两问）：Q1 malloc 和 new 的区别？Q2 delete 和 delete[] 为什么必须配对？

### #53 extern "C" 与符号链接 ★

- **层次声明**：编译/链接层；只到"符号名对不对得上"，PLT/GOT 延迟绑定是邀约线不展开。
- **主轴句**：「C++ 为了支持重载，把函数名编码成带参数信息的修饰名；C 不编码——extern "C" 就是叫 C++ 编译器'这段按 C 规矩来，别修饰'，否则 C 编译的目标文件和 C++ 编译的目标文件符号对不上，链接器报 undefined reference。」
- **一张图**（符号对照）：
```
同一份代码 int foo(int):
  C 编译的符号表:   foo          ← 链接器找这个
  C++ 编译的符号表: _Z3fooi      ← 名字带上了参数信息
C++ 调 C 的库: 找 _Z3fooi → 库里只有 foo → undefined reference
加 extern "C": 强制不修饰 → 两边都是 foo → 链上
```
- **一张表**（排错三步）：

| 步 | 动作 | 工具 |
|---|---|---|
| 1 看报错 | undefined reference 到谁 | 链接器输出 |
| 2 看两边符号 | 目标文件/库里符号长什么样 | nm a.out / nm -D libxxx.so |
| 3 修 | 给 C 头文件包 extern "C"（__cplusplus 宏守卫） | 代码 |

- **教学正文**（四层讲）：
  1. **痛点开场**：你 C++ 代码里调一个 C 编译出来的库，链接器突然报 `undefined reference to foo(int)`——代码明明都在，为啥找不到？因为 C 和 C++ 给同一个函数记的"名字"不一样。
  2. **生活类比（公司门卫查工牌）**：
     - C 员工工牌上就写两个字"张三"。
     - C++ 因为要支持重载（同名函数 `foo(int)` 和 `foo(float)` 都叫 foo），工牌上写成"张三(男,30岁,工程师)"这种带参数信息的全名——这就是**名字改编（name mangling）**，比如 `foo(int)` 编成 `_Z3fooi`。
     - 门卫（链接器）按工牌字面对人：C 库门口挂的牌子是"张三"，你 C++ 员工找的是"张三(int)"，门卫说"查无此人"（undefined reference）。
     - `extern "C"` = 你跟 C++ 员工说"你跟 C 库对接时，工牌别带参数了，就写'张三'"——两边工牌格式一对，门卫放行。
  3. **机制映射**：
     - 标准头文件写法：`#ifdef __cplusplus extern "C" { #endif ... 声明 ... #ifdef __cplusplus } #endif`——`__cplusplus` 这个宏只有 C++ 编译器定义，所以这张"特别工牌"只有 C++ 员工领，C 员工看了当没看见；同一份头文件两种编译器都能吃。
     - **排错三步**（见上表）：看报错找谁 → nm 看两边符号长啥样 → 给 C 头文件包 extern "C"。
     - **反向变式**：C 调 C++ 的函数？C++ 侧把对外函数声明成 extern "C" 做包装，本质同一步。
     - **一句坑**：C++ 头文件里的 C++ 函数不能塞进 extern "C"（重载会撞名）。
  4. **新手三问预埋**：
     - Q：extern "C" 把代码编译成 C 了吗？A：没有——**只管名字怎么记，不管代码怎么编**（A5 卡 3 金句）。
     - Q：nm 命令怎么用？A：`nm a.out` 看目标文件符号表；`nm -D libxxx.so` 看动态库导出符号。
     - Q：FFmpeg 是 C 库，我们项目为啥没写 extern "C"？A：因为我们整个项目就是 C 写的；FFmpeg 自己的头文件里已经包好了 `#ifdef __cplusplus` 守卫，将来哪个 C++ 工程 include 都直接能用（项目桥备用句）。
  5. **与 A5 卡 3 的关系**：A5 卡 3 是 P1 最小集，"只管名字不管代码"那句仍是答题金句；本卡补了工牌类比和排错三步。
- **真题锚**：海康「extern "C" 有什么用、为什么声明 C 语言环境」／中兴「C++ 调 C 符号对不上怎么解决」。
- **项目桥**：不配（项目纯 C 单语言；但 FFmpeg 头就是 C 库，若被追可说"我们调的 FFmpeg 头文件里有 extern C 守卫"一句——按追问备用，不主动铺）。
- **考察**（选答级两问）：Q1 extern "C" 是干什么的，不加会怎样？Q2 链接时报 C 符号 undefined，你怎么排查？

### #54 STL 容器与扩容 ★（全景版）

- **层次声明**：库用法层；"为什么红黑树/哈希冲突/堆与 TopK"归 #56，本点只管列举、扩容、选型。
- **主轴句**：「容器按'怎么组织数据'分四族——序列、关联（有序）、无序（哈希）、适配器；vector 是默认选：内存连续对缓存友好，扩容成倍翻、元素搬迁，摊到每次 push_back 是 O(1)。」
- **一张图**（四族分类 + 扩容三时刻）：
```
 序列:  vector(数组) deque(双端) list(双向链表)
 关联:  map / set          —— 底层红黑树,按 key 有序
 无序:  unordered_map/set  —— 底层哈希表
 适配器: stack / queue / priority_queue —— 拿别人包一层,限操作

 vector 扩容三时刻: capacity 满 → 申请更大新内存(常见 1.5~2 倍,标准未规定)
                  → 旧元素搬到新家 → 旧内存释放(此刻旧迭代器/指针全部失效)
```
- **一张表**：

| 问题 | 答案锚 |
|---|---|
| 扩容为什么摊销 O(1) | 成倍翻 → 搬迁总量是几何级数，摊到 n 次 push_back 每次常数 |
| reserve vs resize | reserve 只加产能不改 size（元素数不变）；resize 改 size，多出的元素给初值 |
| vector vs list | 随机访问+缓存友好 vs 任意位置 O(1) 插删；默认 vector，插删不在头尾且频繁才考虑 list/deque |
| map vs unordered_map | 红黑树 O(log n)、按序遍历 vs 哈希平均 O(1)、无序；深入归 #56 |
| 迭代器失效 | vector 扩容全失效；list/map 插入不失效、删除仅指向被删元素的失效（一句级） |

- **教学正文**（四层讲）：
  1. **痛点开场**：C 里你要个动态数组、要个字典、要个队列，全得自己手搓——malloc 数组、写增删、管扩容、防越界。STL 就是把这些"搓好的轮子"给你，但你得知道每个轮子内部咋转，不然选错容器性能塌方。
  2. **生活类比**：
     - **序列容器** = 排队打饭：vector 是单人紧挨队（找第 100 个 O(1)，但中间插人要把后面全队往后挪）；list 是手拉手但中间有空隙的队伍（插人 O(1)，但找第 100 个要从头数）；deque 是两头都能加人的队。
     - **map/set** = 按拼音排好的字典，查一个词要翻 log n 页，但遍历时天然有序。
     - **unordered_map/set** = 字典后面加了个索引表，查词直接跳过去（哈希），平均 O(1)，但顺序是乱的。
     - **适配器（stack/queue/priority_queue）** = 拿别人包一层，只露特定操作（你只能 push/pop，不能乱访问中间）。
     - **vector 扩容 = 换大食堂搬家**：
       1. 现在食堂坐满了（capacity 满）；
       2. 租个大 1.5~2 倍的新食堂（标准未规定倍数，常见实现 1.5~2 倍）；
       3. 把所有人从旧食堂搬到新食堂（拷贝/移动，C++11 起是移动）；
       4. 旧食堂退掉——**所有拿着旧地址找你的人全部扑空（旧迭代器/指针/引用全失效）**。
  3. **机制映射**：
     - **为什么 push_back 摊销 O(1)**：每次搬家后新食堂是旧的 1.5~2 倍，搬家总次数是几何级数增长，摊到 n 次 push_back 上每次是常数。反过来说：为啥不一次租最大？浪费内存；为啥每次只扩 1.5~2 倍而不是加固定 100？加固定数的话总搬迁量是 O(n²)。
     - **reserve vs resize**：reserve = 先租好大食堂但还没坐人（capacity 变大，size 不变）；resize = 直接坐满 N 个人（size 变大，多出的元素给初值）。
     - **vector vs list 选型**：默认 vector（内存连续对缓存友好，随机访问 O(1)）；只有"频繁在中间插删、且元素很大"才考虑 list/deque。
     - **map vs unordered_map**：要有序遍历/范围查询选 map；只要快速按键取值选 unordered_map。
     - **迭代器失效**：vector 扩容全失效；list/map 插入不失效、删除仅指向被删元素的失效。
  4. **新手三问预埋**：
     - Q：标准规定 vector 按 2 倍扩容吗？A：**没规定**，常见实现 1.5（libstdc++）~2（MSVC）倍——把话说成"标准规定 2 倍"是边界翻车点。
     - Q：C 里这些容器对应啥？A：vector 对应环形缓冲/动态数组、map 对应手写的有序链表——"C 里这些要手搓，STL 是搓好的"（项目桥）。
     - Q：C++11 新特性提啥？A：auto、右值引用与移动语义（扩容搬迁从拷贝变移动）、智能指针三样各半句。
  5. **与其他卡的关系**：红黑树为啥平衡、哈希冲突怎么解决、堆与 TopK 归 #56 卡深挖；本卡只到列举+扩容+选型。
- **真题锚**：宇视「C++ 中的 STL 都有什么数据结构」／荣耀「C++11 新特性；智能指针；STL 容器」。
- **项目桥**（1 句）：C 项目里对应物=我们手写的环形缓冲和链表，答 C++ 时可一句"C 里这些要手搓，STL 是搓好的"。
- **考察三问**：
  Q1 STL 里有哪些容器？各自底层是什么？
  Q2 vector 扩容机制讲一下，为什么 push_back 还算 O(1)？
  Q3 reserve 和 resize 的区别？vector 和 list 你什么时候选谁？
