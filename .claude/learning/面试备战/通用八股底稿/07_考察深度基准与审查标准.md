# 07 · 考察深度基准与审查标准

> 建档:2026-10-10 晚。定位:04 号(执行规格)判分层的**可执行细化**——开考前先立"面试够用线"和判卷尺,后续一切快筛/验收/抽检/模拟面试的判卷按本文执行。不新立体系:三句+变式封顶、判卷=机制+权威源、错题三态机、熔断均继承 04。
> 产生背景:用户要求分批考核(一批一循环)、题目须考察真实掌握度、并先明确"通过达到什么程度、后续保温还是继续学"。

---

## 一、深度基准:"面试够用"的两条线

| 档 | 够用线(判"过"=达到) | 面试视角翻译 | 上限(刻意封顶) |
| --- | --- | --- | --- |
| **P0**(30 点) | 三句:①结论 ②一条因果(why)③边界或常见错法;外加一个**变式**接住 | 面试官连追两层(是什么 → 为什么 → 换个情况还成立吗)不塌,**校招一面此点即过关** | 三句+变式封顶;"底层一句"/项目滑入=自愿加分,不挡通过 |
| **P1**(10 点) | 两句:结论 + 一个 why | 被问到两句站住;再被追边界,诚实交"再深没学" | 不备变式、不备边界 |

两条校准说明:

1. **这个深度是"面试够用"不是"满分"**:三句封顶是刻意设计——通用八股再深,边际收益低于项目深挖与场景题;面试里更深的层(底层实现追问、事故推演、系统设计)由项目资产承接,不在本区加深度。趋势类"底层怎么实现"问法用「底层一句」应对,一句即止。
2. **判卷基准源**:机制 + 权威源(man7 / APUE / TLPI / RFC / C 与 C++ 标准)。飞书不是标准;飞书与机制冲突按机制判,冲突句记错题册替换句并回飞书旁改。

## 二、审查标准:五维判卷 + 特殊判定

每个点的回答按五维过:

| 维度 | 判什么 | 硬度 |
| --- | --- | --- |
| 1 事实正确 | 结论与机制是否符合权威源 | **一票否决**:概念错直接"不过" |
| 2 因果完整 | why 是机制因果链,不是结论换说法再念一遍 | 缺 → "条件过"(缺 why 句) |
| 3 深度达线 | 该档句数结构是否齐(P0 三句 / P1 两句) | 缺哪句记哪句,只补缺句 |
| 4 边界意识 | 有没有把话说过头(说满) | **红线**:概念级说满="不过";普通说满(结论对但讲过界)=最高"条件过" |
| 5 变式应对 | 换一个条件后能否**当场判断**对错(不是背原题) | 接不住 → "条件过",不降"不过" |

特殊判定:

| 情形 | 处置 |
| --- | --- |
| 背书腔(疑似背笔记) | 不预先扣档;当场换条件追问,以变式结果定档 |
| 术语错但因果不受影响(如 packet/frame 混用) | 当场纠偏,不影响判档;影响因果链的术语错=事实错 |
| 结论说不出但有部分正确直觉 | "不过",但教学步从已有直觉接,不整点重讲 |
| 选择/判断答 `?` | 按黄:该点走完整验收 |
| 答"没" | 按红:该点从零学 |
| 选择题乱猜答对 | 快筛第二关(口头 why)拦住:why 答不出不算绿 |

## 三、判定 → 达到程度 → 处置(保温还是继续学)

| 判定 | 达到什么程度 | 后续动作 | 保温/继续学 |
| --- | --- | --- | --- |
| **快筛过**(选择对 + 口头 why 过) | 结论与机制初步站住,但未经教学与复测检验 | 标"快筛过",**≥3 天后抽检一个变式** | 半保温:不学,等抽检 |
| 抽检变式过 | 与验收"过"同级:一面深度达标 | 进观察,≥3 天再一变式 | 保温 |
| **验收"过"**(三句 + 变式) | **一面够用**:该点两层追问不塌 | 进观察(≥3 天)→ 已稳 | 保温 |
| **验收"条件过"** | 差一句(缺 why 或缺边界) | 下一场只补那一句 | 继续学(单句级) |
| **验收"不过"** | 概念错或结论说不出 | 回飞书该节 → 下一场变式重问 | 继续学(整点) |
| **已稳**(观察到期变式过) | 长期持有 | 不再单独复习,只在模拟面试里碰到 | 全保温 |

- **保温期仅两个动作**:每过两批 P0 一场模拟面试(冷面+2 探针,探针专打已稳点防回归);临面前把待复测/条件过/到期观察过一遍。
- **熔断继承 04**:待复测 >12 条或同条两次未出 → 停新点专场清偿。
- **收口线**:P0 全部点"已稳" + P1 一轮 = 通用八股区收口,时间转投项目保温/情景题库/投递。

## 四、样例:同一点的三档对照(TIME_WAIT)

问题:"TIME_WAIT 是什么?为什么要等 2MSL?"

| 档 | 学生答案长这样 | 为什么是这个档 |
| --- | --- | --- |
| **过** | "主动关闭方发完最后一个 ACK 后进 TIME_WAIT,等 2MSL(结论)。因为最后的 ACK 可能丢,对方会重发 FIN,得留着应答;同时让旧连接的迟到报文在网上过期,不被新连接误收(why)。代价是主动方端口被占,大量短连接会耗尽端口(边界)。" 变式"最后那个 ACK 丢了会怎样?"→"对方重发 FIN,我还在 TIME_WAIT,能再答一次" ✓ | 三句齐 + 变式当场接住 = 一面够用 |
| **条件过** | "TIME_WAIT 是关闭后等 2MSL 的状态,大概一两分钟。" 追问 why:"…为了确保数据都传完吧?" | 结论对;why 是含糊猜测句(且"确保传完"不准确),边界没交——缺 why |
| **不过** | "TIME_WAIT 出现在被动关闭的一方,等对方把数据收完。" 或 "有了 TIME_WAIT 连接就绝不会出问题。" | 前者概念错(在主动方)一票否决;后者概念级说满 |

## 五、分批考核流程(一批一循环,2026-10-10 用户定)

| 步 | 做什么 | 说明 |
| --- | --- | --- |
| 1 | tutor 发该批选择+判断题(每点 ≤1 题,选项埋常见错法) | 学生闭卷笔答;`?`/“没”照实写,不猜 |
| 2 | tutor 判卷,**当场对答对的点追问 1 个 why(第二关,口头)** | 考掌握不考认字:why 答出 = 该点绿 |
| 3 | 出该批结果表:每点 绿(快筛过)/ 黄 / 红 + 判定依据 | 绿点 ≥3 天后进抽检漏斗 |
| 4 | 黄/红点 = 该批验收场清单 →「验收飞书:批 N 的红黄点」走 04 三段式 | 考察 → 教学 → 复盘,25–40min |
| 5 | 该批全部点闭环(快筛过或验收过)→ 批次通过,进下一批 | 绿点不必等验收,先行 |

批次通过 ≠ 整批保温:批内各点各自走"观察 → 已稳";全部点已稳,整批才入保温池。
