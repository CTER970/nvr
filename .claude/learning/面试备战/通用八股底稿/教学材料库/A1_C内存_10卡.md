## 卡 1 · #16 内存分区（A 层·高频 12 家·承重墙·内存墙锚点）

**主轴句**（v2.1 双句版）：一个对象三个问题——放在哪、活多久、谁管；堆与栈的答案就是「谁分配谁回收」。
**层次声明**（开教必说）：本卡主线=进程运行时的典型虚拟地址空间；补语言存储期与 ELF 节的对应——三层相关但不等价（防"局部变量一定在栈/const 一定在 .rodata"一族混淆）。

**结构图**（低地址→高地址）：
```
.text/.rodata(代码+字面量,只读) → .data(已初始化全局/static,占文件体积) → .bss(未初始化,不占体积加载清零)
→ [堆 ↑ 向上长] → ↓ 空隙 ↓ → [mmap 映射区(libc/共享库)] → [栈 ↓ 向下长,默认8MB] → [内核空间]
```

**维度表**：

| 区 | 放什么 | 谁管 | 三特征 |
|---|---|---|---|
| .text/.rodata | 代码+字符串字面量（.rodata） | 系统 | 只读，写=段错误 |
| .data | 已初始化全局/static | 系统 | 占文件体积，初值逐字节存文件 |
| .bss | 未初始化全局/static | 系统 | 不占体积只记"清零 N 字节"，随进程同寿 |
| 堆 | malloc 动态分配 | **程序员** | 慢(找空闲块/合并)；忘了 free=泄漏 |
| 栈 | 局部变量/返回地址/帧 | **编译器** | 快(SP 一拨)；生命周期=作用域；上限约 8MB |

**机制演示**（SP 记账 demo）：main 调 work()：SP=1000→(bl 压 lr+旧 fp、sub sp)→SP=960→return：从栈取返回地址装 PC+SP 写回 1000。**内存一字节没动**——释放=记账作废，下个函数直接复写（悬空指针还能读到旧值=铁证）。

**分层答案**：
- **L1**：六区名：代码/.data/.bss/堆/栈/映射区（+内核），堆向上栈向下。
- **L2**（三句式）：①栈管调用帧（局部变量/返回地址）编译器自动伸缩，堆管动态分配程序员手动配对 malloc/free；②栈快是因为 SP 一条指令一拨、堆慢是因为要找空闲块还要维护元数据；③.bss 不占文件体积——文件只记"清零 N 字节"，加载器到时清零，.data 初值逐字节进文件所以占体积。
- **L3**（项目）：frame_grabber 最新帧在堆——跨线程长期持有，生命周期要逃逸出函数帧，栈给不了（主循环不 return，循环体局部占固定栈槽每轮被复写）；send_all(fd,buf,len) 必须传 len——栈上数组传参即退化成指针；g_running 与 static 模块状态在 .bss——随进程同寿+默认零，正是标志位想要的语义。
- **L4**：加载器把 ELF 段映射进地址空间（.text r-x/.data rw/.bss 匿名零页 COW 共享）；爆栈=SP 越过栈底保护页→段错误，无保护方向则踩映射区数据静默损坏。

**真题问法**：
- "进程的内存空间怎么划分/全局静态变量存储位置"（Z-015 大华 B2-06、Z-002 海康 B2-04、Z-013 大华 B2-08）
- "C 语言程序运行时的内存分配"（Z-002 海康 AV-02）
- "全局/局部/malloc 的内存分别在哪个区"（Z-065 大疆 B2-15）

**变式池**（v2.1 新增，迁移考察用——教学中未出现过的新代码）：①`void f(void){ static int a; const int b=10; char *p=malloc(32); }`——a/b/p/*p 各从哪些角度判断？哪些只是"通常情况"？②反向指针题：哪个对象由指针访问，但指针本身和对象不在同一个区？（p 在栈、*p 在堆；static 指针在 .bss、对象在堆）③爆栈变式：SP 从 960 往下越界，踩的是谁的内存？

**扩容笔记 · 栈溢出/守卫页/MMU 保护**（❌ 2026-10-19 首答未出 · 高频复习；学生整理稿经 tutor 核验修正后收录——原稿"栈下方是全局静态区→堆"系层次混淆复发，已按 Linux/裸机两模型修正）：

爆栈时 SP 向低地址生长——**Linux 进程模型**：栈下方第一邻居是 mmap 映射区（全局静态区在低地址端，隔着整个地址空间够不着；大跳跨过守卫页踩的是共享库数据）；**裸机模型**：RAM 布局自底向上 .data/.bss→堆→栈，往下越界先踩堆、再踩静态区（无保护页，静默破坏，可能跑飞或复位）。有 MMU 时栈下方设守卫页：内核故意不建页表映射的一页——不对应物理页、不占内存，"不可访问"通过"不存在"实现。MMU 每次访存拿虚拟地址查页表：查到且权限够→译出物理地址放行；查不到（或权限不够）→缺页异常陷入内核，按出错地址（x86 存于 CR2）与访问类型裁决——良性缺页（demand paging/写时复制/栈自动扩展）补映射后重执行指令无感知，恶意访问投递 SIGSEGV 当场崩溃。**守卫页是绊线不是墙**：保护以页表为中心逐次核验，不跟踪 SP 轨迹——巨型栈帧（alloca/VLA/大数组）一步拉低 SP、跨过守卫页直接落到已映射可写区域时，翻译成功直接放行，无异常、内核不知情，静默踩坏数据且暴露无保证。此即 Stack Clash（CVE-2017-1000364），修复=加宽绊线（guard gap 64 位默认 1MB/32 位 256KB）+ -fstack-clash-protection 令 SP 下移时逐页探测步步踩线。

**首卡壳点**（复习先看）：跨过守卫页落到已映射区为何静默——MMU 只逐次查页表不跟踪 SP，翻译成功即放行；无异常则内核连知情的机会都没有。

**联动补**：本笔记预付 #21 缺页第三分支"栈扩展"（VMA·VM_GROWSDOWN·额度判决）与 14 号卡爆栈估算。

**坑点措辞险**：①字符串字面量在只读段不在栈；②static 局部变量在 .data/.bss **不在栈**；③"堆上不清理就一直保存"→安全版"帧能长期存在是因为没人调 free，堆只是没有自动回收机制的区域"；④别用"被回收"说栈——用"作废可复写"（防"谁回收的"追问陷阱）。

**边界句**（L4 答不上时）："ELF 段属性和加载器细节我了解到映射这一层，链接脚本如何排段是 BSP 侧的活，我知道它决定各区起址。"

**联动**：#18（生命周期）／14 号卡（栈帧机制=本卡 L2 深化）／#19（static 去向）／#21（虚拟内存是本卡的"为什么有地址空间"层）。

**状态**：条件过→复述通过（10-18 试点场，范式首例）；悬账变式=爆栈 960 往下越界踩谁。

## 卡 2 · 14 号 · 函数调用与栈帧（高频实证 6 家·下次面试最高优先）

**主轴句**：调用=压返回地址开新帧，返回=PC 跳回+SP 回拨——全程只有两个寄存器被写。

**结构图**（一帧的解剖，高地址→低地址）：
```
[参数区:第5个及以后的参数] ← 调用方压
[返回地址] ← bl/call 硬件压(先经 lr)
[旧 fp(rbp)] ← 被调方 prologue 压
[局部变量/保存的临时寄存器] ← sub sp 开出
SP →———
```

**维度表**：

| 动作 | 谁做 | 具体内容 |
|---|---|---|
| 传参 | 调用方 | ARM AAPCS 前 4 参走 r0-r3，第 5 参起压栈；x86-64 走 rdi/rsi/rdx/rcx/r8/r9 |
| 压返回地址 | call/bl 硬件 | 返回地址=call 下一条指令地址；ARM 先写 lr，被调方要再调人才转存栈上 |
| 开帧 | 被方 prologue | 压旧 fp→设新 fp→sub sp,N |
| 收帧 | 被方 epilogue | 取返回地址装 PC（ARM 常见 pop {fp,pc}）+SP 回拨 |
| 递归 | — | 每层一帧，SP 持续下降，无终止=爆栈（帧大小×深度 vs 8MB） |

**机制演示**（三时刻快照）：①call 前 SP=1000；②work 执行中：旧fp(996)/返回地址(992)/局部(960-991)，SP=960；③return 后：PC=返回地址、SP=1000，旧帧内存原样躺着"作废待复写"。

**分层答案**：
- **L1**：前几参走寄存器、call 压返回地址、保存旧帧指针、局部变量从帧指针往下分配。
- **L2**：①返回地址是 call/bl 指令的硬件动作压的，不是函数代码，被调方只有再调人时才把 lr 转存栈上；②第 5 参起入栈是 AAPCS 调用约定，编译器链接器都认；③返回时恢复 fp/sp 按保存的返回地址跳回，这一帧弹掉——内存没动，复写交给下个函数。
- **L3**：frame_grabber/cloud_ai 独立线程各有一份栈（Linux 线程默认 8MB，ulimit -s 可查可调）；线程主循环不 return，循环体局部变量固定槽每轮复写；30 个局部变量上下文切换不用逐个保存——换 SP 即换整栈，PC/SP/通用寄存器整套现场才是切换对象。
- **L4**：ARM 满栈/空栈×升/降四种组合（MCU 启动文件配）；fp 链是栈回溯(backtrace)的依据；优化 -O2 可能省 fp（frame pointer omit）导致回溯要用 unwind 表。

**真题问法**：
- "栈指针指向栈顶还是栈底/函数返回时如何知道返回地址/栈指针如何恢复"（G-003 TCL 2026-09）
- "从汇编角度看函数调用过程/main 调用函数哪些汇编指令一定会被用到"（Z-075 TP-Link 上海）
- "递归、栈溢出"（Z-031 睿联）"函数调用参数存在哪里/局部变量存在哪里/30 个局部变量上下文切换如何保存"（Z-068 影石）

**坑点措辞险**：①"返回地址是函数内部压的"→是 call 指令；②"局部变量一定在栈上"→可能寄存器化、static 的在静态区；③"传参都走栈"→前几参走寄存器；④"上下文切换保存局部变量"→保存现场（PC/SP/寄存器），局部变量本来就在栈里。

**边界句**："手写汇编/启动文件配置我没有一手经验，我说的是用户态 C 视角的调用约定+帧布局；指令编码级细节到这就到边界了。"

**联动**：#16（分区是本卡的容器）／#18（生命周期=帧的存续）／P1#36（RTOS 任务栈 vs Linux 线程栈 8MB——萤石原题）。

**状态**：未开始→机制层已预付（10-18 试点：返回地址/SP/复写/悬空铁证）；剩缺口=AAPCS 传参、30 变量切换问法、爆栈变式——下场从缺口切入。

## 卡 3 · #18 栈和堆的生命周期（中高频·小米已过线保温）

**主轴句**：栈的生命周期由作用域强制结束，堆的生命周期由你手动决定——想活多久活多久，代价是忘了 free 永远不回收。

**结构图**：
```
时间轴: 栈变量 ████▄(出作用域即作废)   堆块 █████████████(free 前一直活,可跨函数/跨线程/跨轮循环)
        ↑SP 回拨即作废                  ↑唯一死法=free/munmap 或进程退出
```

**维度表**：

| 维度 | 栈 | 堆 |
|---|---|---|
| 分配/释放 | 编译器插的指令（sub sp/pop） | malloc/free 跑库逻辑 |
| 速度 | 一条指令 | 找空闲块+维护元数据 |
| 大小 | 小（默认 8MB 上限） | 大（受物理内存/虚拟地址限制） |
| 生命周期 | 作用域强制 | 手动，无上限 |
| 典型错误 | 爆栈/返回栈地址 | 泄漏/悬空/碎片 |

**机制演示**：返回局部变量地址 bug：`int* f(){int x=10;return &x;}` ——return 后 SP 回拨，x 作废；调用方拿到的指针指向"下个函数随时复写的草稿区"，读到 10 纯属运气。堆版：malloc 的指针 free 前永远有效。

**分层答案**：
- **L1**：栈随函数生灭自动管，堆 malloc/free 手动管。
- **L2**：①栈变量出了作用域就作废（SP 回拨+待复写），指针带出函数=悬空；②堆块 free 前一直有效，可以跨函数跨线程传递——这正是它存在的意义；③代价配对：自动换不自由、自由换要负责（泄漏只可能发生在堆）。
- **L3**：frame_grabber_get_jpeg 返回 malloc 拷贝——深拷贝到堆+调用方 free（线程安全+生命周期归调用方）；采集终端两份深拷贝 P95 约 1ms——堆拷贝的成本有一手数字。
- **L4**：ptmalloc arena/bins 一句（小块 tcache 快路径）；碎片=长期运行反复 malloc/free 后空闲块不连续。

**真题问法**："堆栈的内存区别、什么时候用堆什么时候用栈"（Z-080 TPL 成都）；"栈的作用"（Z-013 大华）。

**坑点措辞险**："栈快堆慢因为栈在高速缓存"——错，主因是分配机制（一条指令 vs 库逻辑）；安全版："栈的分配释放是编译器生成的栈指针操作，堆要走分配器逻辑"。

**边界句**："malloc 内部实现（arena/bins）我了解到'找空闲块+合并'这层，glibc 具体策略没读过源码。"

**联动**：#16／#25（悬空指针）／14 号卡。

**状态**：**过**（10-23 17点深化场：返回栈地址 bug 全链+判断规则+快慢机制收口，锚句见 02 册）。

## 卡 4 · #19 static 三用法（中频·影石原题·段2 复述过待探针）

**主轴句**：static 的三个作用域收缩——局部变量延长生命、全局变量/函数限制链接到本文件。

**结构图**：
```
static 局部变量: 作用域=函数内(不变) + 生命周期=进程级(变长) → 落在 .data/.bss
static 全局变量: 生命周期=进程级(不变) + 可见性=本文件(收缩) → 符号不进全局符号表
static 函数:     可见性=本文件 → 同上,链接器看不见
```

**维度表**：

| 用法 | 改变什么 | 存放 | 典型场景 |
|---|---|---|---|
| 局部变量 | 生命周期→进程级 | .data(有初值)/.bss | 函数内计数器/一次性初始化标志 |
| 全局变量 | 链接可见→本文件 | 同上 | 模块私有状态 |
| 函数 | 链接可见→本文件 | .text | 内部 helper |

**机制演示**（undefined reference 全链）：main.c 里 extern void helper(void); 编译能过（编译器信 extern）→链接器去全局符号表找 helper → helper 在别的文件里是 static，符号不进表 → undefined reference。"链接认的是符号不是代码"。

**分层答案**：
- **L1**：三用法——局部延命/全局限文件/函数限文件。
- **L2**：①static 局部在 .data/.bss 不在栈，初始化只做一次；②static 全局/函数=内部链接（internal linkage），符号不进全局符号表，所以别的文件 extern 声明也链接不到、同名不冲突；③C++ 里还修饰成员（属于类不属于实例）——一句带过。
- **L3**：web.c 用 static 把模块状态封装成文件内私有——模块边界=文件边界，这是 C 的模块化纪律；static 局部变量多线程要加锁（共享一份，不是每次调用新副本）。
- **L4**：符号表/强弱符号；-O 下 static 函数可被内联后删除。

**真题问法**："static 关键字"（Z-078 TPL）"static 修饰局部/全局/函数的作用"（Z-025 星宸 B1-11）"static volatile inline"（Z-032 富瀚微）。

**坑点措辞险**："static 局部变量每次调用初始化"——错，只一次；"static 变量存在栈"——在 .data/.bss。

**边界句**："符号解析和重定位我知道到'链接器查全局符号表'这层，--whole-archive/版本脚本这类细节没实操过。"

**联动**：#16（去向）／#41（undefined reference 与链接四阶段）。

**状态**：**过**（10-23 17点深化场补句收口：第三用法三件+多线程要锁探针自产+全局/函数=符号收缩本文件；锚句见 02 册）。

## 卡 5 · #20 const 与 const 指针（中频·字节/华为原题）

**层次声明**（多层卡必说）：本卡横跨三层——语言语义（编译期约束）/ELF 布局（.rodata 放置）/运行时（段错误保护）；"const 一定在 .rodata"与"const 一定安全"都是层次混淆，先分层再作答。

**主轴句**：const 锁的是"通过这个名字的写操作"——读法：* 左边锁物、* 右边锁指针。

**结构图**：
```
const int *p  ≡ int const *p   → 物不可写(*p=x 编译错), 指针可改(p=&b 合法)
int * const p                  → 指针不可改(p=&b 错), 物可写
const int * const p            → 双锁
```

**维度表**：

| 写法 | 谁被锁 | 项目场景 |
|---|---|---|
| const char *src | 指向物 | strcpy 源参数——"我只读不写"的契约 |
| int *const p | 指针本身 | 句柄类（少见） |
| const 与 #define | 类型检查/作用域/调试可见 | 常量优先 const |

**机制演示**：编译期检查——const int *p 下写 *p=1 编译器直接报错（不是运行期保护）；但通过非 const 别名写同一块内存编译器不拦（const 锁名字不锁内存）——这是"const 不是物理只读"的证据。

**分层答案**：
- **L1**：两种读法（* 左锁物/* 右锁指针）；const int\*≡int const\*。
- **L2**：①编译期约束，违反编不过；②锁的是"这个名字的写权"，不保证内存物理只读（别名可绕）；③接口设计用法=入参契约（src 只读），比注释可靠。
- **L3**：项目里 rtsp_server.c 的 send_all(int fd, const void *buf, size_t len)——buf 只读契约；与 #define 比：有类型、可调试、遵守作用域。
- **L4**：物理只读取决于存放位置：字符串字面量与文件作用域 const 常被编译器放 .rodata（别名写=段错误），局部 const 在栈上可被别名改（语言层 UB 但物理可写）——所以 const 是语言约束，不是内存保护。

**真题问法**："const int *p 与 int * const p"（D-022 华为）"const 修饰指针几种写法/const 和 #define 区别"（Z-065 大疆 B2-15）。

**坑点措辞险**："const 保证只读所以一定有内存保护"——语言层约束≠物理保护，取决于编译器放哪；安全版："const 是编译期检查，文件作用域常量可能进 .rodata（写会段错误），局部 const 物理上可被别名改"。


**边界句**（10-19 补）：汇编层面 const 参数的传参约定与编译器去 const 优化的具体策略我没验证过，语义层（编译期检查/别名可绕）是我的边界，物理放置按 GCC 主线行为说。
**联动**：#24（strcpy 契约）／#16（.rodata）。

**状态**：**过**（10-25 17点深化场补句：三差+边界句+实参兼容性超规格自产收口；两种读法 10-12 已过保留；锚句见 02 册）。

## 卡 6 · #21 虚拟内存与缺页（中高频·睿联原题·小米场过线保温）

**层次声明**（多层卡必说）：本卡主线=进程运行时（地址空间与缺页行为）；虚拟/物理布局是运行时层，"地址空间怎么映射"的页表细节属内核机制层——分层作答防"虚拟布局=物理布局"混淆。

**主轴句**：虚拟内存=每个进程一套独立地址空间，隔离+藏物理碎片+按需分配；缺页=访问还没映射的页时内核补映射。

**结构图**：
```
进程视角: [0 .. 4G 连续虚拟地址]  --MMU+页表-->  [物理内存页(离散)/swap/未分配]
访问未映射页 → 缺页异常 → 内核: 首次访问? 分配物理页建映射 : 从 swap 换入 : 越界→段错误
```

**维度表**：

| 虚拟内存三收益 | 一句话 |
|---|---|
| 隔离 | 进程 A 写不进 B 的空间（页表权限） |
| 藏碎片 | 连续虚拟→离散物理，物理不用连续 |
| 按需/超额 | 先给地址不给内存，用到才分配（overcommit） |

**机制演示**（2M 物理板 malloc 10M）：malloc 返回成功（虚拟地址已预留）→前 2M 边用边缺页边分配→用到第 3M：无 swap→OOM 杀进程。**malloc 成功≠有内存，只代表虚拟地址批下来了。**

**分层答案**：
- **L1**：每进程独立地址空间；访问未映射页触发缺页由内核处理。
- **L2**：①三收益（隔离/藏碎片/按需）；②缺页两分支：首次分配建映射 vs 换入；越界访问=段错误那支；③无 swap≠无虚拟内存——只是不够时不换出直接 OOM。
- **L3**：V4L2 mmap 把驱动 DMA 缓冲映射进用户态（虚拟内存机制的直接应用）；"fork 地址空间看起来一样又不是"=虚拟地址同值物理页 COW 各一份（与 #27 联动）。
- **L4**：多级页表为什么（省页表内存：两级 4K 页 vs 单级全表）；TLB 缓存翻译；COW=页表只读位+写触发。

**真题问法**："虚拟内存/缺页异常/页表"（Z-075 TPL 上海二面）"虚拟内存、递归栈溢出"（Z-031 睿联）"物理地址虚拟地址区别、怎么转换"（D-001 字节）。

**坑点措辞险**："malloc 了就有内存"——错，见 demo；"无 swap 就没有虚拟内存"——错，见 L2③。

**边界句**："页表多级结构和 TLB 我知道到'分级省内存'这层，具体 PTE 位段没背过。"

**联动**：#34 mmap／#27 COW／#16（容器）。

**状态**：**过**（10-23 17点深化场：缺页四分支决策框架+栈扩展+swap 边界+bss 两层链+零页增量收口，锚句见 02 册）。

## 卡 7 · #22 大小端（中低频但有独家场景·PICO 图像题·小米场过线保温）

**主轴句**：字节序=多字节值的字节在内存里的排列顺序；网络序固定大端，htons/htonl 负责转换。

**结构图**：
```
uint32_t 0x12345678:
大端(网络序): 12 34 56 78  ← 高字节在低地址(像人读数字)
小端(x86/ARM默认): 78 56 34 12  ← 低字节在低地址
判断: *(uint8_t*)&x == 0x78 → 小端
```

**维度表**：

| 项 | 大端 | 小端 |
|---|---|---|
| 优势 | 网络序/排序比较字节序 | 强转/位运算方便（取低字节不动） |
| 谁 | 网络协议、部分 DSP | x86、ARM Linux 默认 |

**机制演示**（htons 截断战绩）：32 位字段误用 16 位 htons——**htons 只管序不管宽度**，高 16 位被截断。32 位字段必须 htonl。这是你简历缺陷台账里的一手战绩。

**分层答案**：
- **L1**：定义+union/指针两法判断（要能当场写：`*(uint8_t*)&i` 或 union b[0]）。
- **L2**：①成因=字节可独立寻址+厂商历史选择；②网络序选大端是协议规定，收发两端各自转换（htons/ntohs 成对）；③UDP/TCP 头多字节字段都要转，忘了就是错数据。
- **L3**：图像场景（PICO 原题）：两字节 RGB565 按错字节序解释，高低字节对调，颜色全错——"图像数据传输为什么要关心字节序"的答案就是像素解释依赖字节序；htons 截断 bug 战绩。
- **L4**：RTP 头部 16 位序号网络序——rtsp_server 打包时的实操锚点。

**真题问法**："大端小端是什么、写代码判断"（Z-065 大疆）"图像数据传输为什么要关心字节序"（D-009 PICO）。

**坑点措辞险**：只说"架构差异"给不出判断代码=快筛红点教训；安全版：定义+两法代码+一句 why。


**边界句**（10-19 补）：htonl/ntohl 在不同平台的宏实现（字节交换指令级）我按 x86/ARM 主线讲，网络序与主机序判定的编译期技巧知道一种，交叉场景以头文件实际展开为准。
**联动**：手撕 T0-3（字节序族母题）／RTP 头打包（B 层）。

**状态**：**过**（10-23 17点深化场：htons 截断句自产+网络序大端六要素链终落地——曾三次缺席、一次方向口误后填空收口；锚句见 02 册）。

## 卡 8 · #23 sizeof 与 strlen（中频·场11 满分保温）

**主轴句**：sizeof 编译期算类型宽度，strlen 运行期数到 \0——数组退化那一刻大小信息就丢了。

**结构图**：
```
char buf[64] = "hi";
sizeof(buf)=64 (编译期,整个数组)   strlen(buf)=2 (运行期,数到\0)
传参 f(char buf[]) → buf 退化 char* → sizeof(buf)=8 (指针宽度) ← 大小信息在退化处丢失
```

**维度表**：

| 维度 | sizeof | strlen |
|---|---|---|
| 时机 | 编译期 | 运行期 |
| 对象 | 类型/表达式 | C 字符串 |
| 界限 | 整个数组（含 \0 及未用空间） | 到第一个 \0 为止（不含） |
| O(?) | O(1) | O(n) |

**机制演示**：函数签名 f(char a[100]) 与 f(char *a) 完全等价——编译器把数组参数一律当指针，100 这个信息只留在声明处骗人。所以 send_all 必须带 len 参数。

**分层答案**：
- **L1**：编译期宽度 vs 运行期长度；char\*、指针均 8（64 位）。
- **L2**：①数组退化：传参即指针，sizeof 变指针宽度——"大小信息在退化那一刻丢掉"；②sizeof(数组)=整个数组宽度含 \0；strlen 数到 \0 不含。
- **L3**：send_all(fd,buf,len) 项目桥——正因退化，长度必须显式传；RTSP interleaved 帧头带 2 字节长度域同理（字节流协议都要自带长度）。
- **L4**：VLA/alignof 一句带过。

**真题问法**："sizeof 数组和 sizeof 指针结果有什么不同"（D-019 小米 B2-14）"sizeof 和 strlen 区别"（Z-065 大疆）。

**坑点措辞险**："sizeof 是函数"——是运算符（可写 sizeof(int) 无括号对象）。


**边界句**（10-19 补）：sizeof 求值时机（编译期常量 vs VLA 运行期）我了解到 C 标准层面，各编译器对柔性数组/位域的特例处理没逐一验证——这部分到边界。
**联动**：#5（定帧=长度信息传递）／#16（数组在栈的布局）。

**状态**：**过**（10-23 17点深化场快验：三问全对含 send_all 双因超规格；「运算符 vs 函数」层学生自报新钉；锚句见 02 册）。

## 卡 9 · #24 strcpy/strncpy 危险与库函数契约（中频·大华手撕直连·场⑧过）

**主轴句**：strcpy 无界拷贝——目标装不下就越界写；安全=知道边界的人负责定长（memcpy+n 或 snprintf）。

**结构图**：
```
strcpy(dst,src): 从 src 拷到 \0 为止 —— dst 容量是隐含假设,没人检查 → 越界写
strncpy(dst,src,n): 拷 n 字节,不够补 0,刚好 n 不补 \0 ← 第二个坑
安全版: memcpy(dst,src,n); dst[n-1]=0;  或 snprintf(dst,n,"%s",src)
```

**维度表**：

| 函数 | 停止条件 | 返回 | 坑 |
|---|---|---|---|
| strcpy | \0 | dst | 无界 |
| strncpy | \0 或 n | dst | 截断不补 \0 |
| memcpy | 拷满 n | dest | 重叠区未定义（该用 memmove） |
| strcmp | 差值≠±1 | 差值 | 返回值不是布尔 |

**机制演示**（攻击直觉）：char pwd[8] 前面是 flag[1]——strcpy 越界可把 flag 覆写成非零"通过"位。栈上越界写破坏返回地址=缓冲区攻击的原理入口（联动 14 号卡）。

**分层答案**：
- **L1**：strcpy 无界可越界写；memcpy 只认 n 不看 \0。
- **L2**：①n 的定义=目标容量上限（不是源长度——场⑧你已产出的判据）；②strncpy 截断时无 \0，读越界在后头等；③重叠区交给 memmove（反向拷贝）。
- **L3**：web.c 解析后拷贝定长字段用 snprintf；手撕安全版四要素=assert(dst&&src)+while((*dst++=*src++)!='\\0'); 存 dest 原值+return 原值（与 T0-2 手撕同网）。
- **L4**：FORTIFY_SOURCE/ASan 检测原理一句。

**真题问法**："strcpy 安全隐患、更安全的替代"（D-033 荣耀 B2-37）"strcpy 和 memcpy 的区别"（Z-015 大华 B2-06）。

**坑点措辞险**："strncpy 比 strcpy 安全"——只是换了坑（截断无 \0）；安全版="知道边界的人定长"。


**边界句**（10-19 补）：strlcpy/strcpy_s 的平台差异与安全 CRT 精确语义我知道结论层，glibc 源码级实现没读过——按『契约+两头坑』层作答。
**联动**：手撕 T0-2（母题）／#23（长度从哪来）／14 号卡（越界破坏帧）。

**状态**：**过**（10-23 17点深化场补句：三条安全路落地+大华对仗句+码流跨点联动；strncpy 方向纠错一次后补收全对；三条路首次学挂冷查；锚句见 02 册）。

## 卡 10 · #25 野指针与悬空指针（中频·场⑧过·防法两句已销账）

**主轴句**：野=从未初始化（指向随机处），悬空=曾经有效但目标已死（free 后/帧回收后）——防法两句：定义即 NULL、free 后置 NULL。

**结构图**：
```
野指针: int *p; ──未初始化──> 指向随机地址 → 解引用=未定义
悬空指针: p=malloc(..) ──free(p)──> 目标已死,p 还留着旧地址 → 解引用=未定义(常能读到旧值!)
治野: int *p=NULL;   治悬空: free(p); p=NULL;
NULL 的意义: 解引用立即段错误 —— 让错误当场暴露,而不是延后腐蚀
```

**维度表**：

| 型 | 成因 | 危险表现 | 防法 |
|---|---|---|---|
| 野 | 未初始化 | 指向任意，读写皆祸 | 定义即 NULL |
| 悬空 | free 后/出作用域 | 常能读到旧值（没人擦）→静默腐蚀 | free 后置 NULL |

**机制演示**（与 #16 悬空铁证联动）：free 后读常得到旧值——因为 free 只改记账不动内容；这让悬空 bug 比野指针更隐蔽（"能跑"直到那块被复用）。精度补丁：glibc 会把 tcache 链指针写进 free 块头部——"读旧值"对块内偏移成立、块头前几字节可能已变，这本身就是"释放后内存处于什么状态没有任何保证"的又一证据。

**分层答案**：
- **L1**：野=没初始化，悬空=目标已死；防法两句。
- **L2**：①NULL 的价值=失败前置（当场崩好过延后腐蚀）；②悬空比野更险：读旧值掩盖问题；③多别名场景（两个指针指同一块）free 一个另一个即悬空——单别名纪律由所有权解决。
- **L3**：frame_grabber_get_jpeg 深拷贝+调用方 free——所有权转移消灭多别名悬空（"多别名→所有权单一"）；抽帧线程借用 packet 不持有——生产者统一释放。
- **L4**：ASan use-after-free 检测（影子内存标记）。

**真题问法**："野指针"（Z-095 经纬 B2-47）"free 之后还能不能访问、会发生什么"（D-009 PICO）。

**坑点措辞险**："free 会把内存清零"——不会（记账而已）；"悬空指针一定崩"——常是不崩的静默错。


**边界句**（10-19 补）：悬空读旧值的具体表现依赖分配器版本（glibc tcache 前后块头行为不同），我按『作废可复写』语义层讲，具体版本差异到边界。
**联动**：#16（悬空铁证）／#18（返回栈地址）／BV-03（所有权）。

**状态**：**过**（10-25 17点深化场快验：成因句终验+所有权落地收口；「循环复用」纠为单槽覆盖；锚句见 02 册）。
