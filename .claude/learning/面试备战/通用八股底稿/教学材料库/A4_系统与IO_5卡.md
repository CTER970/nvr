## 卡 1 · #34 mmap（中频·芯长征原题·P1 未开始）

**主轴句**：mmap=把文件/物理内存"映射"进你的地址空间——访问指针就是访问文件/缓冲，省一次内核-用户拷贝。

**结构图**：
```
普通 read: 磁盘→页缓存(内核) → copy_to_user → 用户缓冲        (两次拷贝: 磁盘→缓存→用户)
mmap:      磁盘→页缓存 ←直接映射进用户地址空间 (访问缺页时按需搬) (一次拷贝, 访问即读缓存)
匿名映射(MAP_ANONYMOUS): 不挂文件,要的就是一块零初始化内存 (malloc 大块即此)
MAP_SHARED vs MAP_PRIVATE: 改动回写文件/共享 ←→ COW 私有副本
```

**维度表**：

| 用法 | 场景 | 项目锚点 |
|---|---|---|
| 文件映射 | 大文件随机访问/加载 ELF | 配置文件读 |
| 设备/物理映射 | 驱动缓冲暴露给用户 | **V4L2 采集缓冲** |
| 匿名映射 | 大块内存 | malloc 大块底层 |
| MAP_SHARED | 两进程共享 | shm 底座 |

**机制演示**（V4L2 闭环——你的最强锚点）：VIDIOC_REQBUFS 让驱动分配 DMA 缓冲→mmap 把每块缓冲映射进用户态→QBUF 交还驱动→DQBUF 取帧——**用户态拿到的指针直接指 DMA 写入的物理页，零拷贝取帧**。这就是"mmap 的通用含义"在采集链路的实然。

**分层答案**：
- **L1**：把文件/内存映射进地址空间，指针访问即读写。
- **L2**：①vs read：少一次内核→用户拷贝（页缓存直接映射）；②缺页按需搬（不是映射时就全拷）；③MAP_SHARED 改动共享、PRIVATE 走 COW。
- **L3**：V4L2 缓冲映射（演示段）；IPC 的 shm 底座（与 #28 联动）；"共享内存分配的空间是否依赖内核"（B2-04 海康二面问法）=建立时靠内核，建立后数据面不过内核。
- **L4**：页缓存回写时机（脏页/writeback）；vm_area_struct 一句。

**真题问法**："mmap 有没有用过"（Z-056 芯长征 B1-16 原题）"共享内存分配的空间/读写速度/是否依赖内核"（Z-002 海康 B2-04）"mmap 的底层"（D-001 字节 B1-01 语境）。

**坑点措辞险**："mmap 一定比 read 快"——随机访问大文件/共享场景赢；顺序读一遍 page cache 一样；"mmap=零拷贝"——省的是用户态那次，磁盘→页缓存仍在。

**边界句**："页缓存回写策略和 vm_area 细节我没读过，用户态视角到'映射+缺页'这层。"

**联动**：#21（缺页机制底座）／#28（shm）／BV-01（V4L2 三模式）。

**状态**：未开始（P1#34）；V4L2 锚点现成，教学时可从采集链路切入。

## 卡 2 · #37 环形缓冲区（中频·华为/宇视原题·场13 预热未登记）

**主轴句**：定长数组+读写索引取模回绕——空间复用免 malloc，判空判满与并发安全是两个真考点。

**结构图**：
```
容量N的数组:  [·][·][·][·][·]
              ↑r(读)     ↑w(写)
写: buf[w]=x; w=(w+1)%N      读: x=buf[r]; r=(r+1)%N
判空: r==w   判满: (w+1)%N==r(留一格) 或 独立计数count(不留格)
单生产单消费: r 只被读者改,w 只被写者改 → 无锁可行(索引原子+内存屏障)
```

**维度表**：

| 设计点 | 选项 | 权衡 |
|---|---|---|
| 判满 | 留一格 vs 计数器 | 少一格空间 vs 多一个共享变量（要原子） |
| 并发 | 锁 vs 无锁单写单读 | 简单 vs 极致性能 |
| 变体 | 双缓冲(乒乓) | 整帧交换，不碎片化 |

**机制演示**（中断写+任务读——华为 B2-30 原题）：中断上下文不能睡眠不能拿互斥锁→单生产单消费无锁环形：写者只动 w、读者只动 r，各自原子更新——中断侧永不阻塞；若多生产者，退回关中断或 per-CPU 缓冲。**这个变式是华为二面真题。**

**分层答案**：
- **L1**：数组+读写索引取模回绕；判空 r==w。
- **L2**：①判满两法（留一格/计数器）；②为什么嵌入式爱用：免 malloc（时间确定）、内存恒定（无碎片）、cache 友好；③单写单读可无锁的原理（各自只写自己的索引）。
- **L3**：**双答案设计题**（宇视原题+影石三连的接法）：要每一帧的（录像/逐帧分析）→环形；只要最新的（预览/识别）→**单槽覆盖**（我们的选法：丢帧隐式免费+省内存，新帧覆盖旧帧）；有界队列丢旧=中间态。frame_grabber 单槽 vs 采集终端有界队列双实然。
- **L4**：无锁内存序（Acquire/Release 配对）；DMA 环形（网卡 rx ring 同构）。

**真题问法**："环形缓冲区由中断写、任务读怎么保证并发安全"（D-022 华为 B2-30 原题）"讲讲线程安全 Ring Buffer"（G-003 TCL）"ringbuffer 的水位调整"（Z-098 商泰 B2-48）"循环队列入队"（06 手撕#6）。

**坑点措辞险**："环形队列满了阻塞生产"——嵌入式常选丢旧保新（阻塞会倒灌采集线程）；"加锁最安全就用锁"——中断上下文禁互斥锁。


**边界句**（10-19 补）：内核 kfifo 的内存序保证（smp 屏障嵌入）我没读过源码，单生产单消费免锁我按『读写各一个索引+索引单向走』讲——多生产多消费必须加锁是边界。
**联动**：手撕#6（同源）／BV-05（帧缓存三策略）／#12（中断禁锁的原因）。

**状态**：未开始正式验收（10-14 场13 读写索引插播直答过未登记）；与手撕#6 联动开卡。

## 卡 3 · #33 HTTP 报文（中低频·P1 未开始·项目直连）

**主轴句**：HTTP=请求行/头/体三段的文本协议——头靠 \r\n\r\n 定界，体靠 Content-Length 或 chunked 定长。

**结构图**：
```
请求:  GET /api/events HTTP/1.1\r\n      ← 请求行: 方法 路径 版本
       Host: x\r\n ... \r\n\r\n          ← 头(每行一个字段, 空行结束)
       [body]                            ← GET 无, POST 有(长度看头)
响应:  HTTP/1.1 206 Partial Content\r\n  ← 状态行: 版本 码 短语
       Content-Range: bytes 0-1023/8192  ← Range 回放的关键头
状态码: 200 OK / 206 部分内容 / 301 重定向 / 404 / 500
```

**维度表**：

| 段 | 定界 | 项目锚点 |
|---|---|---|
| 请求行 | 第一个 \r\n | web.c 解析 method/path |
| 头 | \r\n\r\n（空行） | Content-Type/Length |
| 体 | Content-Length / chunked | POST 配置解析；MJPEG 无边界持续推 |

**机制演示**（web.c 实然三连）：①收请求=头扫到 \r\n\r\n（分隔符定帧）+body 按 Content-Length（长度前缀）——**正好是 #5 定帧法的组合拳**；②MP4 回放 Range：浏览器拖进度条→请求头 `Range: bytes=x-y`→服务端回 206+Content-Range 切片——大文件分段+seek；③MJPEG：Content-Type multipart/x-mixed-replace，一 GET 后持续推边界帧。

**分层答案**：
- **L1**：三段（请求行/头/体）；GET/POST；200/404。
- **L2**：①头空行定界+体两种定长（Content-Length/chunked）；②GET 幂等取数据、POST 提交 body；③无状态协议→Cookie/Session 补状态。
- **L3**：web.c 三实然（演示段）：Range→206 回放、MJPEG 持续推、POST /api/config 热更新；"点开浏览器域名访问的流程"（TPL 成都原题）=DNS→TCP→HTTP 请求→渲染，HTTPS 加 TLS 握手。
- **L4**：chunked 编码格式；HTTP/2 多路复用一句。

**真题问法**："HTTP 协议"（Z-020 宇视 B2-09）"HTTP 和 HTTPS 的区别"（D-007 字节 B1-07）"点开浏览器进行域名访问的流程"（Z-080 TPL 成都 B2-20）。

**坑点措辞险**："HTTP 基于 UDP 的版本"——HTTP/3 之前都基于 TCP（一句防抬杠）。


**边界句**（10-19 补）：HTTP/2 多路复用与 HTTP/3 QUIC 的帧格式我了解概念层，没有一手抓包——HTTP/1.1 报文结构+Range 语义是主线边界。
**联动**：#5（定帧组合拳）／B 层 web.c 全模块。

**状态**：未开始（P1#33）；L3 素材全有，低教学成本高回报。

## 卡 4 · #38 排查工具链（中频·6 家·JD 原文对应·P1 未开始）

**主轴句**：崩溃看 gdb+core、丢数据看 strace、性能看 top、内存看 valgrind——工具是岗位职责 D 块（疑难问题跟进）的敲门砖。

**结构图**：
```
现象 → 分流:
崩溃/段错误  → gdb 跑 core → bt 栈回溯 → addr2line 定位行号
卡死/无响应  → strace 看卡在哪个 syscall / gdb attach 看栈
慢/占CPU     → top -H 找线程 → perf 定位热点
内存异常     → valgrind (泄漏/UAF) / top 看增长
文件/网络    → lsmod/lsof/netstat/ss / tcpdump 抓包
```

**维度表**：

| 工具 | 一句 | 典型命令 |
|---|---|---|
| gdb | 断点/单步/看 core | bt / break / info threads |
| addr2line | 地址→源码行 | addr2line -e app 0x4012ab |
| strace | 追系统调用 | strace -p PID / -f -T |
| top/-H | 进程/线程 CPU | top → H 键切线程视图 |
| valgrind | 内存错误/泄漏 | valgrind --leak-check=full |
| netstat/ss | 连接状态 | ss -antp 看 CLOSE_WAIT |

**机制演示**（段错误定位全链——海康 B2-04 原题）：程序崩→`ulimit -c unlimited` 留 core→`gdb ./app core`→`bt` 出栈→帧里地址 `addr2line -e app 0x...` 得到源文件:行号——**从"崩了"到"哪一行"五步**。web 慢客户端 CLOSE_WAIT 排查=ss -antp 数状态→定位进程→代码找没 close 的路径（与 A3 卡 2 联动）。

**分层答案**：
- **L1**：四件套名+各一句（崩溃 gdb/调用 strace/性能 top/内存 valgrind）。
- **L2**：①段错误定位链（core→bt→addr2line）；②strace 卡 syscall=阻塞点定位；③top -H 线程级看谁吃 CPU。
- **L3**：项目排查故事：NVR 性能=分段计时打点（CLOCK_MONOTONIC 各段 P95）+top 线程视图；web 资源=ss 数 CLOSE_WAIT 定位泄漏；多线程崩溃=core 里 info threads+bt all。
- **L4**：perf 火焰图；ASan/valgrind 原理（影子内存）一句。

**真题问法**："GDB 常用命令、段错误如何定位"（Z-002 海康 B2-04 原题）"gdb 一般操作指令"（Z-025 星宸 B1-11）"linux 查看内存、负载等指令"（D-028 OPPO B2-19）"调试中遇到的难问题"（Z-006 海康 B2-03）。

**坑点措辞险**：只报名不举场景——每个工具带一个"什么现象用它"句；"printf 调试不行吗"——时序敏感 bug printf 会改变行为，strace/gdb attach 不重编译。

**边界句**："perf 火焰图我了解到用途层，板端常用还是打点+top 组合。"

**联动**：#3#4（CLOSE_WAIT 排查闭环）／BV-07（分段计时是项目的一手方法）。

**状态**：未开始（P1#38）；L3 项目故事现成——此卡是"职责对口卡"，建议优先开。

## 卡 5 · #29 信号（中频·大华同名岗原题·红点·场⑥教材已备未教）

**主轴句**：信号=内核代投的异步通知——产生到处理之间有窗口（pending），处理函数只能用异步安全函数。

**结构图**：
```
来源: kill()/内核异常(段错误 SIGSEGV)/终端(Ctrl+C SIGINT)
投递: 内核在返回用户态的路上查 pending → 置起 → 回到用户态前调处理函数
标准信号特性: ①同类不排队(多个合并成一个=可丢) ②处理时机不确定(异步)
实时信号(SIGRTMIN..): 排队不丢
安全: 处理函数中只能调用异步安全函数(write/_exit...) —— printf/malloc 都不行
```

**维度表**：

| 问题 | 答案锚 |
|---|---|
| 如何传递 | 内核置 pending，返回用户态路上递交 |
| 如何避免丢失 | 同类合并不排队→用实时信号/缩短屏蔽窗口 |
| 处理函数限制 | 异步安全函数白名单；只置 volatile 标志最稳 |
| 与 volatile 关系 | g_running 模式：handler 只写标志，主循环查 |

**机制演示**（同类合并直觉）：连发 3 次 SIGUSR1 期间目标在屏蔽该信号/忙着——解屏蔽时只补投 **1 次**（标准信号同种只留一个 pending 位）——这就是"会丢"的机制根源；SIGKILL/SIGSTOP 不可捕获不可忽略（保底控制权）。

**分层答案**：
- **L1**：软件中断异步通知；kill -l 常见 SIGINT/SIGTERM/SIGSEGV；默认动作/捕获/忽略三处置。
- **L2**：①传递机制（内核 pending→返回用户态路上递交）；②避免丢失=同类合并的对策（实时信号排队/缩短 sigprocmask 窗口）；③处理函数只可用异步安全函数（printf/malloc 非安全——可能死锁在被中断的持锁状态里）。
- **L3**：g_running 模式=信号驱动优雅退出的标准姿势：SIGINT/SIGTERM 的 handler 只做 `g_running=0`（volatile sig_atomic_t），main 循环查标志退出——**与 #14 volatile 的项目联动即此**。
- **L4**：sig_atomic_t 为什么存在（读写不可分割）；实时信号队列上限 sigqueue。

**真题问法**："信号是如何传递的、如何避免信号丢失"（Z-014 大华 B2-05 原题）"信号如何传递？如何避免丢失？实时信号 vs 普通信号？"（大华嵌入式 Linux 一面 LX-03——与目标岗同名）"信号、信号量、互斥锁、读写锁区别"（Z-028 星宸 B1-09）。

**变式池**（红点卡必配，10-19 补）：①主循环 `while(g_running){ poll(-1); }`——SIGINT 到来时 poll 会怎样？handler 只写标志够不够？（poll 被 EINTR 打断返回，标志+检查 errno 才能优雅退出——自动重启语义一层）②进程屏蔽了 SIGUSR1 期间连收 3 次，解屏蔽后 handler 执行几次？想一个不丢的方案？（1 次，同类合并；sigqueue 实时信号排队 3 次）③反向题：为什么 handler 里不能 printf？给出一个"handler 里就想留痕"的最小安全做法（write(2) 异步安全，预处理好缓冲区直接 write）。

**坑点措辞险**："信号和信号量是一类"——完全两个机制（异步通知 vs 同步原语），星宸原题就考这个辨析；"handler 里 printf 打日志"——非异步安全。

**边界句**："实时信号编程我没有一手场景，机制到排队不丢这层。"

**联动**：#14（volatile 第一场景，同病根两卡）／#11（信号按进程投递→任意线程处理）。
