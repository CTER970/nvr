## 卡 1 · new 与 malloc 的区别

**主轴句**：new = malloc + 调构造函数 + 类型安全——malloc 只给内存，new 给的是"生出来的对象"。

**结构图**：
```
malloc(40) ──→ 40 字节裸内存(void* 要强转)          对象未出生
new Obj    ──→ 分配内存 → 调用构造函数 → Obj* 带类型   对象出生
delete p   ──→ 调用析构函数 → 释放内存                对象善终
free(p)    ──→ 只释放内存                            不管善终
```

**维度表**：

| 维度 | malloc/free | new/delete |
|---|---|---|
| 返回 | void*（要强转） | 具体类型指针（类型安全） |
| 构造/析构 | 不调用 | new 调构造、delete 调析构 |
| 失败 | 返回 NULL | 抛异常 bad_alloc（默认） |
| 本质 | 库函数 | 关键字（编译器认识，可重载） |
| 数组 | 手算大小 | new[] 与 delete[] 严格配对 |

**关键 why**：C++ 对象 = 内存 + 初始化状态。malloc 给了内存但对象还没"生"（构造函数没跑，成员没初始化，虚表指针没设）——所以对 C++ 对象用 malloc 是"给了躯体没给灵魂"。配对铁律：new/delete、new[]/delete[]、malloc/free 三对严禁混用（混了是未定义行为）。

**真题问法**："new 和 malloc 的区别"（池内多源在案：老池 C++ 向帖+B2 地平线系；出处待复审）。"C 中 malloc 和 C++ 中 new 的区别"（B2-XX SCI 追问链）。

**坑点措辞险**："new 比 malloc 快"——错，底层都走分配器；安全版"new 赢在语义完整不是速度"。"delete 完顺手 free 一下"——双重释放，UB。

**边界句**："operator new 的重载和 placement new 我知道存在，项目里没用过——到'new=分配+构造'这层是我的边界。"

**状态**：未开始（待教，明早第一件）。

## 卡 2 · 指针与引用的区别

**主轴句**：指针是"存地址的变量"（自己占内存、可改指向、可为空）；引用是"对象的别名"（出生即绑定、不能换人、不能为空）。

**结构图**：
```
int a=10, b=20;
int *p = &a;  p=&b;   ✓ 指针可改指向        p 自己占 8 字节
int &r = a;    r=b;   ✗ 这不是重新绑定——是给 a 赋值 20！
```

**维度表**：

| 维度 | 指针 | 引用 |
|---|---|---|
| 可否为空 | 可以（NULL） | 不可以（必须绑定） |
| 可否重绑 | 可以 | 不可以（绑定即终身） |
| sizeof | 8（指针自身） | = 被引用对象的大小 |
| 多级 | 二级指针有 | "引用的引用"没有 |
| 典型用途 | 可能不存在的/要改指向的/指针运算 | 函数改实参、避免拷贝 |

**关键 why**：什么时候用哪个——需要"可为空/改指向/做运算"→指针；函数参数想改实参且认定非空→引用更安全（调用方没法传 NULL 进来，少一类检查）。

**真题问法**："指针和引用区别？何时用哪个？"（池内多源在案：老池海康系+蔚来向；出处待复审）。

**坑点措辞险**："引用不占内存"——语言层是别名没错，但实现层编译器通常用指针实现（层次声明！这正是你 10-18 学的"语言语义 vs 实现"分层的 C++ 版）；面试安全版："语义上是别名，实现上通常是常量指针。"

**边界句**："右值引用/万能引用属于移动语义那套，我没用 C++11 做过项目，问到就说了解概念名。"

**状态**：未开始。

## 卡 3 · extern "C"

**主轴句**：C++ 编译器会把函数名改编成带参数信息的符号（名字改编），C 不改编；extern "C" = 告诉 C++ 编译器"这段按 C 的记法来"——C/C++ 混编的桥。

**结构图**：
```
        C 编译器记:      foo
C++ 编译器记:      _Z3fooi   (foo(int) 带类型信息)
链接器按符号名找人 → 两边记法不同 → undefined reference
extern "C" { void foo(int); }  → C++ 也按 "foo" 记 → 对上了
```

**维度表**（接 #19 static 的链接知识——同属"符号在链接层怎么记"）：

| 关键字 | 对符号做什么 |
|---|---|
| static | 不进全局符号表（本文件私有） |
| extern "C" | 进表，但按 C 记法（不改编名字） |
| 都不写（C++） | 进表，按改编后的名字 |

**关键 why**：链接器找函数靠符号名，名字对不上就是 undefined reference——和你 #19 学过的"链接认的是符号不是代码"同一层的病。头文件惯用法：`#ifdef __cplusplus extern "C" { #endif ... #endif`（让同一份头文件两种编译器都能吃）。

**真题问法**："C++ 调 C 的库符号对不上怎么解决？"（老池在案）。

**坑点措辞险**："extern C 把代码编译成 C"——只影响命名规则，不改变语言语法；安全版"只管名字怎么记，不管代码怎么编"。

**边界句**："name mangling 的具体改编规则（各编译器差异）我没背过，到'按 C 记法不改编'这层是边界。"

**状态**：未开始。

## 卡 4 · 虚函数表与虚析构（本组核心件）

**主轴句**：虚函数表 = 每个类一张"函数地址表"，每个对象里藏一个指针（vptr）指向它——调虚函数时先摸 vptr、查表、再跳，"运行时才决定调谁"就是多态；析构函数声明为虚，是为了让"用基类指针删派生类对象"时能删干净。

**结构图**（对象内存布局）：
```
class Base { virtual void f(); int x; };        class Der : public Base { void f() override; int y; };
Base 对象: [vptr → Base vtable: &Base::f][x]     Der 对象: [vptr → Der vtable: &Der::f][x][y]

Base *p = new Der;  p->f();
   └─ 编译器不知道 p 指向谁 —— 生成: 查 p->vptr 的表 → 取 f 槽位 → 跳过去 → 跑的是 Der::f ✓

Base *p = new Der;  delete p;
   析构是虚  → 同样查表 → 调 ~Der → 先清 y，再自动调 ~Base → 干净 ✓
   析构非虚  → 直接调 ~Base → y 成员没清理 → 资源泄漏 ✗
```

**维度表**：

| 问题 | 答案 | 一句话 why |
|---|---|---|
| 虚函数原理 | vptr + 虚表间接调用 | 多一次寻址换运行时决定权 |
| 何时虚析构 | 基类析构**默认都写虚** | 只要可能拿基类指针删派生对象 |
| 空对象多大 | 1 字节（保唯一地址） | 有虚函数则 8（vptr） |
| 构造函数能虚吗 | 不能 | 对象没建好，vptr 还没就位 |

**关键 why**（虚析构）：你的项目里所有清理代码（free/close/解锁）如果写在派生类析构里，而非虚析构走基类指针删除时这些代码根本不会跑——"类有多态用途，析构就声明虚"是一条可以无脑遵守的纪律。

**真题问法**："虚函数解决什么问题？析构何时声明为虚函数？"（AV-06 大华 2021 春·腾讯云社区源=净源在案）；"虚函数和纯虚函数区别"（宇视 AV-08 净源在案）；"C++ 空对象占几字节"（宇视 C++ 向帖在案）。

**坑点措辞险**："虚函数太慢别用"——代价是一次间接寻址，不是数量级问题；安全版"用一点调用开销换运行时灵活性"。**层次险**：虚表存在哪（只读段/每个类一份 vs 每对象一份 vptr）是实现细节，说"每个类一张表、每个对象一个指针"即可，别把 vptr 说成"每个对象一张表"。

**边界句**："多重继承下的虚表布局、虚继承我没实际用过，到单继承+vptr 这层是边界。"

**状态**：未开始。

## 卡 5 · 智能指针三兄弟

**主轴句**：智能指针 = 把裸指针包进对象，析构函数里自动 delete——"忘了 free"这个 #25 的老问题交给语言机制管（RAII：资源的生死绑定对象的生死）。

**结构图**：
```
裸指针: new → 忘 delete → 泄漏（人管生死）
unique_ptr<int> p = make_unique<int>(10);   独占: 一块内存一个主人（#25 所有权句的语言版!）
shared_ptr<int> a = make_shared<int>(10);   共享: 计数 1 → a,b 持有 = 2 → 都释放 = 0 → 自动 delete（最后一个走的人关灯）
weak_ptr: 不加计数的旁观者 —— 专治循环引用: A 持 B、B 持 A，计数永不归零 → 一方改 weak_ptr → 环断开
```

**维度表**：

| 兄弟 | 语义 | 拷贝 | 一句话 |
|---|---|---|---|
| unique_ptr | 独占所有权 | 禁止（只能 move 转移） | 一块内存一个主人 |
| shared_ptr | 共享所有权 | 允许，计数+1 | 最后一个走的人关灯 |
| weak_ptr | 旁观不拥有 | 允许，不加计数 | 观察用，用时先 lock 提升检查还活着吗 |

**关键 why**（接你已有资产）：#25 你自己产的"所有权随返回值转移、一块内存一个主人"正是 unique_ptr 的语义——frame_grabber_get_jpeg 返回 malloc 拷贝=手工所有权转移，智能指针就是把这套纪律变成语言机制。循环引用 why：计数的规则是"持有就+1"，环里 A、B 互相持有，谁也等不到 0——weak_ptr 的"持有不算数"破环。

**真题问法**："智能指针的优势、为什么可以自动释放"（B2 在案）；"shared_ptr 和 unique_ptr 区别、什么时候用 weak_ptr"（池内多源，出处待复审）。

**坑点措辞险**："shared_ptr 线程安全"——计数是原子的，但指向的对象本身仍要保护；安全版"计数安全≠对象安全"。"循环引用用裸指针破"——裸指针能跑但语义倒退，正解 weak_ptr。

**边界句**："make_shared 与 new 构造 shared_ptr 的差异（一次分配 vs 两次）、控制块结构我知道结论层，没读过实现——到'三兄弟语义+循环引用'是边界。"

**状态**：未开始。

## 卡 6 · mutable

**主轴句**：mutable = 给 const 成员函数留的例外口子——"这个成员即使在 const 函数里也保留修改权"。

**结构图**：
```
class Cache { 
  mutable int hits = 0;        // 命中计数:逻辑上不算对象"状态"
  int query() const {          // const 承诺:不改对象
      hits++;                  // ✓ mutable 成员例外
      ...
  }
};
```

**维度表**（接 #20 const）：

| 关键字 | 管什么 |
|---|---|
| const 成员函数 | 承诺不改对象的任何成员 |
| mutable 成员 | 天生豁免：const 函数里也能改 |
| 典型用途 | 缓存/计数器/懒加载/互斥锁 |

**关键 why**：有些成员"改了也不算改变了对象"（缓存命中数、调试计数、多线程下锁的状态）——逻辑状态 vs 物理位的区分。没有 mutable，要么把整个函数的 const 去掉（承诺失效），要么 const_cast 强改（危险且丑）。

**真题问法**：直问少，多为追问"mutable 了解吗"（你 10-25 自报不会挂账的正是这条）。

**坑点措辞险**：mutable 滥用=const 承诺名存实亡；多线程下 mutable 缓存自身要加锁（mutable 不给线程安全）。"mutable 和 volatile 混"——一个是 const 的例外（C++ 语义层），一个是禁优化（两层东西）。

**边界句**："mutable 在 lambda（C++14 按值捕获修改）里的用法我知道存在，没用过——成员场景是主线。"

**状态**：未开始（你亲口说不会的那条，收官件）。
