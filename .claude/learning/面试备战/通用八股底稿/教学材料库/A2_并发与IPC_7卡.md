## 卡 1 · #11 进程与线程（高频·17 家第一梯队·小米场已过保温）

**主轴句**：进程是资源分配单位，线程是调度单位——内核里都是 task_struct，差别只在 clone 共享多少。

**结构图**：
```
进程=独立的地址空间+fd表+资源    线程=共享进程资源,私有:栈/寄存器/errno
同进程线程间: 共享 全局变量/堆/fd/信号处理 ┃ 私有 栈·PC·寄存器组
内核视角: clone(CLONE_VM|CLONE_FILES..)→线程   clone(不带)→进程(页表 COW)
```

**维度表**：

| 维度 | 进程 | 线程 |
|---|---|---|
| 本质 | 资源容器 | 执行流 |
| 切换成本 | 页表+fd+全上下文 | 换栈+寄存器（同地址空间） |
| 隔离 | 强（一个崩全家活） | 弱（一个段错误全进程死） |
| 通信 | IPC（跨地址空间） | 全局变量+同步（同空间） |

**机制演示**（"线程崩溃为什么带走全进程"）：线程段错误=内核给**进程**发 SIGSEGV（信号按进程投递，页错误按地址空间判定）——所以一个线程踩野指针，整进程退出。这就是"隔离差"的机制根源。

**分层答案**：
- **L1**：资源分配单位 vs 调度单位；调度单位是线程（"进程里的执行流"）。
- **L2**：①共享/私有清单（全局变量/堆/fd 共享；栈/寄存器/errno 私有）；②切换差=页表要不要换；③内核同构 task_struct，clone 标志位决定共享量。
- **L3**：NVR 为什么单进程多线程：frame_grabber 最新帧一份内存多线程直读（省 IPC）、配置热更新即时生效、崩溃域统一由看门狗管理；代价=任何线程崩全挂——监控场景选"简单+共享"而非"隔离"。
- **L4**：task_struct 关键字段一句（mm_struct 指针共享与否）；NPTL 线程=CLONE_VM 实现。

**真题问法**："进程和线程的区别"（Z-015 大华 B2-06、Z-028 星宸 B1-09、D-019 小米 B2-14）"从内存角度/内核角度说明区别"（Z-075 TPL 上海）"同进程的线程之间什么共享什么不共享"（Z-075）。

**坑点措辞险**："线程是轻量级进程所以开销小"——半对，要点是**共享地址空间所以切换不换页表**；"进程间也可以看到彼此全局变量"——错（除非 IPC）。

**边界句**："clone 标志位细节我知道到 CLONE_VM 共享地址空间这层，调度器实体结构没读过。"

**联动**：#27（fork 的 clone 不共享版）／#12（线程同步的必要性来源）／P1#36（RTOS 任务≈线程）。

**状态**：**过**（10-23 17点深化场：共享/私有清单+切换成本机制句+TLB 位置补课收口，锚句见 02 册）。

## 卡 2 · #12 互斥锁与死锁（高频·星宸原题·小米场超规格保温）

**主轴句**：锁保护的是临界区不变量，不是"数据"本身；死锁四条件同成立才成立，破任意一条即解——工程首选锁排序。

**结构图**：
```
死锁四条件(须同时): 互斥 → 持有并等待 → 不可剥夺 → 循环等待
                        ↓ 破哪个?
工程首选: 全局统一锁序(破循环等待)  |  trylock+退避(破持有等待)  |  超时放弃(破不可剥夺)
```

**维度表**：

| 锁 | 适用 | 一句话 |
|---|---|---|
| 互斥锁 | 通用临界区 | 拿不到就睡（上下文切换成本） |
| 自旋锁 | 极短临界区（内核/多核） | 拿不到就转（不吃切换吃 CPU） |
| 读写锁 | 读多写少 | 并发读、独占写 |
| 条件变量 | 等条件 | 配合互斥锁（见卡 3） |

**机制演示**（双锁成环推演）：线程一持 A 等 B、线程二持 B 等 A——两方都睡着，等待图成环，谁也放不了手。**危险的不是有两把锁，是存在"同时持两把锁"的窗口**——所以纪律是"要拿两把就按固定顺序"（web.c 与 rtsp_server 各自的锁排序）。

**分层答案**：
- **L1**：锁保护临界区；死锁四条件=互斥/持有等待/不可剥夺/循环等待。
- **L2**：①"保护的是不变量"——读写都要锁（读不加锁会读到半新半旧的撕裂读）；②四条件缺一不成死锁，破循环等待最工程化=锁排序；③读写都要锁的原因=64 位变量在 32 位机是两条指令。
- **L3**：星宸原题"项目死锁排查"：锁获取顺序审计（列每条路径的加锁序列找环）+超时日志；frame_grabber 锁设计=单写多读一把锁+锁内不做 IO（发送挪到锁外，慢客户端不能持锁阻塞分发）。
- **L4**：futex=无竞争时用户态原子快速路径，竞争才 syscall 入内核；优先级反转与互斥锁绑定（→卡 7）。

**真题问法**："项目中死锁的排查和解决过程"（Z-028 星宸 B1-09 原题）"读写锁/自旋锁/互斥量区别与实现、死锁问题解决"（Z-083 中兴领军）"什么是死锁"（D-026 OPPO B2-16）"设计实时死锁监控机制"（D-002 字节 B1-02）。

**坑点措辞险**："锁保护共享数据"——安全版"锁保护临界区不变量"；"读不用加锁"——撕裂读反例。

**边界句**："死锁检测工具（如 pstack 找等待环）我用过日志审计法，内核 D 锁检测器没碰过。"

**联动**：#13（条件变量配对）／#15（优先级反转=互斥锁的副作用）／B 层行②（转发锁内阻塞实然）。

**状态**：快筛过（10-12 小米场超规格：临界区非数据/读写都要锁/撕裂读）；死锁过程=外部 AI 辅助初学→独立复述过（02 册在案）。

## 卡 3 · #13 条件变量为什么用 while（中频·A4X 手撕原题·小米场双柱过线）

**主轴句**：醒来≠条件成立——虚假唤醒与偷条件两根柱子，都必须醒来重判。

**结构图**：
```
标准姿势: lock → while(!cond) pthread_cond_wait(cv,&mu); /*拿到锁且条件真*/ 消费 → unlock
wait 内部原子两步: 释放锁+入睡  →  被唤醒: 重新抢锁 → 返回(持锁) → while 再判
if 版: 醒来直接消费 → 另一个等待者已把条件消费光 → 操作空条件=错
```

**维度表**：

| 柱 | 机制 | 后果（用 if） |
|---|---|---|
| 虚假唤醒 | 规范允许无信号唤醒 | 无条件也消费 |
| 偷条件 | 唤醒多个，先醒者持锁消费 | 后醒者消费到空 |

**机制演示**（偷条件推演）：缓冲区 1 个任务、两个消费者等待→signal 唤醒两个（pthread 允许惊群语义）→先醒者拿锁取走任务、释放→后醒者拿到锁，if 版直接"消费"→空取。while 版重判 count==0 →继续睡。

**分层答案**：
- **L1**：wait 返回后必须 while 重判条件。
- **L2**：①两根柱子（虚假唤醒+偷条件）；②wait 前**必须**持锁——"检查条件与入睡"要原子（不持锁就睡=条件在检查和睡之间变了却不知）；③醒来时已重新持锁（wait 返回即持锁状态）。
- **L3**：生产者消费者纸面版=06 手撕#10（必带边界句：本项目 frame_grabber 是单槽覆盖，不是队列——新帧覆盖旧帧，消费者只拿最新）；A4X 原题手撕 AB 线程交替打印也是此模型。
- **L4**：futex 等待队列；惊群与 signal vs broadcast 选型（broadcast 唤全部）。

**真题问法**："多线程同步互斥（结合项目）"（Z-078 TPL B2-21 二面）"条件变量"（Z-056 芯长征语境）"多线程访问同一结构体怎么保护"（D-019 小米 B2-14）。

**坑点措辞险**："if 也行大部分时候没事"——偷条件是概率 bug，压测才炸；"wait 不需要锁"——原子性要求。


**边界句**（10-19 补）：pthread_cond_wait 在不同实现下的唤醒顺序与等待队列结构（futex 层）我没读过源码，行为层（虚假唤醒/重判）是我的边界。
**联动**：#12（配对纪律）／手撕#10／BV-05（单槽=条件变量的项目实然）。

**状态**：快筛过（10-12 小米场双柱版复述过）。

## 卡 4 · #14 volatile 不是锁（中频·小米 B2-14 原题·场11 钉死保温）

**主轴句**：volatile 只保证"每次都真读内存+禁止重排此变量"，不保证原子性——i++ 三步照样被穿插。

**结构图**：
```
volatile int flag; while(!flag);   ✓ 单写者标志位: 每次真读,终会看到更新 —— 够用
volatile int counter; counter++;   ✗ 读→改→写 三步,两线程穿插=丢更新 —— 不够!
原子性需求 → 原子变量/CAS/锁
```

**维度表**：

| 需求 | volatile 够吗 | 该用什么 |
|---|---|---|
| 可见性（标志位） | ✓（单写多读+最终一致即可） | volatile |
| 原子性（计数/i++） | ✗ | atomic/CAS/锁 |
| 内存序（多变量联动） | ✗ | 内存屏障/锁 |

**机制演示**（三步穿插丢更新）：counter++ 汇编=load/add/store 三条。线程 A load(5)、线程 B load(5)、A store(6)、B store(6)——两次自增丢一次。**volatile 改变不了"三条指令"这个事实。**

**分层答案**：
- **L1**：volatile=可见性+禁止优化，**不是锁不是原子**。
- **L2**：①三步穿插演示（见上）；②g_running 为什么 volatile 够=单写者+读侧只要"最终看到 1 就退出"，不需要原子复合操作；③正当用途三场景：信号标志/MMIO 寄存器/setjmp 相关。
- **L3**：项目：g_running 是 volatile（信号处理器写/主循环读）；frame_grabber 的 latest_jpeg 不是 volatile 而是"锁+整帧替换"——因为它需要原子性（指针+长度+时间戳一组）。
- **L4**：C11 atomic 与内存序（relaxed/acquire/release）一句；"程序控制流之外被修改"统摄句（你的自创句）。

**真题问法**："volatile 有什么用、哪些场景必须加"（D-019 小米 B2-14 原题）"static volatile inline"（Z-032 富瀚微 B2-44）"原子变量线程安全么"（D-003 字节 B1-03）。

**坑点措辞险**："volatile 让多线程安全"——面试官最爱挖的坑；"volatile 一定慢"——只是禁优化，语义需要时无成本可言。


**边界句**（10-19 补）：编译器屏障与 CPU 屏障（DMB/DSB 指令级）的区分我知道概念层，强弱内存序架构差异没在实战里踩过——按『编译期优化可见性』主线作答。
**联动**：#29（信号=volatile 的第一场景，同病根）／#12（需要原子时的正解）。

**状态**：快筛过（10-12 段1：J14 旧伤钉死+自创统摄句）；探针候选"三场景各自为什么"。

## 卡 5 · #28 IPC 五件套（高频·14 家·场⑨条件过欠复述句）

**主轴句**：进程讲通信（地址空间隔离，必须借内核），线程讲同步（同空间，直接锁）——IPC 选型按数据量与关系。

**结构图**：
```
管道(单向字节流)  消息队列(定长消息+排队)  共享内存(同物理页映射两边,零拷贝)
信号(异步通知)    本地套接字(全双工,可传fd,接口同socket)
选型轴: 数据量大小 × 是否需要双向 × 是否亲缘
```

**维度表**：

| IPC | 一句 | 量级 | 同步 |
|---|---|---|---|
| 无名 pipe | 单向字节流，fork 继承 fd | 小流 | 自带（写满阻塞） |
| 有名 FIFO | 文件系统具名，任意进程 | 小流 | 同上 |
| 消息队列 | 定长消息排队 | 小中 | 自带边界 |
| 共享内存 | 最快，不过内核拷贝 | 大 | **自理**（配信号量） |
| 信号 | 异步事件通知 | 0 | 特殊 |
| 本地套接字 | 全双工跨任意进程，可传 fd | 中 | 自带 |

**机制演示**（共享内存为什么快）：普通 IPC 两次拷贝（A→内核→B）；shm 同一物理页映射进两进程，写完直接可见，**零次内核拷贝**——代价是"谁先谁后"要自己配信号量，一侧崩溃另一侧踩悬空。

**分层答案**：
- **L1**：五件套列举（管道/消息队列/共享内存/信号/本地套接字）。
- **L2**：①为什么进程讲通信线程讲同步（隔离与否）；②共享内存零拷贝+同步自理；③管道单向+亲缘、套接字双向+跨任意；④同步自理=三病（撕裂踩踏/顺序失控/崩溃悬空）——前两病配信号量（初值 1 当闸门、初值 0 当通知，P 原子性是灵魂）；第三病三板斧（心跳字/序号超时/伴生通道收 EOF），shm 天生无死讯（10-21 补教）。
- **L3**：选型（睿联/TPL 三面级）：大数据流=shm+信号量；控制命令=消息队列/套接字；NVR 是单进程所以**没用 IPC**——同空间直接互斥锁+条件变量，这个"为什么不用"本身就是答案。
- **L4**：mmap MAP_SHARED 实现 shm；fd 传递（SCM_RIGHTS）一句；对端持"钥匙"死亡：System V 信号量 SEM_UNDO 内核代还 / pthread robust 锁幸存者得 EOWNERDEAD（10-21 外部范文核验通过入库，概念级）。

**真题问法**："进程间通信方式+为什么用共享内存"（Z-078 TPL 三面）"共享内存如何实现"（Z-031 睿联原题）"IPC 有什么、分别适用哪些场合"（D-004 字节 B1-04）"linux 数据量大推荐哪种传输"（Z-078）。

**坑点措辞险**："共享内存自动同步"——恰恰相反，同步全自理；"管道双向"——单向，双向要两根（FIFO 同罪，双向=两条背靠背，防自读回声）；"V 释放内存/清空数据"——V 只加一+叫人，发许可不碰数据（10-21 学生实错点）。

**边界句**："System V 与 POSIX 两代接口差异我知道存在，具体 API 族没有都写过。"

**联动**：#11（隔离是 IPC 存在的原因）／BV-03（零拷贝谱系）／#12+信号量小场（同步自理=三病与信号量两职，10-21 打通）。

**状态**：**过**（10-21 补句场闭环：管道两句+FIFO 单向纠错+本地套接字四卖点+传 fd 跨点联动 #27「异号同源」均自产；同步自理扩展教学三轮[三病模型/信号量 P·V 原子性/覆盖式数据观]；外部范文三句经核验通过入库；V=清空数据误解当场纠）。

## 卡 6 · #27 fork 与 COW（中频·全志三面/vivo 实考·场⑨条件过）

**主轴句**：fork 拷贝的是地址空间的"壳"（页表），物理页写时才复制（COW）；fd 不拷贝只继承引用。

**结构图**：
```
fork() → 子进程获得页表副本(全部标只读) → 双方任一写 → 缺页 → 内核复制该页各指新份
fd: 父子指向同一"打开文件描述"(引用计数+1) → 共享文件偏移!
```

**维度表**：

| 资源 | fork 后 |
|---|---|
| 地址空间 | 页表复制，物理页共享→COW 分家 |
| fd 表 | 引用共享，偏移共享 |
| 全局变量 | 各写各的副本（COW），互不可见 |
| 线程 | 只保留调用线程（多线程 fork 是坑，冻结层） |

**机制演示**（vivo 原题直觉）：父子打印 &g 值相同（虚拟地址同）但 g=1 父 g=2 子互不影响（物理页 COW 分家）——"地址一样，内存不一样"。

**分层答案**：
- **L1**：fork 创建子进程；返回 0=子、pid=父（一个返回点两个世界）。
- **L2**：①COW 全链（页表副本→标只读→写触发复制）；②fd 共享同一打开文件（偏移连续）；③fork 返回 0 是哪个进程=子进程分支。
- **L3**：NVR 为什么不 fork——单进程多线程模型，无多进程需求；若做看门狗双进程=exec 重启而非共享状态。
- **L4**：vfork（挂起父直到 exec，冻结层）；多线程 fork 只保留调用线程（13 号归档）。

**真题问法**："fork 还是 vfork、返回 0 是哪个进程"（Z-015 大华 B2-06）"fork 地址空间看起来一样又不是"（vivo D-037/D-038）"copy on write 机制"（Z-075 TPL 上海）"fork 和 vfork 区别"（Z-042 全志三面 AV-16）。

**坑点措辞险**："fork 拷贝了整个内存"——只拷页表；"父子变量同步"——COW 互不可见；"fork 后 fd 号变了"——照抄号同（10-21 学生实错点），分开的是"各自新开的 fd 互不可见"。

**边界句**（10-19 补）：COW 缺页处理在内核里的具体路径（do_wp_fault/反写入标志）我没读过源码，到『缺页时复制+页表置可写』这层是边界。
**联动**：#11（clone 家族）／#21（页表与缺页是 COW 的机制底座）。

## 卡 7 · #15 优先级反转（中频·三家实考·场⑧条件过欠修正句）

**主轴句**：高在等锁→低持锁→低被中抢走 CPU→临界区跑不完锁放不掉——最高的高实际效力低于中，这就是"反转"。

**结构图**：
```
高优先级 H ──等锁──> 锁被 L 持有 ──> L 想跑, 却被中优先级 M 抢走 CPU
                     └─ L 跑不完 → 锁放不掉 → H 被 M 间接压制 = 反转
解: 优先级继承(L 临时提到 H 级尽快放锁) / 天花板(拿锁即提到天花板)
```

**维度表**：

| 方案 | 机制 | 代价 |
|---|---|---|
| 优先级继承 | 持锁者临时提到等锁者级 | 链式反转治不了；切换抖动 |
| 优先级天花板 | 拿锁即提到预设天花板 | 预设保守，无关任务也被压 |

**机制演示**（因果链逐步推演）：关键修正句（你的旧伤）——**M 抢的是 CPU 不是锁**：L 并没有失去锁，只是失去执行权；H 等的是锁，锁要 L 跑完临界区才放，L 要 CPU 才能跑，CPU 在 M 手里——环形成。

**分层答案**：
- **L1**：产生链一句+继承/天花板各半句。
- **L2**：①完整因果链（四步，见主轴句）；②继承=临时提升持锁者优先级，放锁即恢复；③继承的代价（大疆追问）：链式反转（L 又等更低者的锁）治不了，且提升/恢复有切换成本——所以有天花板方案。
- **L3**：互斥锁与优先级反转绑定（自旋/信号量无继承）；Linux 用户态调度粒度粗，此题在 RTOS/驱动语境更常见——答完机制补这句场景感。
- **L4**：PI futex（内核维护 PI 链）；RTOS 独享深句（中断里不能阻塞等）在 13 号冻结。

**真题问法**："优先级反转怎么产生？继承的代价？"（Z-062 大疆 EX-07、Z-065 大疆 B2-15）"优先级反转与解决"（Z-053 地平线 B2-01）"freertos 优先级反转是什么、如何避免"（Z-045 全志 B2-29）。

**坑点措辞险**："中优先级抢走了锁"——抢的是 CPU；"继承完全解决"——链式治不了（变式追问标准答案）。
