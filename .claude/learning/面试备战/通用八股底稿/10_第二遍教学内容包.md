## 场① · #3 TIME_WAIT 和 2MSL(零接触)

- **结论**:主动关闭方发出最后一个 ACK 后进入 TIME_WAIT,停留 2 个 MSL 才进 CLOSED(Linux 实现约 60s,面试说「一两分钟量级」)。
- **因果**:①最后的 ACK 可能丢——对方收不到会重发 FIN,我得还活着才能再答一次;②让旧连接的迟到报文在网上自然过期,不被之后复用同四元组的新连接误收。2 倍=一来一回各一个 MSL(我的 ACK 过去+对方重发 FIN 回来)。
- **边界**:出现在**主动**关闭方(说成被动方=概念错);代价=端口被占,客户端大量短连接会耗尽端口;优化一句带过:SO_REUSEADDR/长连接。
- **项目桥**:网关作为 RTSP 客户端反复重启拉流,客户端侧会攒 TIME_WAIT。
- **判卷口径**:①主动方+最后一个 ACK 后 ②丢 ACK 重答+旧报文过期两条因果 ③端口占用代价;变式「ACK 丢了怎么办」接住。

## 场① · #4 CLOSE_WAIT(零接触)

- **结论**:本端收到对方 FIN、回了 ACK,但**本端应用还没调 close()**——本端 FIN 未发,停在 CLOSE_WAIT。
- **因果**:关闭是全双工两个半关;对方 FIN 只关掉对方的发送方向;本端 close 是自己的义务,不调就永远挂在这。
- **边界**:堆积大量 CLOSE_WAIT=**本端代码 bug**(漏 close/泄漏),不是网络问题;对比 TIME_WAIT=CLOSE_WAIT 在被动方且无定时器(不 close 不消失),TIME_WAIT 在主动方且有定时器。
- **项目桥**:web 一连接一线程模型里,客户端断开后若处理线程漏 close 就是它——「netstat 见 CLOSE_WAIT 堆积,先查自己代码」。
- **判卷口径**:①FIN 已收已回 ACK、自己 FIN 未发 ②根因=应用没 close ③堆积=本端 bug;变式「会自己超时消失吗」接住(不会)。

## 场① · #6 队头阻塞(黄,补一句)

- **结论**:同一条 TCP 连接里,中间一个段丢失时,后面**先到达的段也不能交给应用**,只能排在内核里等重传补洞——这就是 TCP 的队头阻塞。
- **因果**:TCP 承诺按字节流有序交付(交给应用的顺序=发送顺序);要守住承诺,后到的段必须缓存到空洞补上才能交付。
- **边界**:UDP 无此问题(数据报独立,丢旧不堵新)——实时视频选 UDP 的核心理由:旧帧迟到已无用。HTTP/2 的应用层队头阻塞是另一层,被问再滑。
- **项目桥**:监控流走 RTSP over TCP 弱网卡住等重传=该机制现实现象。
- **判卷口径**:连出「丢一段→后到的排队→有序交付承诺」+UDP 对照一句。

## 场② · #5 粘包/拆包/定帧(零接触)

- **结论**:TCP 是**字节流,不保留每次 write 的消息边界**——一次 read 可能拿到两次 write 拼一起的数据(粘),也可能只拿到半条(拆);消息边界要应用层自己**定帧**。
- **因果**:TCP 只承诺「字节按序不丢不重」,没有「消息」概念;发送端缓冲合并(含 Nagle)、接收端读取时机都会让边界消失。Nagle 只是成因之一,TCP_NODELAY 解决不了边界。
- **边界**:①拆包≠IP 分片——分片是网络层装不下 MTU 的切法,与消息边界无关;DF=1 不送来边界。②定帧三招=**定长/分隔符/长度前缀**(如 Content-Length)。
- **项目桥**:web.c 收 HTTP 请求=定帧活例:空行切头部+Content-Length 定 body。
- **判卷口径**:①字节流无边界 ②合并/读取时机两成因 ③定帧三招;变式「TCP_NODELAY 能否消除粘包」接住(不能)。

## 场② · #8 确认号 +1 语义(边界答反)

- **结论**:确认号=**期望对方接下来发的第一个字节的编号**=已连续收到的最后一个字节序号 **+1**;序号=本段数据第一个字节的编号;窗口=本端剩余接收能力(流控);SYN/ACK/FIN/RST=标志位。
- **因果**:TCP 用**累计确认**——ack=N 一个数字承认「N 之前全部收到」;「下一个期望」与「已收齐到哪」是同一句话,这就是 +1 的设计。
- **边界**:SYN/FIN 各占一个序号(握手回 ACK=ISN+1 即此语义);窗口≠cwnd(一个=接收方流控通告「别撑爆我」,一个=发送方拥塞控制「别堵网络」)。
- **项目桥**:你已绿的三次握手 ACK=ISN+1 就是同一件事。
- **判卷口径**:确认号=下一个期望字节(非最后已收字节)+累计确认一句;数字变式答对。

## 场③ · #21 虚拟内存与缺页(零接触)

- **结论**:虚拟内存=每个进程有独立的虚拟地址空间,由 MMU 按页(常 4KB)映射到物理内存;页可以暂时不在物理内存。访问合法但不在内存的页→缺页异常→内核装入(文件映射/按需分配/swap)→继续;访问非法地址→缺页失败→段错误。
- **因果**:为什么存在——①隔离:进程写坏不伤别人;②按需分配:malloc 大块不立即占物理内存,首次写才给页;③fork 写时复制成为可能:父子先共享物理页标只读,谁写谁缺页,内核复制那一页。
- **边界**:没配 swap≠没有虚拟内存(嵌入式常无 swap,隔离/按需分配照常,缺页照发,只是不换出到盘,内存不够 OOM);指针值是虚拟地址不是物理地址。
- **项目桥**:你答对的 fork COW 就是它的直接产物;V4L2 mmap 把内核缓冲映进用户空间也是页映射活例。
- **判卷口径**:①独立地址空间+页映射 ②合法装入/非法段错误 ③无 swap 仍有虚拟内存;变式「无 swap 板子还有虚拟内存吗」接住(有)。

## 场③ · #22 大小端(零接触,有战绩桥)

- **结论**:大小端=多字节数据在内存里的字节顺序。小端=低字节放低地址(0x12345678→78 56 34 12);大端=高字节放低地址(→12 34 56 78)。x86/ARM 默认小端;网络字节序=大端。
- **因果**:htons/htonl 存在的原因=协议规定线上大端;本机小端时 16/32 位字段必须逐字节反转,htons=16 位两字节交换。你抓过的 bug:把 32 位地址交给 16 位 htons,高 16 位被截——「序」与「宽度」是两个独立概念。
- **边界**:htons/htonl 只管序不管宽度;判机器端序:`char *p=(char*)&x; p[0]==低字节→小端`(或 union)。
- **项目桥**:htons 截断战绩(缺陷台账在册)。
- **判卷口径**:①低字节低地址+手排 0x12345678 ②网络序大端+htons 换两字节 ③序与宽度分开;变式=手排 16 位小端。

## 场③ · #23 数组退化(C 对 J 没)

- **结论**:数组作函数参数时(写 `char s[]` 或 `char *s` 都一样)退化成指针:函数里 `sizeof(s)`=指针大小(64 位=8),拿不到数组总大小;strlen 照常可用(只要内容带 '\0')。
- **因果**:C 规定传参只传首地址(按值拷贝整个数组太贵);sizeof 是编译期运算,形参类型已是指针。定义处 `char a[]="abc"`:sizeof(a)=4(含 '\0'),strlen(a)=3。
- **边界**:函数里要长度→额外传参(s, len);sizeof 是运算符非函数、编译期定;二维数组传参必须给列宽(推论,一句带过)。
- **项目桥**:项目里所有带 buffer 的函数都带长度参数(get_jpeg 的 out 参数+返回码)=「退化所以传长度」的实战。
- **判卷口径**:①形参退化、sizeof=指针大小 ②sizeof 含 '\0' vs strlen 不含 ③解法=传长度;变式「定义处与形参处 sizeof 各多少」(4/8)。

## 场③ · #17 对齐(蒙对=未学)

- **结论**:编译器在结构体成员间和末尾插填充,使每个成员地址落在自身对齐要求(基本=类型大小)的整数倍上;整个结构体大小补齐到最大成员对齐数的整数倍。
- **因果**:硬件按对齐访问更快(一次总线事务);有的 CPU 未对齐直接故障,允许未对齐的(如 x86)也可能拆成两次访问。末尾填充是为了数组:元素连续排布,不补齐下一个元素的首成员就错位。
- **边界**:空间换速度;`#pragma pack(1)` 压掉填充(网络协议结构体常用,代价=可能慢/不可移植);手算 sizeof 要会。
- **项目桥**:协议帧结构体常用 pack(1) 防 padding。
- **判卷口径**:①成员地址满足自身对齐 ②硬件原因 ③末尾填充为数组;变式=手算 struct{char;int;char}=12。

## 场④ · #9 LT/ET(主体在,缺半层)

- **结论**:水平触发 LT=只要缓冲区里**还有**数据,epoll 每次都通知;边缘触发 ET=只在状态**变化**(无→有)时通知一次;epoll 默认 LT。ET 正确用法=非阻塞 fd+收到通知后**循环读到 EAGAIN**。
- **因果**:ET 只给一次事件——阻塞 read 读完可用数据会挂住线程;没读完就返回,剩余数据不会再触发通知→数据饥饿。
- **边界**:LT 编程简单(没读完还会提醒);ET 减少 epoll_wait 唤醒次数,高并发更省;select/poll 只有 LT 语义。
- **项目桥**:NVR web=一连接一线程+阻塞(当时论证过:客户端十几个,线程模型最简,不是 epoll);EAGAIN 在 rtsp send 侧见过。
- **判卷口径**:①LT 条件成立继续通知/ET 变化通知一次 ②ET 必须非阻塞读到 EAGAIN+为什么 ③默认 LT;变式「ET 读完一半就返回会怎样」(剩余无通知=饥饿)。

## 场④ · #10 非阻塞与 EAGAIN(零接触)

- **结论**:非阻塞 fd 上读写条件暂不满足,read/write 返回 -1 且 errno=EAGAIN——「现在做下去会阻塞,稍后再试」;不是错误、连接未断;Linux 上 EAGAIN=EWOULDBLOCK(同值)。
- **因果**:非阻塞的契约=内核绝不挂起线程;没数据/发送缓冲满只能立即返回,用 EAGAIN 表达「暂时不可用」,常与事件循环配合。
- **边界**:与关闭区分——对端正常关闭 read 返回 **0**(EOF);对端复位=ECONNRESET;EAGAIN 只是「暂时没有」。发送缓冲满+非阻塞 write=EAGAIN,rtsp send 就有这分支。
- **项目桥**:rtsp_server send EAGAIN 分支(在册)。
- **判卷口径**:①暂不可用稍后重试、连接未断 ②非阻塞契约 ③与 EOF/RST 区分;变式「-1+EAGAIN 和返回 0 各表示什么」。

## 场⑤ · #14 volatile 不是锁(边界答反)

- **结论**:volatile 只要求编译器「每次读写真实访问内存,不许优化掉」;**不提供原子性**——volatile int 的 i++ 是读→改→写三步,两线程穿插照样丢更新;也不提供内存序与互斥。
- **因果**:i++ 编译成 load/add/store 三条指令;volatile 禁止合并/缓存到寄存器,但三条指令之间照样可被插入。原子性要么硬件原子指令,要么锁,要么 C11 atomic。
- **边界**:正当用途=信号标志、MMIO 寄存器;g_running 这类停机标志用 volatile 合理;计数/算术共享必须锁。
- **项目桥**:g_running 停机标志;协作式取消卡的护边句。
- **判卷口径**:①不优化掉访问 ②i++ 三步可穿插=不原子 ③正当用途;变式「两线程 volatile++ 会怎样」(丢更新)。

## 场⑤ · #19 static 三用法与内部链接(边界答反)

- **结论**:①函数内局部变量 static:静态存储期+只初始化一次;②文件作用域变量 static:内部链接,别的 .c 看不见;③函数 static:内部链接,**别的 .c 用 extern 声明也链接不到**(J19 那句错在这)。
- **因果**:「链接」=链接器跨翻译单元解析符号;static=符号不进全局符号表(internal linkage),别处的 extern 声明找不到定义→链接错误;这就是模块私有函数的机制。
- **边界**:与非 static 全局(外部链接)对照;static 局部变量多线程共享一份,要锁;两个 .c 各自同名 static 函数互不冲突。
- **项目桥**:你天天写的 static helper——现在知道它对链接器意味着什么。
- **判卷口径**:三用法齐+「extern 链接不到 static 函数」;变式「两个 .c 同名 static 函数冲突吗」(不会)。

## 场⑤ · #29 信号:异步安全(蒙对)

- **结论**:信号处理函数里只能调用**异步信号安全**函数(可重入,如 write);printf/malloc/free/pthread_mutex_lock 都不在列。标准做法=处理函数里只改 `volatile sig_atomic_t` 标志,其余回主流程做。
- **因果**:信号可在任意两条指令之间打断主流程——若主流程正在 printf/malloc 内部(内部锁/结构改到一半),处理函数再调同一个→死锁或踩坏内部结构(不可重入)。
- **边界**:sig_atomic_t=标准保证「读写不可分割」的整型;volatile 管不被优化、sig_atomic_t 管不可分割、锁管互斥——三层各管一件事(#14 同源)。
- **项目桥**:与 #14 合并成一课:volatile/sig_atomic_t/锁 的分工表。
- **判卷口径**:①只能异步信号安全函数 ②任意打断=重入风险 ③标志模式;变式「处理函数里 printf+malloc 出什么问题」(重入死锁/踩堆)。
