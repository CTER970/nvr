## 先数据流(一张白板,5 分钟画完)

```
摄像头 ──MIPI──▶ V821(ISP+VENC) ──RTSP H.264──▶ IMX6ULL 拉流线程
                                              一次 av_read_frame 的 packet 三分发
                         ┌─ A 录像 ─▶ recorder remux ─▶ fMP4 段 ─▶ 磁盘循环回收
                         ├─ B 预览 ─▶ frame_grabber 旁路软解 ─▶ 最新 JPEG 缓存
                         │                ├─▶ web /stream  (MJPEG)
                         │                └─▶ cloud_ai 线程 ─▶ C 云AI
                         │                       HTTPS ─▶ 大模型 JSON
                         │                       ─▶ event_bus(SQLite+快照+订阅)
                         │                            ├─▶ alarm(条件变量+GPIO)
                         │                            └─▶ web /api/events
                         └─ 转发 ─▶ rtsp_server 透传 RTP/FU-A ─▶ 本地客户端

D Web/配置: 浏览器 ─▶ web HTTP ─▶ POST /api/config ─▶ conf_save ─▶ conf_apply_hot
```

面试口述顺序永远是这条图,不是文件夹列表。骨架里把 RTSP 转发标成链路 E,对外仍说「三分发的第三腿」,不要另开一条业务主链。

## 模块怎么连(相互关系,本讲要讲透的)

1. **一个生产者,三个同步消费者。** 拉流线程里一次 `av_read_frame` 之后,同一包按顺序借给 recorder → frame_grabber → rtsp_server,然后 `unref`。没有每消费者一条队列——这是 CPU 与延迟的选型,Phase 1 可深讲。
2. **主路 vs 旁路。** A 和转发待在压缩域(不解码);B/C 才进像素域,而且共享**一份**最新 JPEG,不是两条解码管线。
3. **C 是 B 的下游,失败不回灌 A。** cloud_ai 自己的线程取拷贝、调 HTTPS、publish;挂了只少事件,录像和预览继续。
4. **event_bus 是中枢不是过滤器。** 入库 + 快照 + 广播;`none` 是 cloud_ai 调用点过滤的,不是总线规则。Web 查库、alarm 订阅,两者解耦。
5. **alarm 回调必须快返回。** 真正的 GPIO 延时在报警线程里用条件变量等(C2 已学);回调里睡会拖住 publish 所在的 AI 线程。
6. **D 不碰码流。** Web 读 JPEG 缓存、读 MP4 文件、查 event_bus、改 conf;改 conf 走 `conf_save` + `conf_apply_hot`,不重启整进程。

## 热更新边界(conf,职责层一句)

`conf_apply_hot`(`conf.c:296-303`)实际推了五项:

| 推给谁 | 字段 |
| --- | --- |
| `log_set_level` | `log_level` |
| `alarm_reload` | 报警 GPIO/类型/阈值/时长 |
| `cloud_ai_reload` | AI 开关/fps/prompt/模型/端点(开关翻转会热启停线程) |
| `frame_grabber_set_target_fps` | `web_mjpeg_fps`(作用在生产端节流,不是 Web 发送端) |
| `stream_receiver_set_segment_seconds` | `segment_seconds`(下一段生效) |

**必须重启才生效的**(不要讲成能热更):源 RTSP 地址、Web/RTSP 监听端口、存储目录、token 本身能否从空变非空取决于 `cloud_ai_reload` 实现——速讲层只说「源地址不热更」,细节留给 Phase 3。

## 未学模块的对外话术(到边界就停)

- web:「自研 HTTP,浏览器不播 RTSP 所以转 MJPEG;大 MP4 用 Range 拖动。实现我梳理到职责和数据流,细节在后面的 Phase 3。」
- conf:「能热更的是日志/报警/AI/MJPEG 帧率/分段时长五项,源地址和端口要重启。」
- event_bus 落库:「中枢负责 INSERT、把 JPEG 落成快照、再回调订阅者。落库和持锁细节我正在 2.3A。」
- rtsp_server 实现:「透传、FU-A、SDP 来自 SPS/PPS 这些概念我讲得清;parse_nalus 边界和会话管理还没走到实现层。」
- alarm 动作:「回调只叫醒线程,GPIO 在线程里拉高再睡。具体规则匹配留 2.4。」
