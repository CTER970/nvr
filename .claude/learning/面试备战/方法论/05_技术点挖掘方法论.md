# 项目技术点挖掘方法论(简历·面试向)

> v1.0 · 2026-09-21 · 由 EdgeFusion 简历 v6→v7.14 全流程沉淀(tutor×2 外部前沿模型三方对账+用户逐 Phase 裁决+两轮外部终审实证)。
> 适用:任何项目从零挖出简历技术亮点;骨架=AI 生成→人筛选→表述优化,贯穿四机制。

## 总流程

```
阶段一 候选生成 ──→ 阶段二 人工筛选 ──→ 阶段三 表述优化
(冷眼挖掘,多源独立)   (价值分档+逐条裁决)    (四层规范+分层去向)
        └────────── 贯穿:源码裁决 / 掌握闸门 / 归属红线 / 版本注记 ──────────┘
```

## 阶段一:候选生成(AI 先行,人后改)

**做**:
1. **构造冷眼挖掘提示词**(给 AI 的输入,自包含五件套):
   - 角色:目标岗位的资深面试官兼简历顾问(写清考察权重);
   - 项目事实卡:架构/硬约束/模块清单/关键机制(客观陈述,不预设权重);
   - 挖掘框架:约束驱动(每条硬约束→对应的工程设计)+链路扫描(每条业务链问"最能体现工程判断的决策")+自研内容单独评估+横切面(线程/所有权/停机/热更);
   - 筛选滤网(五问):面试官能追到第三层吗/是主链路核心还是叶子/不写它故事缺不缺一块/岗位权重/稀缺性;
   - 输出格式:候选池 8-12 条→精选 5-6 条(每条=机制/为什么亮/三层追问预演)+自查(维度/技术栈覆盖)。
2. **多模型独立挖掘**:同一提示词丢给 2-3 个不同模型+自己(tutor/导师角色)各挖一份,**互相不看**,防单模型偏见锚定。
3. **AI 先出它选的技术点,人在其上整理修改**——不从零自己写,起点是 AI 的完整提案。

**不做**:不按学习/开发路径组织候选(那会把简历绑架成历史路径,漏掉没学完但高价值的点);不预设"哪些最亮"喂给 AI(否则只是确认偏见)。

## 阶段二:人工筛选(人裁决,AI 提供判定依据)

**做**:
1. **三方对账**:几方输出对比,共识条直接定,分歧条逐条裁决——**以源码为准**,不是以谁更自信为准(本轮实证:外部模型抓出了导师 v5 以来的存量机制错误)。
2. **按 Phase 盘点**(不按 Phase 挑选):每个学习/开发阶段列素材表,每行四栏:素材/价值判定/去向/理由。**盘点按路径、判定按价值**,两者不混。
3. **去向四档**(每个素材必有归宿,内容在层间移动而非蒸发):
   - 精选亮点条(纸面,4-6 条)
   - 支撑句(项目介绍带过)
   - 锚点/弹药库(追问层:选型理由、边界、缺陷与修法)
   - 不上简历
4. **维度配比定稿**:亮点条不选"最强的 N 个并列",按维度铺——架构取舍/核心数据流/自研协议/可靠性/个人战绩至少各占其位;第一条=最能立住项目人设的。
5. **数量纪律**:宁缺毋滥,凑数弱条稀释强条;扫读测试=只看加粗词能否拿到全部关键词。

## 阶段三:表述优化(四层规范+分层去向)

**四层规范**(全部过检才算定稿):
1. **零函数名/零实现参数**(av_read_frame/选项串/位标志/调优数值)——面试官看不到代码;
2. **零评价句**——系统的行为可以写(掉电后已落盘 fragment 仍可播放),对行为的评价不写(CPU 远低于转码/主动取舍),论证归面试口述;
3. **白话机制+否定句式**——「不对码流解码或转码,只做重新封装」「不建队列、不重复拉流」(设计事实可用否定式);
4. **术语锚点必须实然**——模式词上纸前必答「线程在谁身上、有没有队列」,答不出或与源码相反不印(反例:生产者/消费者、发布-订阅、罩错对象的单写者多读者)。

**分层去向**(同一素材三层分工):纸面=what/how;锚点库=why+边界+缺陷修法;口述版=论证叙事(约束→取舍→代价)。

**介绍与亮点分层**:项目介绍=宏观「是什么」(功能清单+约束+技术栈),「怎么做的」归亮点区,两区不重复。

## 贯穿机制

1. **源码裁决**:任何分歧(含 AI 之间的、AI 与用户的)回到源码,给行号;AI 引用的 API/机制要抽查核实——前沿模型也会把机制写满、把术语挂错对象。
2. **外部终审循环**:构造审查包(五条+详细理由+**公开滤网**+**公开落选项邀请挑战**)丢给未参与挖掘的模型;它按你的规范打你的正文,产出修正清单;只改句子不改结构。可多轮直到无新发现。
3. **掌握闸门**:简历每行都是追问邀请函——「项目有+岗位要+能讲三层」才写;「项目有+没学完」→小成本回补后再启用(降级为支撑句先投);「项目没有」永远不写。冷眼模型不知道你掌握什么,防守判断(如"这个细节难防守")不能外包。
4. **归属红线**:AI 辅助落地的不宣称纯手写;原作者/开源仓库的实测数据(置信度等)零引用;参考公开仓库时功能面对齐、措辞不同源。
5. **版本注记**:每轮修订写一行注记(改了什么/为什么/谁的裁决),全程可回溯,回退有据。
