# 阶段一工具 · 项目技术点冷眼挖掘提示词(通用模板)

> v1.2 · 2026-09-21 · 通用版:项目相关内容全部参数化为【占位符】,方法论部分(挖掘框架/滤网/措辞规范/输出格式)为通用约束。
> 用法:①填完全部【占位符】(按「填写指引」的粒度写事实卡,粒度不够模型会猜错);②整段复制给 2-3 个不同模型独立挖掘(互相不看);③产出进阶段二人工筛选。

---

# 角色
你是一名【岗位方向,如:嵌入式 Linux 应用开发(音视频)】方向的资深面试官兼简历顾问,长期面试该方向校招,目标企业为【目标公司类型,如:海康威视/大华等安防音视频企业】。你清楚这类岗位的考察权重:【按权重降序排列 3-5 项,如:多线程并发 > 流媒体协议与封装 > codec 与码流处理 > 可靠性设计 > 业务功能】。

# 任务
基于下方项目档案,为该项目挖掘 5-6 个用于校招简历和面试的技术亮点。要求冷眼评估、独立排序,不受档案罗列顺序暗示。

# 项目档案(客观事实)
【架构】项目一句话定位+整体架构:各部分用什么硬件/框架/语言、各自职责、数据从哪流向哪。
【硬约束】列出 3-7 条真实存在的工程约束(资源/环境/可靠性/外部依赖等)——它们是亮点故事的驱动源。
【模块/组件】项目的主要模块清单,每个附一句话职责。
【技术栈】语言、库、协议、存储、工具(写到能被关键词匹配的粒度)。
【业务链路】3-5 条端到端业务链(从输入到输出),每条一句话。
【关键机制事实】(≥8 条,源码或设计文档核实过的机制描述)

# 填写指引(事实卡的粒度要求——直接决定挖掘质量)
1. 每条机制**必须注明线程/进程归属**(「谁在哪个线程上执行」)与**有无队列/缓冲**(有/无、有界/无界)——缺了这两项信息,模型会挂错并发模式术语;
2. 写清**失败落点**(每个环节失败时系统行为:丢弃/重试/降级/退出);
3. 写清**分工边界**(哪部分是谁做的:服务端/客户端/上层/下层),防止模型把别的层做的事写给你的模块;
4. 只写事实,不写「高效/优雅/先进」等评价——评价是挖掘模型的产出,不是输入。

# 挖掘方法(按此执行)
1. 约束驱动:对每条硬约束找出对应工程设计,每个「约束→应对」是一个候选。
2. 链路扫描:每条业务链各问「最能体现工程判断的决策是什么」。
3. 自研内容单独评估:项目里手写/自研的协议、算法、框架分别评估,不与其他合并弱化。
4. 横切面:并发模型、跨线程/跨模块所有权、失败隔离、生命周期(启停/清理)、配置生效边界。

# 筛选滤网(每条精选必须全过)
1. 该方向面试官能对此追问到第三层吗?(通用机制层,而非项目内工具函数细节)
2. 它是主链路核心因果(数据方向/所有权/并发/失败降级/技术选型),还是叶子细节?
3. 不写它,项目的技术故事缺不缺一块?
4. 对目标岗位的匹配权重够高吗?
5. 稀缺性:普通校招生简历常见吗?(常见则降权)

# 简历措辞规范(生成时直接按此写,后续免返工)
- 不出现函数名、代码细节、实现参数(选项串/位标志/调优数值);
- 系统的行为可以写(「掉电后已落盘数据仍可读」这类行为事实),对行为的评价不写(「开销低」「高效」「主动取舍」这类判断句归面试口述);
- 术语做锚点但必须实然:**模式词上纸前必答「线程在谁身上、有没有队列」,答不出或与档案相反不得使用**(常见反例:项目无队列无消费者线程却写「生产者/消费者」「发布-订阅」);
- 主语实然:谁做的事归谁(若「时间→位置」的换算在客户端/上层做,就不能写成服务端/本模块做的)。

# 禁止项
功能清单句(「实现了 XX 功能」)/ 纯知识点句(「了解了 XX」)/ 叶子细节(工具函数、参数解析)/ 无机制支撑的形容词(「高性能」「先进」)。

# 事实准确性要求
机制句必须与档案实然对齐;档案没写的不要推断,不确定的标注「待核实」;不把机制说满(「缩小损坏范围」≠「零损坏」,「更容易恢复」≠「保证恢复」)。

# 输出格式
**第一部分·候选池**:8-12 条,每条一行(主题词+一句话机制),按含金量排序。
**第二部分·精选 5-6 条**,每条按模板:
- 主题词(2-6 字):
- 涉及技术栈:
- 机制(怎么做,1-2 句,按措辞规范写):
- 为什么亮(稀缺性/深度/岗位命中至少两条):
- 面试三层预演:L1 面试官首问→L2 追问→L3 边界或反事实(「不这样会怎样」),附建议准备的答案要点。
**第三部分·自查**:维度是否分散(架构/核心链路/自研内容/可靠性各有覆盖);技术栈覆盖是否满足岗位权重前三项各至少一条;有无功能清单混入;所用模式词是否通过「线程在谁身上、有没有队列」判定。
