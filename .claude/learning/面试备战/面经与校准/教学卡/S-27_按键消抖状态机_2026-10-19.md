# S-27｜状态机：按键消抖（函数指针表版）

> **卡头**：S-27｜嵌入式原创｜F5 特色族｜P1｜嵌入式进阶｜纯 C（原创轨）
> **实证**：定性：嵌入式身份题（嵌入式岗位高频手撕，考"以事件驱动思维组织裸机代码"）
> **定位**：状态机=中断/RTOS 之外裸机系统最常用的程序骨架——贯穿按键、协议解析、通信帧收发、设备上下电时序等一切"分阶段推进"的场景。

---

## 一、题目解析

- **输入**：周期性采样的按键电平序列（每 5~10ms 读一次 GPIO，无内存对应裸机定时器轮询）。
- **输出**：按下事件（callback）；必须过滤 20ms 内的抖动毛刺与静电干扰脉冲。
- **约束确认**（写码前 30 秒口述）：抖动期多长？→按 5~10ms 机械抖动计，连续 N 次（N=4×5ms=20ms）同电平方确认；长按要不要连发？→本题只报"按下沿"一次；能否阻塞等待？→不能，主循环还要跑别的任务。
- **一句话考什么**：把"时间性"折算成"状态+计数值"——事件驱动状态机是嵌入式代码组织的基本功。

## 二、解题思路

抖动期电平随机翻转（上图），但真实按压的稳定期远长于 20ms（下图）。思路：**不信任任何单次采样**，只在同一电平**连续保持满 N 次**时才迁移状态；任何一次不一致就把计数清零——毛刺永远凑不满 N。

```
        抖动毛刺（<20ms 即被清零，凑不满 N）
电平 ──┐ ┌──┐   ┌──────────────────────────── 稳定按下（≥20ms）
       └─┘  └───┘

状态机：
                    read==LOW（连续 N 次）
   ┌──────┐  按下沿  ┌──────┐
   │ IDLE │ ───────→ │ DOWN │
   └──────┘          └──────┘
     ↑  read==HIGH     │  read==LOW
     │  （连续 N 次）   │  （连续 N 次，无动作）
     │  ┌──────┐       │
     └──│  UP  │ ←─────┘
        └──────┘  read==HIGH（连续 N 次）→ 抬起沿→ 回 IDLE
每拍：同电平 stable_cnt++；异电平 stable_cnt=0、采样新候选
stable_cnt==N 时迁移（进入新状态先把计数清零，重新观察）
```

写码前先画状态转移图——状态×输入的格子填满，代码就是把格子抄成 switch；主循环 while(1) 每 5ms 定时拍调一次扫描函数（裸机轮询骨架）。

## 三、代码（两版）

### 3.1 面试清爽版（enum + while + switch）

```c
typedef enum { ST_IDLE, ST_DOWN, ST_UP } key_state_t;
#define DEBOUNCE_N  4    /* 4 x 5ms = 20ms */
#define KEY_PRESSED 0    /* 低电平=按下（GPIO 常见接法） */

void key_scan(key_state_t *st, int *cnt, int level, void (*on_event)(int))
{
    switch (*st) {
    case ST_IDLE:                    /* 历史电平=松开 */
        if (level == KEY_PRESSED) {
            if (++*cnt >= DEBOUNCE_N) { on_event(KEY_DOWN); *st = ST_DOWN; *cnt = 0; }
        } else { *cnt = 0; }
        break;
    case ST_DOWN:                    /* 历史电平=按下 */
        if (level != KEY_PRESSED) {
            if (++*cnt >= DEBOUNCE_N) { *st = ST_UP; *cnt = 0; }
        } else { *cnt = 0; }
        break;
    case ST_UP:                      /* 等待彻底松开再回 IDLE */
        if (level != KEY_PRESSED) { *st = ST_IDLE; *cnt = 0; }
        else { *cnt = 0; }
        break;
    }
}
```

### 3.2 教学讲解版（升级：函数指针表）

```c
typedef enum { ST_IDLE, ST_DOWN, ST_UP, ST_NUM } key_state_t;

typedef struct {
    key_state_t next[2];   /* [0]=采样到低电平去向，[1]=采样到高电平去向 */
    void (*act)(int edge); /* 进入该状态时报告的事件，可为 NULL */
    int  need_stable;      /* 迁移前需连续同电平次数（0=立即迁移） */
} key_trans_t;

/* 转移表=状态图的直接誊写：加状态只加行，分发逻辑不动 */
static const key_trans_t table[ST_NUM] = {
    [ST_IDLE] = { .next = { ST_DOWN, ST_IDLE }, .act = key_report_down, .need_stable = 4 },
    [ST_DOWN] = { .next = { ST_DOWN, ST_UP   }, .act = NULL,            .need_stable = 4 },
    [ST_UP]   = { .next = { ST_IDLE, ST_UP   }, .act = NULL,            .need_stable = 0 },
};

void key_fsm(int level, int *stable)
{
    key_state_t *pst = &g_state;
    const key_trans_t *t = &table[*pst];

    int lv = (level == KEY_PRESSED) ? 0 : 1;
    if (lv != g_last_lv) { *stable = 0; g_last_lv = lv; }  /* 换候选：计数归零 */

    if (++*stable >= t->need_stable && t->next[lv] != *pst) {
        *pst = t->next[lv];          /* 先迁状态再触发：act 看到的新状态已生效 */
        *stable = 0;                 /* 新状态重新起算稳定期（不变量恢复点） */
        if (t->act) t->act(KEY_DOWN);
    }
}
```

## 四、代码解析

**三块结构**：

1. **状态定义块**：`enum` 显式列出合法状态；状态数 ST_NUM 供数组定长，加状态先加枚举。
2. **分发块**（switch 版）：**每个 case 一个状态**，case 内只做"读电平→计数→迁移"三件事；不写 case default=ST_IDLE（合法输入下走不到；掩盖枚举漏项反而危险）。
3. **迁移纪律**：**先迁状态、再清计数、最后报事件**——顺序不能换：不清计数则新状态"继承"旧稳定期，20ms 判据失效；先报事件再迁移则回调里读到的还是旧状态。

**升级版要点**：函数指针表把"状态×输入→去向/动作"折成查表 `table[st].next[lv]`，switch 整体消失；加状态=加一行表项+一个处理函数，符合开闭原则。不变量：`stable` 恒等于"当前候选电平已连续出现的次数"——电平一换就清零，这是凑不满 N 次的毛刺被过滤的全部机制。

## 五、复杂度

- **时间 O(1)/拍**：每拍只走一个 switch 分支/一次查表；扫描 n 拍总时间 O(n)，与状态数无关（switch 会被编译成跳转表，与 case 数解耦）。
- **空间 O(1)**（口径：辅助空间）
  - **口径说明**：辅助空间=状态变量+计数器+转移表。转移表 `const` 存 Flash（嵌入式只读数据不占 RAM），RAM 仅一个状态字节+一个计数字节，是真正的 O(1)；回调函数指针不计入（代码空间）。
- **口述模板**："单拍 O(1)、定长转移表放 Flash，RAM 开销一个状态加一个计数器；这是它能塞进 5ms 定时拍里和别的任务共存的理由。"
