# S-49｜生产者消费者（环形队列 + mutex + 两条件变量）

> **卡头**：S-49｜嵌入式原创｜F10 并发族｜P0｜嵌入式进阶｜纯 C（原创轨）
> **实证**：网易原题、A4X 手撕原题（并发手撕的 C 版头牌）
> **定位**：生产者消费者=NVR event_bus 的裸线程骨架——多路视频流/事件源往队列塞，消费线程统一分发；这套"一锁两条件变量+环形队列"是所有 RTOS 消息队列的 pthread 教科书实现。

---

## 一、题目解析

- **输入**：N 个生产者线程不断 push 任务；M 个消费者线程不断 pop 任务。
- **输出**：线程安全的定长环形队列；满则生产者阻塞等待，空则消费者阻塞等待，不丢任务、不忙等。
- **约束确认**（写码前 30 秒口述）：判满用 while 还是 if？→**while**（虚假唤醒+被唤醒后条件可能又被同伴抢走）；两把锁还是一把？→一锁两条件变量（两锁易死锁且难讲）；pthread_cond_wait 调用时要不要持锁？→**必须持锁，返回时自动重新持锁**。
- **一句话考什么**：条件变量的三条契约——wait 前持锁、while 重判、两条件变量各管一侧。

## 二、解题思路

环形队列（head 读/tail 写）做容器，重点全在**同步协议**：一个 mutex 保护 head/tail/count，两个条件变量 `not_full`/`not_empty` **各管一个方向的等待**——生产者等 not_full，消费者等 not_empty；放完数据 signal not_empty，取完数据 signal not_full。方向绝不能接反。

```
环形队列（SIZE=8）：
        tail（写指针，生产者推）
         ↓
   ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ T │ T │   │   │   │   │ T │ T │   T=任务
   └───┴───┴───┴───┴───┴───┴───┴───┘
     ↑
   head（读指针，消费者取）        count：满→生产者等 not_full
                                  count：空→消费者等 not_empty

同步关系（谁等谁、谁唤醒谁）：
  生产者                          消费者
    │ lock                            │ lock
    │ while(满) wait(not_full) ◄──┐   │ while(空) wait(not_empty) ◄─┐
    │ 入队 tail                     │   │ 出队 head                   │
    │ signal(not_empty) ──────────┼───┼──────────────────────────┼──┘
    │ unlock                        │ signal(not_full) ──────────┘
    ▼                               ▼ unlock
  "我放了东西，喊空的起来拿"      "我取走东西，喊满的继续放"
```

while 而非 if 的两层理由：①pthread_cond_wait 存在**虚假唤醒**（无人 signal 也返回）；②多消费者时被唤醒到重新拿到锁之间，**队列可能又被同伴取空**——必须回到 while 重判。

## 三、代码（两版）

### 3.1 面试清爽版（现场手写形态）

```c
#include <pthread.h>
#define SIZE 8

typedef struct {
    int buf[SIZE];
    int head, tail, count;
    pthread_mutex_t mtx;
    pthread_cond_t  not_full, not_empty;
} queue_t;

void q_init(queue_t *q)
{
    q->head = q->tail = q->count = 0;
    pthread_mutex_init(&q->mtx, NULL);
    pthread_cond_init(&q->not_full, NULL);
    pthread_cond_init(&q->not_empty, NULL);
}

void q_push(queue_t *q, int v)
{
    pthread_mutex_lock(&q->mtx);
    while (q->count == SIZE)                    /* while：虚假唤醒+重判 */
        pthread_cond_wait(&q->not_full, &q->mtx);
    q->buf[q->tail] = v;
    q->tail = (q->tail + 1) % SIZE;
    q->count++;
    pthread_cond_signal(&q->not_empty);         /* 有数据，喊消费者 */
    pthread_mutex_unlock(&q->mtx);
}

int q_pop(queue_t *q)
{
    pthread_mutex_lock(&q->mtx);
    while (q->count == 0)
        pthread_cond_wait(&q->not_empty, &q->mtx);
    int v = q->buf[q->head];
    q->head = (q->head + 1) % SIZE;
    q->count--;
    pthread_cond_signal(&q->not_full);          /* 腾出位置，喊生产者 */
    pthread_mutex_unlock(&q->mtx);
    return v;
}
```

### 3.2 教学讲解版（关键决策注释）

```c
void q_push(queue_t *q, int v)
{
    pthread_mutex_lock(&q->mtx);
    /* 判满必须在持锁下做：count 是共享变量，无锁读取是数据竞争。
       while 不改成 if 的两层原因：
       ① 条件变量允许虚假唤醒（无人 signal 也可能返回）；
       ② 多生产者场景：A 被唤醒→排队等锁→B 抢先放入任务又把队列填满——
          A 拿到锁时队列可能又是满的。
       if 版此时直接越界写入；while 版回去重判，安全。
       这就是'被唤醒'≠'条件成立'，只代表'可能成立，重新检查' */
    while (q->count == SIZE)
        /* pthread_cond_wait 三位一体（原子地）：解锁+睡眠+被唤醒后重新加锁。
           入参必须持锁：不持锁则"判满"与"入睡"之间队列状态可能变化
           （丢信号的窗口）；wait 返回时代锁已回到手上，
           所以循环体结束直接操作共享变量是安全的，最后统一 unlock */
        pthread_cond_wait(&q->not_full, &q->mtx);

    q->buf[q->tail] = v;
    q->tail = (q->tail + 1) % SIZE;
    q->count++;

    /* 两个条件变量各管一侧：push 完只会让"空"变"非空"，
       因此 signal not_empty；signal 错对象是面试当场抓的硬伤。
       在持锁内 signal：配合 while 重判，signal 丢失也不致死
       （醒来重判失败继续睡，逻辑自洽；锁外 signal 则唤醒的线程
        可能看到的 count 是旧值——虽然 while 兜底仍正确，
        但持锁内 signal 是最不依赖巧合的写法） */
    pthread_cond_signal(&q->not_empty);
    pthread_mutex_unlock(&q->mtx);
}
/* q_pop 完全对称：等 not_empty、取 head、signal not_full，不再展开 */
```

## 四、代码解析

**四块结构**：

1. **初始化块**：head/tail/count 三件套显式清零（static 全局本为 0，写出来是给面试官看的纪律）；mutex+两 cond 各自 init。
2. **push/pop 对称块**：两者互为镜像——push 等 not_full/写 tail/signal not_empty，pop 等 not_empty/读 head/signal not_full。口述"对称"二字，面试官即知你懂全貌。
3. **等待块**：`lock → while(条件不满足) wait → …`——顺序纪律：**判条件必须在锁内**（否则数据竞争+丢信号）；wait 内部"解锁睡、醒来拿锁"，调用者无感。
4. **唤醒块**：signal 在 unlock 之前（讲解版注释了两种写法的权衡）；signal 只"提示"不"保证"，正因如此 while 重判兜底成立。

**不变量视角**：任一线程持锁时看到 `0 ≤ count ≤ SIZE` 且 head/tail 合法——所有修改都在锁内，不变量天然维持；wait 返回点等价于"重新持锁后从头执行临界区检查"，这就是 while 语义正确性的来源。

## 五、复杂度

- **时间 O(1)/次操作**：push/pop 各一次取模、一次 signal；无自旋不忙等（CPU 0% 空转，阻塞在 wait 上由调度器唤醒）。吞吐上限=临界区执行速度，与队列容量 SIZE 无关。
- **空间 O(SIZE)**（口径：辅助空间）
  - **口径说明**：环形缓冲 SIZE 个槽是**必须的工作存储**，计入辅助空间；mutex+2 个 cond 是固定 O(1) 同步原语；无递归栈；无动态分配（队列静态/栈上构造，禁 malloc 场景同样成立）。
- **口述模板**："单次 push/pop 都是 O(1)，阻塞靠条件变量不忙等；空间一个定长环形数组加一锁两条件变量，固定开销没有堆分配；NVR 里 event_bus 就是这个骨架——回调只入队就返回，重活在消费线程做，所以生产端延迟被压到微秒级。"
