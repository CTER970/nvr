# S-07｜237. 删除链表中的节点（O(1) 删除）

> **卡头**：S-07｜LC237｜F1 链表族｜P2 激活池｜Medium（思想型 Easy）｜C++（C 风格）
> **实证**：MTK HS-132
> **定位**：一道"脑筋急转弯"母题——用拷贝值代替改前驱，考的是**对链表结构的换位思考**；追问点"尾节点为何不适用"是完整性试金石。

---

## 一、题目解析

- **输入**：待删节点 `node` 的指针（**注意：不给头指针**）；node 不是尾节点且存在于链中。
- **输出**：无返回值；链表删除该"节点"。
- **约束确认**：函数签名只有 node？→是（这就是全部陷阱所在）；值可重复？→不影响（删的是结构不是值）。
- **一句话考什么**：无前驱时如何删——**把后继拷进来，删掉后继**，让"这个节点"变成"下一个节点"。

## 二、解题思路

常规删除需要"前驱→跳过当前→接后继"，但拿不到前驱（没有头指针）。换位思考：删除的语义是"值 X 不再在链上"——不必删这个物理节点，让它**冒名顶替**后继：把后继的值拷进来，再物理删除后继节点（它的前驱正是我们持有的 node，可直接跳过）。

```
删 node(3)：      4 → 5 → [3] → 9 → 2
第一步 拷值:       4 → 5 → [9] → 9 → 2     （node 变成了"9"）
第二步 删后继:     4 → 5 → [9] → 2         （真正的 9 节点被跳过+free）
```

## 三、代码（两版）

### 3.1 面试清爽版

```cpp
class Solution {
public:
    void deleteNode(ListNode* node) {
        ListNode* nxt = node->next;
        node->val = nxt->val;
        node->next = nxt->next;
        delete nxt;
    }
};
```

### 3.2 教学讲解版

```cpp
class Solution {
public:
    void deleteNode(ListNode* node) {
        // 先握住后继：一旦改了 node->next，后继地址就丢了
        ListNode* nxt = node->next;

        // 冒名顶替：node 逻辑上"变成"了后继。
        // 题目保证 node 非尾 → node->next 必非空，此处解引用安全
        node->val = nxt->val;

        // 跨过后继完成"删除"的观感；物理上被释放的是后继节点
        node->next = nxt->next;
        delete nxt;   // C 风格场景对应 free(nxt)
    }
};
```

## 四、代码解析

**三拍结构**：存后继 → 拷值 → 跨接+释放。顺序纪律：先存 `nxt` 再改 `node->next`（改完就找不到后继了）。

**为什么尾节点不适用（必被追问）**：尾删需要把**前驱**的 next 置空，而我们恰恰没有前驱——拷值法依赖"后继存在"，尾节点没有后继，此路不通。完整的表述："这题能 O(1) 是因为题目排除了尾节点；通用删除仍需头指针遍历找前驱，O(n)。"

**延伸（口述级）**：`node->next = nxt->next` 若在 `delete nxt` 之后做就成悬空读取——释放前必须完成所有对 nxt 的使用。

**不变量视角**：整个生命周期中 node 的地址从未失效——我们删除的从来不是"node 这个盒子"，而是让它逐步"变成后继、再释放后继的盒子"；外界所有指向 node 的指针始终有效。

## 五、复杂度

- **时间 O(1)**：三次赋值+一次释放，与链长无关。
- **空间 O(1)**
  - **口径说明**：辅助空间=一个指针；释放一个节点（负增量）；不申请新内存。
- **口述模板**："O(1) 时间空间：拷后继的值进来、跳过并释放后继——本质是删了后继、让 node 顶替它；局限是尾节点不适用，因为拿不到前驱。"
