# S-24｜结构体 sizeof 手算（对齐三规则 + #pragma pack）

> **卡头**：S-24｜嵌入式原创｜C2 位运算/C 基本功/嵌入式特色族｜P1 第三批｜基础+｜纯 C
> **实证**：大疆 HS-005/053
> **定位**：对齐三规则秒算任意结构体——协议解析、DMA 布局、寄存器映射的每日常识。

---

## 一、题目解析

- **输入**：结构体定义（成员类型序列）；变体：含 `#pragma pack(n)` 或嵌套结构体。
- **输出**：`sizeof` 数值手算，逐成员偏移可报。
- **约束确认**（写码前 30 秒口述）：对齐数取谁？→成员自身对齐数与 pack 上限取小；总大小补齐到谁？→最大对齐数（与 pack 取小后）的整数倍；空结构体？→C 中是 UB/0，GCC 给 0，C++ 给 1。
- **一句话考什么**：成员偏移是"自身对齐数整数倍"、总大小是"最大对齐数整数倍"、pack 取小——三条规则一路填表。

## 二、解题思路

**规则一**：每个成员的偏移必须是**该成员对齐数**（默认=其 sizeof，double 在 32 位 Linux 例外为 4）的整数倍，不足在前面补空。**规则二**：结构体总大小必须是**最大成员对齐数**的整数倍，不足在尾部补空（保证数组里每个元素同样对齐）。**规则三**：`#pragma pack(n)` 给每个成员的对齐数设上限——实际对齐数 = min(自身对齐数, n)；嵌套结构体作为一个成员，其对齐数=其内部最大对齐数。

```
struct S1 { char c; int i; short s; };        （默认 4 字节对齐平台）
  c : 偏移 0（对齐 1）        [c][pad×3]
  i : 对齐 4，0 后最近 4 的倍数 = 4，补 1~3   [0..3: c+pad][4..7: i]
  s : 对齐 2，8 已是 2 倍                     [8..9: s]
  总 : 最大对齐 4，当前 10 → 补到 12          sizeof = 12 ✔

struct S2 { char c; double d; char c2; };     （64 位，对齐 8）
  c@0，pad 1~7；d@8..15；c2@16；总 17→补到 24（最大对齐 8）  sizeof = 24

pack 压缩对比（#pragma pack(1) 下 S1）：
  c@0, i@1, s@5 → 总 7，无任何填充——协议帧常这么干，代价是非对齐访问
```

手算纪律：从上到下给每个成员"找最近倍数偏移→落下→记录 pad"；收尾抬到最大对齐倍数。嵌套 struct 先算内层、把它当一个"对齐数=内层最大对齐、大小=内层 sizeof"的成员代入。

## 三、代码（两版）

### 3.1 面试清爽版（现场手写形态）

```c
#include <stdio.h>
#include <stddef.h>

struct S1 { char c; int i; short s; };

#pragma pack(push, 1)            /* 保存当前 pack，设为 1 */
struct Frame {                   /* 协议帧：零填充紧凑布局 */
    unsigned char  head;
    unsigned int   len;
    unsigned short crc;
};
#pragma pack(pop)                /* 恢复，缩影响范围 */

int main(void) {
    printf("S1=%zu c=%zu i=%zu s=%zu\n",
           sizeof(struct S1),
           offsetof(struct S1, c), offsetof(struct S1, i),
           offsetof(struct S1, s));          /* 12, 0, 4, 8 */
    printf("Frame=%zu\n", sizeof(struct Frame));   /* 7 */
    return 0;
}
```

### 3.2 教学讲解版（关键决策注释）

```c
/* 规则演绎（默认平台：char=1/short=2/int=4/指针8@64bit/double=8）：
   R1 成员偏移是其对齐数整数倍 → i 的 1~3 补空是"给 int 让出 4 倍地址"
   R2 总大小是最大对齐数整数倍 → 10 补到 12，保证 struct S1 arr[2] 中
      arr[1].i 仍落在 4 倍地址上——规则二存在的原因就是数组 */
struct S1 { char c; int i; short s; };       /* 1 + pad3 + 4 + 2 + pad2 = 12 */

#pragma pack(push, 1)
/* pack(1)：每成员实际对齐 = min(自身,1) = 1 → 全部紧贴零填充；
   为什么必须 push/pop 成对：pack 是"编译器状态"，漏 pop 会
   污染其后所有结构体——隐藏布局漂移是实网事故常客 */
struct Frame {
    unsigned char  head;      /* @0 */
    unsigned int   len;       /* @1 —— 非对齐访问，x86 能跑，某些 ARM 硬件异常 */
    unsigned short crc;       /* @5，总 7 */
};
#pragma pack(pop)
/* 语义验证三板斧（现场可写可背）：
   offsetof(struct S1, i) == 4        偏移规则
   sizeof(struct S1)     == 12        总补齐规则
   sizeof(struct Frame)  == 7         pack 规则            */
```

## 四、代码解析

**三块结构**：

1. **S1 默认对齐**：填表法逐成员落位——i 在 4 处（前置 3 字节 pad），s 在 8 处，总 10 抬到 12。尾部 pad 的存在理由必须会说：数组元素循环出现时，下一元素的 i 也必须对齐——规则二服务于数组。
2. **Frame pack(1)**：紧凑布局=零填充=7 字节，协议帧/DMA 缓冲的标配；代价是非对齐访问（x86 静默容忍，部分 ARM/总线直接 fault），跨平台代码需 `__attribute__((aligned))` 或手动 memcpy 兜底。
3. **验证宏块**：`offsetof`（S-23）把"手算"变成"可执行断言"——面试手算后补一句"可用 offsetof 逐项验证"，工程素养直接拉满。push/pop 成对是纪律：pack 是全局状态，泄漏波及整个编译单元。

**不变量视角**：任意成员地址 ≡ 其偏移（mod 对齐数）恒成立；数组 `a[i]` 的每个成员地址都落在与 `a[0]` 相同的对齐网格上——两条规则合起来保证"任何数组的任何成员都天然对齐"，这就是 sizeof 必须尾部补齐的全部原因。

## 五、复杂度

- **时间 O(1)**：sizeof/offsetof 均为编译期常量，运行期零开销；手算成本 O(成员数)。
- **空间 O(1)**
  - **口径说明**：指**辅助空间**——本卡考察的正是"数据自身空间"口径：sizeof 含**填充字节**（S1 的 12 里 5 字节是 pad）；pack(1) 用对齐换紧凑，是空间与访存安全的显式交易。
- **口述模板**："三规则：成员偏移是自身对齐数倍数、总大小是最大对齐数倍数、pack 取小；S1 手算 1+3+4+2 补到 12；pack(1) 后 7 字节零填充但 len 非对齐——sizeof 是编译期常量，空间口径含填充。"
