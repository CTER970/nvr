# S-16｜大小端判断（union 法+指针法）+ 手写 htonl（Byte Order）

> **卡头**：S-16｜嵌入式原创｜C2 位运算/C 基本功/嵌入式特色族｜P0 第三批｜基础｜纯 C
> **实证**：大疆 HS-005、地平线 HS-015、小米 B2-11（八股双形态：口述原理+现场手写判断函数）
> **定位**：union 共用体起始地址相同、指针别名看首字节——嵌入式所有"多字节数据落内存"题的地基。

---

## 一、题目解析

- **输入**：无（判定当前运行平台的字节序）；变体输入 `uint32_t`（字节序转换 htonl）。
- **输出**：小端返回 1、大端返回 0；变体输出转换后的 `uint32_t`。
- **约束确认**（写码前 30 秒口述）：字节序定义在哪种宽度上？→多字节标量（uint32_t）在内存的字节排放；char 需要判断吗？→单字节无字节序；返回值语义？→和 htonl 一样按值返回，不能用返回值携带错误。
- **一句话考什么**：同一块内存用不同类型别名去读——union 成员共享起始地址与指针强转，本质是同一件事。

## 二、解题思路

小端（x86/ARM 默认）：**低有效字节存低地址**；大端（网络序、多数 PowerPC）：高有效字节存低地址。判定思路：给 `uint32_t` 赋 0x01，看**最低地址上那一个字节**是 0x01（小端）还是 0x00（大端）。读这一字节的两条路：①union 让 `uint8_t b[4]` 与 `i` **共享同一块内存**，`b[0]` 恰好落在最低地址；②指针强转 `*(uint8_t*)&i` 直接按字节地址取。

```
uint32_t i = 0x12345678 落内存：

       地址(升序→)  +0    +1    +2    +3
小端:              0x78  0x56  0x34  0x12   （低位在低地址）
大端:              0x12  0x34  0x56  0x78   （高位在低地址）
                   ↑
                   b[0] / *(uint8_t*)&i 读这里
手写 htonl（小端机上 0x12345678 → 0x78563412）：
拼字节=高位字节落到低地址： (v>>24) | (v<<24) | ((v&0xFF00)<<8) | ((v>>8)&0xFF00)
```

 htonl 转换即"字节 0 与字节 3 互换、字节 1 与字节 2 互换"——纯移位+掩码+或，与平台字节序判断解耦（大小端机跑同一份移位代码结果一致，这是按值语义而非按内存）。

## 三、代码（两版）

### 3.1 面试清爽版（现场手写形态）

```c
#include <stdint.h>

/* 返回 1=小端, 0=大端 —— union 法 */
int is_little_endian_union(void) {
    union { uint32_t i; uint8_t b[4]; } u;
    u.i = 0x01;
    return u.b[0];          /* 最低地址字节是 0x01 → 小端 */
}

/* 返回 1=小端, 0=大端 —— 指针法 */
int is_little_endian_ptr(void) {
    uint32_t i = 0x01;
    return *(uint8_t *)&i;  /* 按字节指针取最低地址 */
}

/* 手写 htonl：字节 0<->3、1<->2 对调 */
uint32_t my_htonl(uint32_t v) {
    return ((v & 0x000000FFu) << 24) |
           ((v & 0x0000FF00u) <<  8) |
           ((v & 0x00FF0000u) >>  8) |
           ((v & 0xFF000000u) >> 24);
}
```

### 3.2 教学讲解版（关键决策注释）

```c
#include <stdint.h>

int is_little_endian_union(void) {
    /* union 全部成员从同一地址起始——b[] 不是拷贝，是 i 的字节级视图 */
    union { uint32_t i; uint8_t b[4]; } u;
    u.i = 0x01;                 /* 最低有效字节=0x01，其余为 0，是天然探针 */
    return u.b[0];              /* 只看最低地址：0x01=低字节在低处=小端 */
}

int is_little_endian_ptr(void) {
    uint32_t i = 0x01;
    /* &i 是 uint32_t*，强转 uint8_t* 解引用只读 1 字节——指针别名 */
    return *(uint8_t *)&i;
}

uint32_t my_htonl(uint32_t v) {
    /* 先 & 掩码取字节再移位，顺序不能反：先移后会把相邻字节拖进来；
       四路结果互不重叠（分落不同字节槽），可用 | 合并 */
    return ((v & 0x000000FFu) << 24) |   /* 字节0 → 字节3 槽（低→高地址）*/
           ((v & 0x0000FF00u) <<  8) |   /* 字节1 → 字节2 槽 */
           ((v & 0x00FF0000u) >>  8) |   /* 字节2 → 字节1 槽 */
           ((v & 0xFF000000u) >> 24);    /* 字节3 → 字节0 槽（高→低地址）*/
}
```

## 四、代码解析

**三块结构**：

1. **union 法**：标准保证 union 成员共享存储且起始地址相同，写 `i` 读 `b[0]` 读到的就是最低地址字节——不依赖任何未定义行为，是面试首答。探测值选 0x01 而非 0x12345678：一个非零探针字节+三个零，结论一眼可读。
2. **指针法**：`*(uint8_t*)&i` 是 union 法的指针化表达；强转发生在**指针上**而非值上。字节序属实现细节，C 标准不规定，只能运行期探测。
3. **手写 htonl**：四路"掩码取字节→移位入槽"按值重排。要点：`&` 在移位之前；移位量 ≥ 宽度是 UB（uint32_t 移 24 安全）；常量掩码带 `u` 后缀防符号扩展。

**不变量视角**：无论大端小端机，`my_htonl(my_htonl(v)) == v` 恒成立（对合变换）；union/指针两法在同一平台返回值恒一致——两法互为验证。

## 五、复杂度

- **时间 O(1)**：赋值+一次单字节读；htonl 四路移位掩码合并，固定常数操作，与数据取值无关。
- **空间 O(1)**
  - **口径说明**：指**辅助空间**——union 变量或栈上 `uint32_t` 均为固定 4 字节；无输出空间（按值返回）；无递归。
- **口述模板**："两个判断都是 O(1)——union 让字节数组和 uint32_t 共享内存，看最低地址字节是不是 0x01；手写 htonl 就是四个字节槽移位重排，先掩码后移位，常数时间常数空间。"
