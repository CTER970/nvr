# S-15｜字符串分割 split / strtok 思路

> **卡头**：S-15｜嵌入式原创（无 LC 对应）｜F2 库函数手写族｜P1｜嵌入式基础｜纯 C（原创轨）
> **实证**：CVTE HS-014（现场）
> **定位**：解析类代码的日常件——协议拆包/命令行分词都用它；strtok 的两个坑（static 内部指针 + 破坏原串）是嵌入式编码面试的高频冷知识。

---

## 一、题目解析

- **输入**：待分割串 `s`、分隔符集合 `delim`（如 " ," 表示空格或逗号）。
- **输出**：逐次返回下一个 token 指针；无更多 token 返回 NULL。
- **契约三问**：连续分隔符怎么算？→collapsed（多个当一个）；token 为空？→跳过不返回空 token（strtok 语义）；原串保留？→**不保留，被就地写入 '\0'**。
- **一句话考什么**：**游标推进 + 就地终止**的解析手法 + 对 strtok 副作用的清醒认知。

## 二、解题思路

核心动作两步循环：①跳过分隔符（游标推进到非分隔符或串尾）；②从当前点向后扫到下一个分隔符，**把它改成 '\0'**，返回段头，游标停在改写点+1 处下次继续。

```
s = "ip:192.168.1.5", delim = ":."
第1次: 跳过无 → 扫到 ':' → 改 '\0' → 返回 "ip"
       "ip\0192.168.1.5"   游标停在 192 处
第2次: (NULL 调用) 从游标扫到 '.' → "192"
第3/4次: "168" / "1"
第5次: 游标到尾 → NULL

strtok 的隐身状态: 上图游标就是它的 static 内部指针——
这解释了两个坑：非重入 + 原串被破坏
```

## 三、代码（两版）

### 3.1 面试清爽版

```c
#include <assert.h>

char *my_strtok(char *s, const char *delim)
{
    static char *save = NULL;
    if (s) save = s;
    if (!save) return NULL;

    char *p = save;
    while (*p && strchr(delim, *p)) p++;
    if (!*p) { save = NULL; return NULL; }

    char *tok = p;
    while (*p && !strchr(delim, *p)) p++;
    if (*p) { *p = '\0'; save = p + 1; }
    else save = NULL;
    return tok;
}
```

### 3.2 教学讲解版

```c
char *my_strtok(char *s, const char *delim)
{
    // 坑一现场：static 保存跨调用游标——
    // 代价①非重入（信号处理函数里调用 = 灾难）
    // 代价②同一时刻只能解析一条串（第二条开始游标被覆盖）
    static char *save = NULL;

    if (s) save = s;           // 首调用显式传串；后续传 NULL = "接着上次"
    if (!save) return NULL;    // 无状态可续（首次就传 NULL）

    // 阶段一：跳过前导分隔符（连续分隔符 collapsed 的实现处）
    char *p = save;
    while (*p && strchr(delim, *p)) p++;
    if (!*p) { save = NULL; return NULL; }   // 全是分隔符/已到尾

    // 阶段二：token 体扫描——p 走到分隔符或串尾为止
    char *tok = p;
    while (*p && !strchr(delim, *p)) p++;

    // 坑二现场：就地写 '\0' 截断——原串从此不完整。
    // 若原串是字符串字面量/共享缓冲区，这里就是未定义行为的现场
    if (*p) { *p = '\0'; save = p + 1; }     // 还有余料：游标指向下一段
    else save = NULL;                         // 到尾：下次直接返回 NULL

    return tok;
}
```

## 四、代码解析

**四拍结构**：建/续游标 → 跳分隔符 → 扫 token → 截断+续游标。

两条纪律：①`static save` 的赋值只在 `s` 非空时——这是"新串/续取"的分岔点，条件写反则每次调用都从头开始；②改写 `'\0'` 前必须已确认 `*p` 非零（串尾本来就有 `'\0'`，无需也不能再写）。

**安全替代**（口述必给）：`strtok_r(s, delim, &saveptr)` 把游标交给调用者保管——**可重入、可多串并行**；工程代码（尤其多线程/信号环境）一律用它。自实现 split 返回数组的版本则用"出参 char** argv + 计数返回"，避免 static。

**高频追问**（对话层）：为什么 strtok 不复制 token？→零分配设计（嵌入式无 malloc 场景），代价转嫁给原串可变性——权衡意识的教科书案例。

**不变量视角**：每轮返回时 `save` 恒指向"下一个未消费字符"或 NULL——token 之间不留缝隙、不重不漏，游标推进与消费严格同步。

## 五、复杂度

- **时间 O(n)**：整串每个字符至多被碰两次（一次分类、一次扫描），分摊每 token 线性；`strchr(delim, c)` 是 O(|delim|) 小常数。
- **空间 O(1)**
  - **口径说明**：辅助空间=游标指针（static 或调用者的 saveptr）；**零分配**——不复制 token、不建数组（这是它的设计卖点）；返回的 token 借住在原串内存上。
- **口述模板**："单遍 O(n) 游标推进，跳分隔符、扫到就地把分隔符改 '\0'；空间 O(1) 零分配——代价是 static 非重入+破坏原串，工程用 strtok_r 把游标交还调用者。"
