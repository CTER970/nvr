# S-40｜IP 地址与整数互转

> **卡头**：S-40｜嵌入式原创（LC 与牛客笔试常见）｜F7 字符串·算法族｜P1｜Medium｜C++（C 风格）
> **实证**：定性（网络岗身份题；htons/字节序一手场景挂接）
> **定位**：嵌入式网络编程的身份题——**点分十进制 ↔ 32 位整数**的互转就是 `inet_aton/inet_ntoa` 的手写版，与 S-16 字节序一脉相承。

---

## 一、题目解析

- **输入 A→I**：点分十进制串 "192.168.1.5"；**输出**：uint32_t（如 0xC0A80105）。
- **输入 I→A**：uint32_t；**输出**：点分串。
- **约束确认**：每段 0~255？→**必须校验**；前导零？→严格版拒绝（"01" 非法）；段数必须 4？→是；空段（"1..2"）？→非法。
- **一句话考什么**：解析（切段+数值化+校验）与拼装（移位+格式化）的双向能力——笔试最爱出成"找非法 IP"变体。

## 二、解题思路

**A→I**：逐字符状态解析（S-13 atoi 骨架 ×4 段）：当前段值 val 累积，遇 '.' 结算一段（校验 ≤255 且非空），第四段在串尾结算。全程用"段计数"驱动——**不足 4 段或超 4 段即非法**。

**I→A**：32 位按字节取出（`>>24 & 0xFF` 逐个），点号拼接。

```
"192.168.1.5"
段1: 192 → (192)<<24 = 0xC0000000
段2: 168 → |(168)<<16 = 0xC0A80000
段3:   1 → |(1)<<8   = 0xC0A80100
段4:   5 → | 5        = 0xC0A80105

大端序视角: 高字节段=网络序首字节——这就是 inet_aton 的本质
```

## 三、代码（两版）

### 3.1 面试清爽版

```cpp
#include <cstdint>
#include <cstdio>

bool ip2int(const char *s, uint32_t *out)
{
    uint32_t val = 0;
    int seg = 0, segval = 0, seglen = 0;

    for (; ; s++) {
        char c = *s;
        if (c >= '0' && c <= '9') {
            segval = segval * 10 + (c - '0');
            if (++seglen > 3) return false;
        } else if (c == '.' || c == '\0') {
            if (seglen == 0 || segval > 255) return false;
            val = (val << 8) | (uint32_t)segval;
            seg++; segval = 0; seglen = 0;
            if (c == '\0') break;
        } else {
            return false;
        }
    }
    if (seg != 4) return false;
    *out = val;
    return true;
}

void int2ip(uint32_t ip, char *buf)
{
    sprintf(buf, "%u.%u.%u.%u",
            ip >> 24, (ip >> 16) & 0xFF, (ip >> 8) & 0xFF, ip & 0xFF);
}
```

### 3.2 教学讲解版

```cpp
bool ip2int(const char *s, uint32_t *out)
{
    uint32_t val = 0;        // 累积结果：每段左移 8 位腾出低字节
    int seg = 0, segval = 0, seglen = 0;
    // seg=已完成段数, segval=当前段值, seglen=当前段位数（管前导零/长度）

    for (; ; s++) {
        char c = *s;
        if (c >= '0' && c <= '9') {
            segval = segval * 10 + (c - '0');   // S-13 的累积式复用
            if (++seglen > 3) return false;     // "1234" 超 3 位必 >255，早退
        } else if (c == '.' || c == '\0') {
            // 段结算点：两个合法终结符共享一套结算逻辑（'\0' 是末段哨兵）
            if (seglen == 0) return false;      // 空段："1..2" / "1." / ".1"
            if (segval > 255) return false;
            val = (val << 8) | (uint32_t)segval;  // 高位段先进 → 网络字节序
            seg++; segval = 0; seglen = 0;
            if (c == '\0') break;
        } else {
            return false;                       // 任何杂字符直接判负
        }
    }
    if (seg != 4) return false;                 // "1.2.3" / "1.2.3.4.5"
    *out = val;
    return true;
}
```

## 四、代码解析

**单循环状态解析结构**：字符只有三类归宿（数字/终结符/非法），段的生命周期由 seglen/segval 三变量完整描述。

三条纪律：①`seglen == 0` 检查必须在结算时——空段（连续点、首尾点）是最高频漏判；②`val << 8 | segval` 的顺序——**先到的段占高位**，这正是**网络序（大端）**的存储形态，与 `inet_aton` 语义一致；③`seg != 4` 终检放循环外——循环内 break 时无法区分"正好 4 段"还是"3 段就到 '\0'"。

**不变量视角**：每轮结算后 `val` 的低 `8×seg` 位是已结算段的大端拼装——四段结算完即完整 IP。

## 五、复杂度

- **时间 O(n)**：n=串长（≤15），每字符一次分类；校验与解析同遍完成。
- **空间 O(1)**
  - **口径说明**：辅助=四个标量；输出 32 位值或调用者 buf 均不计辅助。对照 `inet_pton` 返回值语义（1 成功/0 格式错/-1 族不支持）可口述加分。
- **口述模板**："单遍解析 O(n)：逐字符累积段值，'.' 与 '\0' 统一结算并校验 0-255、空段、恰四段；每段 <<8 | segval 拼成大端序——与 htons/inet_aton 同构，网络字节序是本质而非巧合。"
