# S-02｜141/142. 环形链表 I/II 判环+找入口（Linked List Cycle I/II）

> **卡头**：S-02｜LC141/142｜F1 链表族｜P0｜Easy/Medium｜C++（C 风格）
> **实证**：小米 HS-002｜大疆 B2-15｜vivo HS-088
> **定位**：Floyd 快慢指针——面试官最爱追问"为什么一定相遇、为什么入口等于分程换算"的手撕题，a=c 推导是核心弹药。

---

## 一、题目解析

- **输入**：链表头 `head`（141 另给 `pos` 表示尾接到的下标，函数签名不传）。节点数 0~10⁴，值域 −10⁵~10⁵。
- **输出**：141 判环返回 bool；142 **返回入环第一个节点**，无环返回 nullptr——只改判断不改链。
- **约束确认**（写码前 30 秒口述）：`pos=-1` 无环？→是；单节点自环？→是；允许 O(1) 空间？→Floyd 可达，别急着哈希。
- **一句话考什么**：快慢指针的**相遇证明**+**分程推导**——两问共用一套设定，142 是 141 的自然延伸。

## 二、解题思路

龟兔赛跑：慢指针一步、快指针两步同发。若无环快者先到空；若有环两者进环后速度差 1，每轮**追近 1 格**，距离从 d 递减到 0——不重踏、不跳过（速度差 1 是关键），必相遇。

**指针现场示意**（入环前 a 段、环 b 段，相遇点距入口 c）：

```
head → a 格 → [入口●]─── b-c ───→ ●相遇
              ↑  ←─── c ←──────╯
              └──── 环长 b，入口到相遇点走 c 格

追上时：慢走 a+c（进环后未满一圈即被追上）
        快走 a+c+nb（比慢多绕整数圈）
        2(a+c) = a+c+nb  →  a = nb - c
```

**a=c 推导（完整版）**：相遇得 `a = nb − c`，即 `a + c = nb`。**一个指针从 head 走 a 步、另一个从相遇点走 a 步**：后者总程 `a + c + (a − c) = nb + a − c`，其中 `nb` 是环长的整数倍——可整圈约掉，剩下 `a − c + c = a`？更清晰的等价读法：从相遇点再走 `a` 步 ≡ 从相遇点走 `nb − c` 步 ≡ **先倒退 c 格到入口、再绕整圈**——所以它恰好也停在入口。两指针同速同发、同数到达，入口锁定。

## 三、代码（两版）

### 3.1 面试清爽版（现场手写形态，142 版；141 截到相遇判定即返回 true）

```cpp
class Solution {
public:
    ListNode* detectCycle(ListNode* head) {
        ListNode* slow = head;
        ListNode* fast = head;
        while (fast && fast->next) {
            slow = slow->next;
            fast = fast->next->next;
            if (slow == fast) {
                ListNode* p = head;
                while (p != slow) {
                    p = p->next;
                    slow = slow->next;
                }
                return p;
            }
        }
        return nullptr;
    }
};
```

### 3.2 教学讲解版（关键决策注释）

```cpp
class Solution {
public:
    ListNode* detectCycle(ListNode* head) {
        // 两者必须同点出发（都从 head）——若起点错开，
        // "每轮追近 1 格"的相对距离论证就被引入了偏置
        ListNode* slow = head;
        ListNode* fast = head;
        // fast 先触空：循环条件查 fast 和 fast->next 两级，
        // 否则无环时 fast->next->next 对空指针解引用
        while (fast && fast->next) {
            slow = slow->next;          // 1 步
            fast = fast->next->next;    // 2 步——速度差恰为 1
            // 相遇即有环：环内距离每轮减 1，减到 0 必然发生；
            // 速度差 2 会跳过奇偶错位，差 1 不会——这是选 1/2 而非 1/3 的原因
            if (slow == fast) {
                // 数学结论落地：head 走 a 步与相遇点走 a 步同达入口，
                // a 的具体数值不需要知道，两指针同步走对齐即可
                ListNode* p = head;
                while (p != slow) {
                    p = p->next;
                    slow = slow->next;  // 同速 1 步——谁快谁慢都会错过入口
                }
                return p;
            }
        }
        // fast 一侧到空 = 链有终点 = 无环，141 版此处改 return false
        return nullptr;
    }
};
```

## 四、代码解析

**三块结构**：

1. **同点起步块**：slow/fast 都从 `head` 出发——相对距离从 0 起算，追近论证才干净。
2. **判环主循环块**：先走后判（第一轮后两者已分开，首轮 `slow==fast` 误报被天然避开）。循环条件查两级（`fast`、`fast->next`），无环时快者先出界，`fast->next->next` 永不对空解引用。
3. **找入口块**：相遇后新起 `p` 从 head 出发，与 slow **同速**前进——"同速"是 a=c 推导的直接翻译；谁快谁慢都会错过入口。

**不变量视角**：判环阶段，"slow 走 s 步时 fast 恰走 2s 步"恒成立；进环后化为"距离每轮减 1"，递减到 0 即相遇。找入口阶段，"p 与 slow 走的步数恒相等"不变，走到重合时步数=a=分程公式保证的入口位置。

## 五、复杂度

- **时间 O(n)**：判环阶段慢指针进环后一圈内被追上，至多 2n 级；找入口阶段两者合计至多再走 n 步。141/142 同阶。最坏=平均（与值分布无关）。
- **空间 O(1)**
  - **口径说明**：指**辅助空间**——slow/fast/p 三个指针 O(1)；输入节点不计入；判断过程**零修改链结构**，无输出空间。
  - 对照口径：哈希表存 visited 节点做判环是 O(n) 辅助空间——Floyd 的存在意义就是把这 n 个砍掉。
- **口述模板**："时间 O(n)，慢指针至多被追一圈、找入口再走一段；辅助空间 O(1)，就三个指针；哈希版要 O(n) 存访问过的节点，所以标准答案用 Floyd。"
