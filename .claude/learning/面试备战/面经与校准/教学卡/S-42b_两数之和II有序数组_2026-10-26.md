# S-42b｜167. 两数之和 II（有序数组）

> **卡头**：S-42b｜LC167｜F8 数组与矩阵族｜**10-26 数组·字符串四题第二张（总清单未单列，挂 S-46 Hot100 池内 LC1/LC167 两数之和条目下）**｜Medium（思维难度高于编码难度）｜C++（C 风格）
> **实证**：字节 HS-029 两数之和（无序版）；S-46 池明文含"两数之和"
> **定位**：**左右对撞双指针模板题**——"有序才能夹逼"是本题唯一考点。与无序版 LC1（哈希）构成一对必考对照：同一道题，有序与无序两种做法，正好展示"看到有序条件该想到什么"。

---

## 一、题目解析

- **输入**：**已按升序排列**的整数数组 `numbers`（1 ≤ n ≤ 3×10⁴，-1000 ≤ 值 ≤ 1000）；目标 `target`。
- **输出**：两个下标 `{i, j}`（i < j），使 `numbers[i] + numbers[j] == target`；题目保证恰有一个解。
- **约束确认**：
  1. 数组有序吗？能用吗？→ 升序是**本题成立的前提**，读题第一眼就要圈出来。
  2. 同一元素能用两次吗？→ 不能（下标不同）。
  3. 会不会无解/多解？→ 恰好一个解，不用考虑去重或多答案收集。
- **一句话考什么**：怎么**利用有序性排除候选**——每次比较能干掉一整行或一整列的可能性。

## 二、解题思路

暴力：两层循环试所有 pair，O(n²)——没用到有序，必然被否。

另一个"标准"做法：哈希表（无序版 LC1 的解法），O(n) 时间但 O(n) 空间——**也没用到有序**。

第三条路才是本题的正解。设 `l` 指向最小、`r` 指向最大，算 `sum = numbers[l] + numbers[r]`：

- `sum == target`：结束。
- `sum < target`：**太小了**。想变大——`r` 往左只会更小，没用；唯一能变大的方向是 `l++`。这一步**排除了 `numbers[l]` 与任何其他数配对的可能**（连最大的 r 都配不平它，别人更不行）。
- `sum > target`：对称地 `r--`，排除"任何数与 `numbers[r]` 配对"。

每轮干掉一行或一列，最多 n 轮，O(n)。

```
numbers = [2, 7, 11, 15],  target = 9

l=0            r=3
 2 + 15 = 17 > 9  → 太大，r--
l=0         r=2
 2 + 11 = 13 > 9  → r--
l=0      r=1
 2 + 7  = 9  = 9  → 命中，返回 {1, 2}（1 起始下标）

l ─────────────►        l 每一步都有理由：
  ◄───────────── r      "连 r 都救不动 l，l 就没戏了"
```

## 三、代码（两版）

### 3.1 面试清爽版

```cpp
vector<int> twoSum(vector<int>& numbers, int target) {
    int l = 0, r = (int)numbers.size() - 1;
    while (l < r) {
        int sum = numbers[l] + numbers[r];
        if (sum == target) break;
        if (sum < target) l++;
        else              r--;
    }
    return {l + 1, r + 1};
}
```

### 3.2 教学讲解版

```cpp
vector<int> twoSum(vector<int>& numbers, int target) {
    int l = 0, r = (int)numbers.size() - 1;
    while (l < r) {                     // 不变量：解若存在，必在 [l, r] 内
        int sum = numbers[l] + numbers[r];
        if (sum == target) break;       // 命中即出，题目保证唯一解
        if (sum < target) l++;
        // 为什么敢丢掉 numbers[l]：它是当前区间最小，配当前最大 r 都
        // 不够 target——换任何更小的右值更不够，l 与所有人的配对全排除
        else              r--;
        // 对称：numbers[r] 配当前最小 l 都超 target，r 与所有人配对全排除
    }
    return {l + 1, r + 1};              // 题目要 1 起始下标，+1 收尾别忘
}
```

## 四、代码解析

**两块结构**：

1. **夹逼块**（while 循环）：每轮一次比较，三分支走一条。顺序纪律：先判 `==` 再判大小——若先 `l++` 再判，命中态就被跳过了。
2. **收尾块**：下标 +1 转换。LC 风格坑，面试时口述一句"题目要求 1 起始"即可。

**不变量视角**：**"如果解存在，那两个下标一定都在 `[l, r]` 里。"** 每轮移动指针都是在"处决"一个已证明不可能的端点，不变量始终保住。向面试官讲这题，就讲这句话加"为什么敢扔"的那两行。

**与无序版（LC1）的对照**（面试官常拿这个探底）：

| | LC167 有序 | LC1 无序 |
|---|---|---|
| 结构前提 | 升序 | 无 |
| 做法 | 左右对撞 O(n)/O(1) | 哈希表 O(n)/O(n) |
| 核心句 | "有序→每次比较排掉一行/列" | "边扫边查：见 x 问 target−x 来过没" |

被问"为什么不用哈希"时的标准回答："有序条件下对撞指针做到 O(1) 辅助空间，且缓存友好；哈希是没利用有序性的通用解。"——这句本身就是加分点。

## 五、复杂度

- **时间 O(n)**：每轮 l、r 至少一个向内走一格，总步数 ≤ n；无最坏/平均差异。
- **空间 O(1)**（口径：辅助空间；返回的 2 元下标为**输出**不计入，输出 O(1) 也只是常数）。
- **口径说明**：除返回数组（长度恒 2）外零分配；不复制输入。
- **口述模板**："对撞双指针，一头一尾往中间夹；每轮依据与 target 的大小关系干掉一个不可能的端点，时间 O(n)，辅助空间 O(1)——前提就是数组有序。"
