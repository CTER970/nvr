# S-50｜两线程交替打印 + 线程安全队列 + 线程池骨架（口述级）

> **卡头**：S-50｜嵌入式原创｜F10 并发族｜P1｜嵌入式进阶｜纯 C（原创轨）
> **实证**：定性（S-49 通过后的追问延伸；A4X AB 线程交替为同源实考）
> **定位**：S-49 的三连追问族——同一套 mutex+条件变量骨架，换考察点：**交替打印**考"轮到我才动"的谓词设计，**线程安全队列**考"每一步操作都在锁内"，**线程池**考"任务=函数指针+参数"的组织方式。

---

## 一、题目解析

- **输入 A（交替）**：两线程分别只打印 "A"/"B"，要求输出严格 ABABAB…（N 对）。
- **输入 B（安全队列）**：多线程共用一个队列，push/pop 任意线程并发调用，不加任何限制（可阻塞可非阻塞，面试先问清口径）。
- **输入 C（线程池）**：固定 M 个工作线程 + 任务队列，`submit(fn, arg)` 提交后立即返回，工作线程循环取任务执行；`shutdown` 时优雅退出。
- **约束确认**（写码前 30 秒口述）：交替的"轮到我"怎么判断？→用一个 turn 变量做谓词；安全队列 pop 空了怎么办？→阻塞版 wait/非阻塞版返回错误码，两种口径都要会；线程池退出时任务队列还有活怎么办？→先问面试官"排干 or 丢弃"，优雅关闭=排干+毒丸或标志位。
- **一句话考什么**：条件变量三件套（谓词/wait/signal）在不同场景的**变奏**——骨架不变，变的是"条件谓词"和"谁唤醒谁"。

## 二、解题思路

**交替打印**：S-49 等的是"不满/不空"，这里等的是"**轮到我**"。turn 变量（0=该 A 线程，1=该 B 线程）：A 线程 `while(turn!=0) wait(cv_a)`，打印后 `turn=1; signal(cv_b)`——两个条件变量各等各的，比单条件变量双线程互抢再重判更清晰。

**线程安全队列**：把 S-49 的 `q_push/q_pop` 抽成通用模板——**任何共享数据的读写都在锁内，任何"等条件"都用 while 重判**。非阻塞版=条件不满足直接返回 -1（EAGAIN 风格），调用方决定重试还是放弃。

**线程池**：安全队列 + M 个跑同一循环的线程 + 一个退出协议。任务结构 `struct task { void (*fn)(void*); void *arg; }`——函数指针把"做什么"变成数据。退出：置 `stop=1` + broadcast 唤醒所有人 + 工作线程 `while(!stop && 队列空) wait`（排干版：stop 后仍取完队列再退）。

```
交替打印（turn 谓词）：
  线程A: lock → while(turn!=0) wait(cvA) → 打印A → turn=1 → signal(cvB) → unlock
  线程B: lock → while(turn!=1) wait(cvB) → 打印B → turn=0 → signal(cvA) → unlock

线程池一生：
  submit: 封装 task{fn,arg} → 安全入队 → signal
  worker: while(1){ lock → while(!stop&&空) wait → 取 task → unlock → fn(arg) }
  shutdown: lock → stop=1 → broadcast → unlock → join 全部
```

进行到一半的现场（交替，第 3 对刚打完 A）：turn=1，B 醒来持锁打印，A 若此刻抢先拿到锁，`while(turn!=0)` 不成立继续睡——**谓词在锁内重判**保证了"醒了也不一定轮到我"。

## 三、代码（两版）

### 3.1 面试清爽版（交替打印核心）

```c
static pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t  cv_a = PTHREAD_COND_INITIALIZER;
static pthread_cond_t  cv_b = PTHREAD_COND_INITIALIZER;
static int turn;                       /* 0=A 的回合, 1=B 的回合 */

void *print_a(void *arg)
{
    int n = *(int *)arg;
    for (int i = 0; i < n; i++) {
        pthread_mutex_lock(&mtx);
        while (turn != 0)
            pthread_cond_wait(&cv_a, &mtx);
        putchar('A');
        turn = 1;
        pthread_cond_signal(&cv_b);
        pthread_mutex_unlock(&mtx);
    }
    return NULL;
}                                      /* print_b 完全对称 */
```

### 3.2 教学讲解版（线程池骨架，关键决策注释）

```c
typedef struct task {
    void (*fn)(void *);                /* 函数指针：任务="做什么"的数据化，
                                          这就是 C 没有 lambda 时的回调载体 */
    void *arg;
} task_t;

typedef struct pool {
    task_t            q[QCAP];
    int               head, tail, count;
    pthread_mutex_t   mtx;
    pthread_cond_t    cv_not_empty;
    int               stop;            /* 退出标志：只升不降，锁内读写 */
    pthread_t         workers[M];
} pool_t;

static void *worker(void *p_)
{
    pool_t *p = p_;
    for (;;) {
        pthread_mutex_lock(&p->mtx);
        /* 谓词必须含 stop：shutdown broadcast 后队列可能已空——
           只等"非空"的线程将永远睡死（唤醒了也重判失败回去睡） */
        while (!p->stop && p->count == 0)
            pthread_cond_wait(&p->cv_not_empty, &p->mtx);

        if (p->stop && p->count == 0) {    /* 排干版退出：活干完才走 */
            pthread_mutex_unlock(&p->mtx);
            break;
        }
        task_t t = p->q[p->head];          /* 取任务在锁内（共享队列）； */
        p->head = (p->head + 1) % QCAP;    /* 执行必须挪到锁外—— */
        p->count--;                        /* 任务函数耗时未知，持锁执行 */
        pthread_mutex_unlock(&p->mtx);     /* 等于把全池串行化 */

        t.fn(t.arg);                       /* 真正干活：无锁上下文 */
    }
    return NULL;
}

void pool_shutdown(pool_t *p)
{
    pthread_mutex_lock(&p->mtx);
    p->stop = 1;                           /* 先改标志再广播：保证醒来必见 stop */
    pthread_cond_broadcast(&p->cv_not_empty);   /* broadcast 不是 signal：
                                          要唤醒的是全部 worker，signal 只醒一个 */
    pthread_mutex_unlock(&p->mtx);
    for (int i = 0; i < M; i++)
        pthread_join(p->workers[i], NULL);
}
```

## 四、代码解析

**三块结构**：

1. **谓词块**：三个场景三个谓词——交替="turn 是我"、安全队列="非空/非满"、线程池="非空 **或** stop"。顺序纪律：谓词判断必须在锁内（与 S-49 同源理由）。
2. **执行块**：线程池的"取任务在锁内、执行在锁外"是**必须**的拆分——持锁执行任务等于把并行池退化成串行队列，这是线程池题最常见的隐藏挂点。
3. **退出块**：stop 置位 → broadcast → join 三步不可乱序；broadcast vs signal 的选择由"要醒几个"决定。

**不变量视角**：任一线程持锁时，"turn ∈ {0,1} 且恰表示下一个该打印的线程"+"队列内容/count 一致"+"stop 单调不回"恒成立；交替正确性由 turn 谓词直接给出——打印动作只在谓词成立时发生，而谓词翻转与打印在同一临界区内原子完成。

## 五、复杂度

- **时间**：交替打印每轮 O(1)（一次谓词+一次唤醒，上下文切换成本由调度器吸收）；线程池单任务派发 O(1)，吞吐上限=临界区（入队/出队）速度——**任务执行时间不影响其他 worker 取活**（锁外执行的直接收益）。
- **空间 O(QCAP+M)**
  - **口径说明**：任务队列与 worker 线程栈是**结构性必需**（题目要求的载体，非算法辅助）；每任务零额外堆分配（定长数组版）；若换动态链表队列则辅助=当前任务数。
- **口述模板**："三个题一个骨架：mutex+条件变量+锁内谓词重判。交替打印谓词是 turn，两条件变量各管一线程；安全队列谓词是非空非满；线程池谓词加一个 stop 通道——广播唤醒全部、取任务在锁内执行在锁外、排干再退。S-49 的骨架直接搬。"
