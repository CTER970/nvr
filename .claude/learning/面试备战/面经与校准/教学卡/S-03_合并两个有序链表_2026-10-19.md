# S-03｜21. 合并两个有序链表（Merge Two Sorted Lists）

> **卡头**：S-03｜LC21｜F1 链表族｜P0 第二批｜Easy｜C++（C 风格）
> **实证**：海康 HS-021/039（现场）｜TP-LINK 成都 B2-20（数组变体）｜字节 PICO B2-34｜OPPO B2-17 组题之一
> **定位**：dummy 哨兵 + 尾指针不变量——贯穿后续所有"头可能被换"链表题的两个手法。
> **配套图示**：`S-03_思路流程图_2026-10-19.svg`（与本卡同目录，思路段图解）

## 一、题目解析

- **输入**：两条升序链表 `list1`、`list2`。节点数 0~50，值域 −100~100。
- **输出**：一条升序链表——**由两条原链表的全部节点拼接而成**（不新建节点、不拷贝数据，只改指向）。
- **约束确认**（写码前 30 秒口述）：两条都可能为空？→是；值有重复？→可能；原地拼接？→是。
- **一句话考什么**：双指针"比较摘取" + 哑哨兵消特判 + **余段整体接上**的边界意识。

## 二、解题思路

两条链表各自有序，合并退化为**归并**：每轮只比较两个队头，谁小摘谁，接在结果尾部。造哑节点 `dummy` 占住头的位置（头的归属不确定，dummy 让第一次接入和第一万次接入是同一行代码），`tail` 维持不变量——**永远指向已合并段最后一个节点**。任一条耗尽即停，剩余段本身有序，整体接上。

**思路流程图**（文字版，SVG 版见同目录文件）：

```
list1:  1 → 2 → 4 → NULL          ┌─ 谁小摘谁 → 接到 tail 后
list2:  1 → 3 → 4 → NULL          │  （相等取 list1：稳定）
                                  │
dummy → [已合并段] → tail ────────┘→ 来源指针前进 → tail 前进
                                    │
                     一条耗尽？──是──→ 余段整体接 tail->next → 返回 dummy.next
```

三轮循环后的现场（示例 [1,2,4]+[1,3,4]）：

```
dummy → 1(l1) → 1(l2) → 2(l1) → tail
list1: 4 → NULL        （未处理剩余段）
list2: 3 → 4 → NULL    （未处理剩余段）
```

## 三、代码（两版）

### 3.1 面试清爽版（现场手写形态）

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        ListNode dummy(0);
        ListNode* tail = &dummy;

        while (list1 && list2) {
            if (list1->val <= list2->val) {
                tail->next = list1;
                list1 = list1->next;
            } else {
                tail->next = list2;
                list2 = list2->next;
            }
            tail = tail->next;
        }

        tail->next = list1 ? list1 : list2;
        return dummy.next;
    }
};
```

### 3.2 教学讲解版（关键决策注释）

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        // 选哑哨兵而不是特判：结果头的归属事先未知（可能来自任一条），
        // 哨兵让"第一次接入"与"后续接入"走同一行代码，头节点特判整体消失
        ListNode dummy(0);
        // 建立不变量：tail 恒指向已合并段最后一个节点（此刻段为空，即 dummy）
        ListNode* tail = &dummy;

        // 两条都未耗尽时，当前最小节点一定出现在两个队头之一——
        // 这是"有序"前提给出的保证，也是本算法 O(m+n) 的根基
        while (list1 && list2) {
            if (list1->val <= list2->val) {
                // 摘接必须先于来源前进：先前进就丢了当前节点的下家
                tail->next = list1;
                list1 = list1->next;
            } else {
                tail->next = list2;
                list2 = list2->next;
            }
            // 恢复不变量：新节点成为"已合并段最后一个"，tail 必须跟上，
            // 否则下一轮的 tail->next 会覆盖本轮成果
            tail = tail->next;
        }

        // 剩余段整体接上的合法性：它内部仍然有序，逐节点再循环纯属浪费
        tail->next = list1 ? list1 : list2;
        return dummy.next;
    }
};
```

## 四、代码解析

**三块结构**：

1. **初始化块**：`ListNode dummy(0)` 是**栈上对象**（不是 `ListNode* dummy(0)`——那是空指针，没有节点存在）。dummy 是脚手架，函数返回自动回收，零内存管理。`tail = &dummy` 起步，此时已合并段为空。
2. **主循环块**（三拍：比较→摘接→双前进）：两条顺序纪律——①摘接先于来源前进（反了丢下家）；②`tail = tail->next` 不能漏（漏了下轮覆盖上一轮成果）。`<=` 保证稳定性（相等取 list1）。
3. **收尾块**：至多一条非空，剩余段**连同内部所有节点**一次挂上——它们本就有序，逐节点循环是浪费。

**不变量视角**：每轮开始时，"dummy→tail 是有序已合并链，list1/list2 各指向有序剩余段"恒成立；循环结束时该命题直接给出正确性。

## 五、复杂度

- **时间 O(m+n)**：每轮恰好消耗一个节点，每个节点恰好被摘取一次。本题最坏=平均（与数据分布无关，节点数定则轮数定）。
- **空间 O(1)**
  - **口径说明**：指**辅助空间**——dummy 是一个固定大小的栈对象，三个指针为 O(1)；题目已提供的 m+n 个链表节点属**输入空间，不计入**；结果链**复用输入节点**（零新建、零拷贝），无独立输出空间。
  - 迭代实现**无递归栈**；若换递归版，需另计 O(m+n) 递归栈深。
- **口述模板**："时间 O(m+n)，每个节点恰好处理一次；辅助空间 O(1)——只用了哑节点和指针，结果复用原节点、没有新申请内存；递归版要加 O(m+n) 栈深，所以现场用迭代。"
