# S-21｜MAX/MIN 宏与副作用（typeof 安全版）

> **卡头**：S-21｜嵌入式原创｜C2 位运算/C 基本功/嵌入式特色族｜P0 第三批｜基础+｜纯 C
> **实证**：全志 HS-098（MAX 宏原题）
> **定位**：宏=纯文本替换——参数括号/整体括号/副作用双求值，一题讲透；GCC 语句表达式是逃生门。

---

## 一、题目解析

- **输入**：写一个 MAX(a,b) 宏；追问：`MAX(i++, j)` 会发生什么；如何写出无副作用的版本。
- **输出**：正确展开的宏定义 + 对文本替换本质与副作用的分析。
- **约束确认**（写码前 30 秒口述）：宏还是函数？→题目指定宏（考替换本质）；参数可能是表达式吗？→可能，所以每处出现都要括号；会不会被求值两次？→会，副作用参数因此翻车。
- **一句话考什么**：宏不是函数——没有求值一次的契约，展开几次就求值几次。

## 二、解题思路

宏是预处理器的**纯文本替换**：`#define MAX(a,b) ((a)>(b)?(a):(b))` 中每个参数每次出现都被原样贴入。由此两条铁律：①**参数整体加括号**（防 `MAX(a&1,b)` 展开成 `a&1>b` 这类优先级事故）、**结果整体加括号**（防 `3*MAX(a,b)` 变 `3*a>b?a:b`）；②**副作用参数被求值两次**——`MAX(i++,j)` 若 i 较小，i++ 在条件与返回值处各展开一次，i 自增两次。

```
#define MAX(a,b) ((a)>(b)?(a):(b))      输入 i=1, j=5：

MAX(i++, j) 文本展开 →  ((i++)>(j)?(i++):(j))
                        └─求值①┘        └─求值②（i 较小时命中）
条件判 1>5 假 → 返回 (j)=5，但 i++ 已在条件处自增一次；
若 i 大则命中 (i++) 又自增 → 无论哪边，i 可能 ++ 两次、返回值与 i 终值都不符预期

括号缺失事故：
#define SQ(x) x*x     SQ(1+2) → 1+2*1+2 = 5（不是 9）
优先级事故：MAX(a,b)*3 不加整体括号 → (a)>(b)?(a):(b)*3 三目嫁接乘法
```

补救：C++ 用 `std::max`/inline 模板（真函数，单次求值）；纯 C 的 GCC 扩展 **语句表达式** `({ ... })` 把两值先存入局部变量再比较——每参数恰求值一次，类型自动随参（`__typeof__`），是内核源码的标准写法。

## 三、代码（两版）

### 3.1 面试清爽版（现场手写形态）

```c
/* 常规版：括号齐全，但副作用参数双求值 */
#define MAX(a, b)   ((a) > (b) ? (a) : (b))
#define MIN(a, b)   ((a) < (b) ? (a) : (b))

/* GCC 安全版：语句表达式，参数仅求值一次 */
#define MAX_SAFE(a, b) ({      \
    __typeof__(a) _a = (a);    \
    __typeof__(b) _b = (b);    \
    _a > _b ? _a : _b;         \
})
```

### 3.2 教学讲解版（关键决策注释）

```c
/* 每个参数每次出现都括号：防 MAX(a&1, b) 展开为 a&1>b（& 优先级低于 >）；
   整体再括号：防 3*MAX(a,b) 展开为 3*a>b?a:b（三目优先级低于乘法）。
   但括号救不了副作用：MAX(i++,j) 中 i++ 出现两次即求值两次 */
#define MAX(a, b)   ((a) > (b) ? (a) : (b))

#define MAX_SAFE(a, b) ({          \
    /* 语句表达式 ({...})：块内可声明变量，末条表达式是整个"表达式的值"。
       参数在初始化处各出现恰一次——副作用被固定为单次求值 */  \
    __typeof__(a) _a = (a);        /* 类型随参数自动推导，a/b 异型也安全 */ \
    __typeof__(b) _b = (b);        \
    _a > _b ? _a : _b;             /* 比较的是副本，与外界再无牵连 */       \
})
/* 注意：_a/_b 是普通局部名，若调用方恰好也传 _a 会自我遮蔽——
   内核用 __UNIQUE_NAME 拼接行号解决，面试口述该点即加分 */
/* 工程补充：C++ 中优先 std::max/inline 函数；纯 C 且无 GCC 扩展时，
   用 static inline 函数承担 MAX 职责（代价：类型固定/需多版本） */
```

## 四、代码解析

**三块结构**：

1. **常规宏**：文本替换的正确姿势全在括号——参数括号防"传入表达式被运算符撕开"，整体括号防"宏结果被外层运算符嫁接"。这两层括号是宏定义的及格线。
2. **副作用分析**（全志考点核心）：三目运算符的两个分支各含参数一次+条件一次，命中分支的那次与条件那次让副作用参数最多自增两次；函数没有此问题（实参求值一次后传值）——这就是"宏没有函数语义"的实证。
3. **MAX_SAFE**：`({...})` 语句表达式（GCC/Clang 扩展，非 ISO C）——块作用域变量先"冻结"参数，副作用单次；`__typeof__` 保类型泛型。局限要主动声明：不可移植（MSVC 不支持）、变量名可能遮蔽（内核 `__UNIQUE_NAME` 方案）。

**不变量视角**：MAX_SAFE 的不变量是"参数文本出现次数=1"（常规版=2）；只要该不变量成立，副作用次数与函数调用严格一致，语义即可靠。

## 五、复杂度

- **时间 O(1)**：宏展开后是一次比较+至多一次赋值序列；与参数类型、数值无关（注意口径：若参数本身是 O(f) 的函数调用，常规宏最坏调 2 次、安全版 1 次——副作用双求值的"性能面"）。
- **空间 O(1)**
  - **口径说明**：指**辅助空间**——MAX_SAFE 在栈上多两个临时量 `_a/_b`，仍是常数；常规版零临时。均无递归、无输出空间。
- **口述模板**："宏是纯文本替换：参数括号+整体括号是及格线，但括号救不了 MAX(i++,j) 的双求值——三目里参数出现两次；GCC 语句表达式先把参数各存一次再比，单次求值、typeof 保类型，代价是不可移植。"
