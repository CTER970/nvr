# 32 · C 与 C++ 语言考点专批（2026-10-26 建）

> **定位**：把存量 137 池里所有「C 语言 / C++ 语言本体」的题面抽干净，出一份只讲语言的榜，用来回答两个问题：①**C++ 到底要备多少**（现有备考册只写了「C++ 三句」）；②**C 语言哪些点被我漏了**。
> **口径（10-26 用户拍板）**：只收**普通 Linux 应用岗**的 C++（影像/多媒体岗算在内；端侧推理、车载中间件这类重 C++ 场只入 C 榜、不入 C++ 榜）；不收社招；不收 OS/网络/驱动/RTOS 题，哪怕同场出现。
> **与既有体系的关系**：题面沿用 30 号可信度分层与 31 号准入标准；本批**不重采**，全部来自存量，唯一动作是「抽取 + 归类 + 补出处标注」。频率口径与 v3 八股榜不冲突，可对照。
> **一句话结论**：C++ 不用 50 场——**21 场已经饱和**，考点在第 10 场之后基本不再新增；真正缺的是 C 侧的「内存泄漏、字节对齐、编译链接、malloc 底层」四个点，现在备考册里没有独立条目。

## 一、样本量结论：50 份够不够？

**结论：50 份作为「总量」合适，作为「C++ 专采量」是浪费。C++ 侧 18–22 场就见底。**

三条依据：

| 依据 | 数字 | 说明 |
|---|---|---|
| 存量里带 C/C++ 题的场次 | **53** | 137 池去重后 118 个样本，其中 53 个载有语言题，全部纳入本批 |
| 其中 C++ 有效场次 | **21** | 再剔掉 2 个重 C++ 岗（小米端侧部署 CL-08/CL-35） |
| C++ 考点的长尾形状 | 多态 11 场、智能指针 5 场，其余**全部 ≤4 场**，10 个点只有 1 家 | 第 10 场之后新增的只有孤证 |

判饱和的方法很简单：**看新增场次还带不带新考点**。本批 21 个 C++ 场里，前 10 场把「多态/虚表、智能指针、构造析构、C 与 C++ 区别、STL、new/delete、extern "C"」全部覆盖了；后 11 场只多了四种 cast、深拷贝、模板、移动语义四个**各 1 家**的点。再加 30 场，大概率还是这四样重复出现——对「哪些是高频」没有任何增量。

所以执行口径定为：**总量 53（已有）+ 空白公司补 6 场 = 59 封顶**。要补的不是数量，是覆盖缺口（见 §五）。
