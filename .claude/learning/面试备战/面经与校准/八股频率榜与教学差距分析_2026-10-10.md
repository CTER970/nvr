## 二、v3 增量结论（B1 批带来的新信息）

1. **头部两桶实质并列（89 vs 87）**。B1 批的"进程线程/IPC/锁"密度极高（15/20），与 C/C++（11/20）共同确认：**头部是双榜首结构**——v2 的"C/C++ 单独第一"应修正为"双榜首并列"。
2. **手撕升 26%→29%**，且 B1 批内 50%：**字节线 8/8 全部含手撕**（含 LC hard 级：JSON 转对象类）。总体仍 <50% 加量线，但大厂线是强信号（见五-P1.5 的加量决策点）。
3. **编译链接（P1#41）再证**：B1 内 6/20（字节 5 份集中 + 影石 1）。若锁定投字节系，建议升入"第二遍优先层"。
4. **数据结构首次成簇**：哈希表/红黑树/B+树在 B1 出现 5/20（字节、TPL、影石）——含"设计数据库选红黑树还是 B+树""20 亿 int 存储设计"这类选型题，132 池从未有此密度 → 新增微点候选。
5. **体系结构三连首次出现**：缓存命中（按行按列遍历）/CPU pipeline/汇编调用与上下文切换（TPL、影石、字节 3/20）→ 新增微点候选。
6. **新面问法入库**：日志 CPU 占用优化、工程内嵌死锁监控机制设计、A/B 分区 OTA 回滚、环形 vs 乒乓缓冲、最大客户端连接数、websocket、HTTPS 握手过程。
7. **靶子与污染（校准资产）**：字节 8 份大丰收；**NXP/科达/富瀚微/虹软全部 0 净收**（旧帖超期 / 伪面经污染 / 公开渠道无帖）；白名单五家（海康/大华/大疆/小米）被 AI 内容农场大量占据——防污染规则已在 B1 批验证有效（库内重复 12 份全部识别剔除、拦下 5 份存疑帖）。

## 三、关键发现（v3 更新版）

### 发现 1：校招一面生死线 = 语言基础 + 进程线程 + 手撕（数字更新）
C/C++（57%）、进程线程（59%）并列第一，手撕 29%（大厂线 50%+）——"硬门槛三件套"的结论不变，且双榜首并列意味着**语言与并发两条线都不能偏科**。

### 发现 2：「调试排查」校招高频结论再证（43/152，28%）
B1 再添 8 例（字节死锁监控设计/影石 HardFault/涂鸦打印定位/星宸 gdb）。项目 5 个排查故事 + P1 工具链卡的配置维持。

### 发现 3：RTOS 升至 26%，但"混合岗税"性质不变
39/152 全来自混合岗（B1：字节/小米汽车/移远/涂鸦/影石/网易），**方向榜（纯应用）连续三轮为 0**。维持概念级准备，不动项目主线。

### 发现 4：音视频专项 7:3 分层不变，B1 补三条应用层素材
B1 的 rtsp/rtmp 协议对比（芯长征）、v4l2 抓图流程（移远）、ffmpeg 图像处理（网易）均属应用层——继续验证"应用层主力、驱动层话术"的分层策略。

### 发现 5：手撕题型清单再扩充（v3 版）
原清单（链表/字符串位操作/栈队列/RingBuffer/TopK/DP/二叉树）+ **B1 新增：二维矩阵原地翻转、矩阵连通区域计数、均值滤波（图像类首次入镜）、二叉树左视角、下一个最大数字组合、链表倒数第 K 节点、线程安全单例、AB 线程同步打印**。
→ 分类收敛为四族：链表族、矩阵/图像族、字符串/数字族、**线程同步族**（与并发桶联动，是项目能讲故事的手撕）。

### 发现 6：网络双钉子户 + IoT 新贵（更新）
epoll 与 TCP 可靠性稳定（B1 增 3 例 epoll）；MQTT 在此前已达 6 次，B1 再添移远/涂鸦 2 例；**新增小钉子户：HTTPS 握手（2）、websocket（1）、最大连接数（1）**——大厂/直播类岗的边角料考点。

## 四、对照 EdgeFusion 教学体系的差距分析（v3 更新，结论不变）

评级：**✅ 覆盖良好｜⚠️ 有覆盖但不足｜❌ 盲区**

| 考点桶 | v3 频率 | 体系覆盖 | 评级 | 说明 |
|---|---|---|---|---|
| 进程/线程/IPC/同步 | #1 (59%) | Phase 1/2 散落素材 | ⚠️ | 项目一手素材（三线程模型/event_bus 锁/所有权设计）继续有效；需收口通识卡 |
| C/C++ 语言基础 | #2 (57%) | 几乎无 | ❌ | 含编译链接（P1#41）；字节线密度更高 |
| 驱动与底层接口 | #3 (45%) | 无（应用层项目） | ⚠️ 半盲区 | 概念级即可；CAN 仅车企需要 |
| 网络编程 | #4 (41%) | Phase 1.5/3 | ✅ | 体系最强项；B1 新边角料（HTTPS 握手等）按需补 |
| OS 内存管理 | #5 (38%) | Phase 1 零散 | ⚠️ | 虚拟内存/malloc 链路补概念；项目故事继续有效 |
| Linux 系统与启动 | #6 (30%) | Phase 0 概念 | ⚠️ | 启动流程/系统调用补概念 |
| 手撕算法 | #7 (29%) | 无 | ❌ | 大厂线 50%+；题型四族收敛 |
| 调试排查 | #8 (28%) | 无 | ❌ | 排查案例库必要性三轮确认 |
| RTOS | #9 (26%) | 无 | ❌（概念级） | 混合岗税；方向榜 0 |
| 音视频专项 | A 类 ~50%+ | Phase 1/1.5/5 | ✅ | 核心强项，7:3 分层准备 |

## 五、教学模式调整建议（v3 增补）

### P0：通识八股副线（不变 + 新增两个条件微点）
顺序不变：**C/C++（57%）→ 进程线程（59%）→ 驱动通识（45%）→ OS 内存（38%）→ Linux 启动（30%）→ RTOS 概念（26%）→ 网络通识**。
**新增条件微点（仅投字节/大厂线时补）**：① 数据结构三件套（哈希表冲突 / 红黑树 vs B+树选型 / 排序复杂度）；② 体系结构三连（缓存命中与遍历顺序 / CPU pipeline 概念 / 汇编调用与上下文切换一句）。
素材直接用 152 份总池原题；载体进八股卡片体系（铁律 6），不进任务卡主线。

### P1：排查案例库（三轮确认，维持）
5 个现成排查故事（关键帧花屏 / 慢客户端拖住 RTSP / 单帧缓存丢帧 / cleanup_disk / web_start 假成功）+ 工具链卡；B1 再证高频（字节"死锁监控设计"可作加分话术）。

### P1.5：手撕专项（题单增补 + 加量决策点）
- 题单增补：**矩阵族**（二维矩阵原地翻转、连通区域计数）、**图像族**（均值滤波——与项目帧处理语料直接呼应）、**线程同步族**（AB 线程同步打印、线程安全单例——项目可讲"单槽 vs 队列"）。
- **加量判断（提请拍板）**：全池口径 29%＜50% 不加量；但白名单等效口径 8/14=57%＞50% 已触线，规则 5 字面触发。因样本集中字节单公司，建议取**条件加量**：平时维持每周 2 题；一旦锁定字节/大厂线面试，临时提至每周 3 题。

### P2：音视频分层（不变）
应用层（H.264/流媒体协议/同步/播放器/码控）深备；驱动层话术。B1 新增素材（rtsp/rtmp 对比、v4l2 抓图、ffmpeg 图像）挂 Phase 6 收口。

### P3：场景题池扩充
加入 B1 四题：日志 CPU 占用优化、工程内嵌死锁监控设计、A/B 分区 OTA 回滚、最大客户端连接数。

### 目标公司差异化（新增字节系行）
- **投字节系（混合岗）**：RTOS 概念 + 编译链接 + 体系结构三连 + 手撕（含 hard 级）"四件套"是差异考点；
- 投车企：CAN/AUTOSAR/OTA（条件项）；
- 投安防/IPC：流媒体协议对比 + 花屏卡顿 + 项目排查故事；
- 投 SoC 原厂：内核深题按需加量；
- 投 IoT/家电：MQTT/FreeRTOS/通信协议。

### 不建议调整
Phase 结构与"数据流→模块→接口→函数"铁律不动；通识走副线不回流主线。
