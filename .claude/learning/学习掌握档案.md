## 1. 使用规则

1. 本文件回答“为什么判定为这个掌握等级”，不重复维护详细教学计划。
2. 学生的独立口述、闭卷回答、图表、源码追踪和变式追问都可作为掌握证据；不要求固定形式。Tutor讲过只能记为“已接触”。
3. 每次阶段或任务总结都应注明可见证据范围。聊天记录缺失的内容标记“未验证”，不得补写成已掌握。
4. 错误认知不删除；纠正后更新为“当场纠正 / 24h通过 / 72h通过 / 阶段复测通过”。
5. 掌握等级沿用总计划的 L0–L4；L4 必须区分静态完成和 Ubuntu/板端验证。

### 当前教学偏好与阅读方法

- 任务卡作为导航和诊断题库,由Tutor自主选择最有区分度的问题,不机械补齐全部图表。
- 默认顺序：先看文件在整体数据流中做什么→看头文件/外部库/关联模块→找关键状态量穿针引线→建立重点函数与调用关系→进入实现细节→分析错误后果→回答技术选型why。
- 判断重点是能否形成可迁移的代码心智模型；重复性格式产出可省略,关键因果误解必须纠正。
- 时间预算按真实节奏校准：1.5A–C合计约4h、1.6A约5h。后续L3源码/协议任务默认按旧预算的约1.7–2倍，L1–L2略读任务按约1.4–1.7倍；推荐时长必须包含主动阅读、学生口述、纠偏、复测和文档同步，而不只是AI讲解时间。

## 4. 模块代码心智模型

### 4.1 `stream_receiver`

- **数据流位置**：从上游 RTSP 源读取压缩媒体 Packet，筛选视频流后同步分发给录像、抽帧和 RTSP 转发。
- **输入**：网关配置、RTSP URL，以及拉流建立后的 FFmpeg 输入上下文和视频流参数。
- **输出**：向 `recorder`、`frame_grabber`、`rtsp_server` 交付或借用视频 Packet；通过状态接口提供运行快照。
- **已建立的生命周期认识**：`start → receiver_thread → stop设置退出标志 → join → release`；API 启动成功不等于业务已经连接。
- **尚待学生独立恢复**：外层连接/重连循环、内层读包循环、每个控制转移落点、断线清理顺序、Packet 提前退出时的兜底释放。
- **当前不能过度声称**：尚不能仅凭既有记录断言学生已完整掌握 `receiver_thread`、并发可见性或 FFmpeg 阻塞取消边界。

### 4.2 `recorder`

状态：1.6A、1.6B已完成；1.6C待学。已建立的心智模型：`recorder`是由接收线程同步调用的下游录像消费者，借用压缩视频Packet；它复制配置和源`codecpar`，用`ofmt/ost/header_written`维护当前输出段，以`waiting_key`保护首段或开段失败后的起始边界，并用“已写头＋当前关键帧＋达到时长”选择正常切段点。触发切段的关键帧在关闭/重开之后才进入公共写路径，因此属于新段。写失败不会复位输出状态；连续第21次失败使接收线程释放当前Packet、关闭输入并重连，而`g_rec`仍保留。1.6B资源半边：输出侧资源链=上下文→输出流→IO；关闭逆序 closep→free_context；`AVFMT_NOFILE`是muxer能力声明，close侧对称守卫；close含`av_write_trailer`（仅header_written时）与统一后置状态复位。1.6B写路径半边：movflags=fMP4三件套（empty_moov空目录先落盘/frag_keyframe按关键帧切fragment/frag_duration 10s兜底），是写给muxer的行为开关而非文件内容；写帧四步 clone（浅拷贝隔离字段修改）→rescale（src写死1/90000，真实时基未传入——rtsp_server那路传了tb，recorder接口没传，属脆弱假设）→stream_index=0→interleaved_write（成功拿走引用掏空包）。**已知缺陷**：`bytes_written += out->size`在包被掏空后读取，恒为0，导致`bitrate_kbps`与Web“当前段码率”恒0。1.6C补全:磁盘半身=cleanup_disk(水位检查statvfs→scandir按名排序=时间序→循环内手动三过滤(./隐藏、.mp4后缀、strstr(cur_path,name)子串跳当前段)→unlink删最旧→for头条件含空间仍不足→删后重测;仅create和开新段两调用点触发);对外脸面=get_status锁内快照(recording=ofmt&&header_written防误报、seg_index、cur_segment basename、bytes_written、seg_start_wall)锁外算elapsed+码率;失败总账=四类(create→NULL退线程;开文件→fail块释放上下文+ofmt/ost置NULL,状态靠调用点语境;写头→-1且**waiting_key已清0**资源保留(I-05窗口);写帧→-1状态不动,克隆壳free)。已知缺陷扩至I-01~I-06(码率恒0/时基未传/无前缀过滤/清理时机/非关键帧起段窗口/磁盘满熔断稀释)。

### 4.3 `frame_grabber`

状态：1.7A已完成（2026-08-20）。已建立心智模型：**receiver三分发的第二路消费者（旁路）**，输入是借来的H.264压缩Packet（调用后调用者仍负责unref，`.h:23-24`契约）；管线跨三个格式域：H.264 packet→软解码→原始YUV（g_dec_frame，源分辨率，buffer来自解码器池、登记在册）→sws缩放→YUVJ420P（g_dst_frame，目标分辨率，图像内存由init的av_image_alloc裸挂、释放两步）→MJPEG编码→JPEG packet→锁内realloc+memcpy到g_jpeg最新帧缓存。资源五组：解码g_dec/缩放g_sws/编码g_enc/输出缓存g_jpeg+g_lock/节流g_last_emit_us+g_cfg（私有配置快照，set_target_fps改字段即热生效）。生命周期归receiver：init在stream_receiver.c:120-130（!g_fg_inited守卫防重连重复初始化），deinit在stream_receiver_stop(c:211)pthread_join后；g_jpeg上三角色（写emit@receiver线程/读get_jpeg@web+cloud线程/毁deinit）全靠g_lock串行化，当前停机顺序下锁为防御性。节流在emit开头纯按时间（CLOCK_MONOTONIC微秒差），不看帧类型——原始域每帧完整；解码对每包无条件执行（参考链必须逐包维护）。**1.7B已完成**（feed/emit/闭卷三段全通过,2026-08-21）；**1.7C已完成**（节流/缓存/线程安全,2026-08-22,三卡闭合）——证据见下方两段。

**2026-08-21 直问模式续证（send/receive/EAGAIN）**：车间内部追问后讲透——解码实际发生于 `avctx->codec->decode` 的 H.264 流水线（熵解码→反量化/反变换→预测重建→环路滤波→DPB 按显示顺序输出），契约不规定解码在 send 还是 receive 触发（master 新版 send 内主动解码，旧版惰性于 receive，不应依赖时机）；背压设计=取货口有积压则投料口拒收（防内部缓冲无限涨）。**学生随后自主复述 feed 主线全对**（send 入队→车间解码→receive 到 g_dec_frame→emit 节流/缩放/编码/缓存，"内部暂时不用管"抽象层次恰当）。两处纠偏内化：①`g_dec_frame`=static 模块私有复用容器、永不出 frame_grabber.c，模块真正对外数据门=`frame_grabber_get_jpeg()`（交 JPEG malloc 拷贝非 AVFrame），"外面只见 JPEG 不见帧"（**用户明示要求记录此条**）；②"压缩视频流"→"视频包"（一包=一个access unit；用户承诺此后都说视频包）。复述漏项 while(1) 排空防 send EAGAIN 卡死（跨调用状态持久）与恒 return 0 旁路容错已补讲、未复述。

**2026-08-21 1.7B 证据（三段×60min 模式）**：①1.7B-1 feed：0/1/N 三情境独立构造全对（SPS/PPS 不吐帧/B 帧重排序/积压放行）；send-EAGAIN 方向纠偏后内化（官方契约=排空后应重发，本代码不重发→丢一包→参考链断到下个 IDR；稳态结构性不可达）；收口追问通过（空包传播、丢包 c:171 归还）。②1.7B-2 emit（"直接讲"模式）：引导四问独立作答全对（全局 g_dec_frame 归属/两 pkt 借用vs私有/JPEG intra 不循环/nb-realloc 防御）；pts 纠偏=三层证据法（无下游消费者）。③1.7B-3 闭卷：六节点+五箭头拓扑闭卷正确；pts 复述完整关闭；坏包路径作答正确且结构化（remux 延迟失败/IDR 恢复点/机械切分零感知/err_count 唯一决策者 c:157-158）——因并行会话已直讲同内容，记**复述级**，1.9 换情境独立抽查。

**2026-08-22 1.7C 证据（闭卷通过）**：①四问作答：节流饿死变式独立推出（每帧更新基准→now-last 恒为两帧间隔→全丢）✅，debounce 术语标签当场纠偏（debounce=静默后触发,非本模式）；单调钟价值 ✅（墙钟回拨→负差值全丢）；锁外理由纠偏（"独立"→**判定式=有无第二个线程碰**,单线程私有免锁）；撕裂读分析正确,补 UAF 半边（realloc 搬家 free 旧块=悬垂）。②收尾三件套：四变量审计表高质量——init 线程归属准确（receiver_thread 内 c:126,学生记忆准确）、**L206 return g_jpeg_size 锁外读为学生独立发现**（手册第四遍进阶题埋点,后果链=返回值与 buf 不配套→堆越界读,记 code-quality TODO 第⑨项）；精修两格（L47 无锁但启动期单线程良性、L129 deinit 在主线程 join 后）。③闭卷题三问全对（240ms<1000ms 丢弃/第 19 帧恰在 T0+1000ms 放行/改 target_fps 不动 last）。④时序图以口头题替代：**"不是锁本身保证了不阻塞,是锁划得小保证了""②的根本不是锁（是 malloc+memcpy 深拷贝断别名+所有权交割）"**——两个保证者区分自主推导,为学生原创表述,达手册通过标准"mutex 保护一致性 vs malloc 拷贝隔离锁外生命周期"。
