核心要点

  本报告基于 2026 年 10 月 15 日四路并行联网采集的 134 份真实面经，系统统计嵌入式 / Linux 应用开发方向面试中"手撕代码"环节的题型分布与频次。手撕环节出现率为 86.6%，已接近常规环节而非加分项。

  考点呈"两超多强"格局：链表操作（43.1%）与字符串 / 库函数手写（38.8%）为超级大类；单链表反转以 26 次居单项第一，链表判环（15 次）、环形缓冲区（11 次）、strcpy 手写（10 次）紧随其后。嵌入式特色题型（环形缓冲、滑动滤波、状态机、Makefile、socket 流程）合计占 23.3%，是区别于通用软开岗的签名题型。

  难度预期以基础档为主：Top 30 题目绝大多数要求"一遍写对 + 讲清复杂度 + 处理边界"。报告第五章给出 P0 / P1 / P2 分级练习清单与四步验收标准，并与项目既有手撕训练序列做了对照校准。

一、样本说明

本章说明样本的来源与采集方法、纳入与剔除标准、样本构成，以及使用频率数据前必须知晓的局限。

（一）采集目的与方法

本报告面向嵌入式 Linux 应用开发方向（C 语言为主）的校招 / 实习求职者，目标是回答三个问题：面试中的"手撕代码"环节到底考什么、各类题型出现多频繁、应当如何分配练习优先级。

采集于 2026 年 10 月 15 日完成，采用四路并行联网调研：牛客网面经区（66 份）、CSDN 及旗下开发者社区（40 份）、按公司定向检索（29 份）、手撕题专题统计类来源（28 份），共获得 158 条原始记录。经三轮整理后保留 134 份有效样本。

（二）纳入与剔除标准

样本纳入需同时满足以下条件：其一，内容为真实面试经历分享（含单场次面经、多公司汇总帖、专题题库整理帖）；其二，方向属于嵌入式、Linux 应用 / 系统开发或 C/C++ 工程岗；其三，口径为校招或实习，社招面经不计入。

题目记录口径为：仅收录面经中明确出现的"手撕 / 手写 / 白板 / 投屏写码 / 纸上写码 / 本地 IDE 写码 / 在线编程链接 / 笔试编程题"类题目，逐条保留原文措辞；纯口头八股问答不计入题目清单。若整篇面经只有八股没有手撕，样本保留并在题目清单标注"无手撕环节"，用于计算手撕环节出现率。

去重处理包括：同一 URL 只计一次；跨平台同内容镜像合并（如 CVTE 同一篇面经在牛客与博客园双发，保留一份）；与项目既有样本库（第一轮 152 份八股池）比对，剔除 URL 已收录的 15 条记录，保证本轮样本的独立性。完整去重记录见附录 B。

  样本局限性声明：36.6% 的样本为汇总 / 整理类帖子，个别原始面经内容会被汇总帖转述，频率统计中存在同源内容重复计数的可能，频次应当作"量级与排序"使用；样本时间跨度约 2017—2026 十个校招周期，早期帖子约占三分之一；部分牛客页面需登录才能打开全文，采集采用搜索引擎收录的正文快照替代，题目措辞与快照一致，但无法逐篇复核原帖。

二、手撕环节总体形态分析

本章从出现率、环节形式、考察方式与难度分层四个维度，刻画手撕环节在嵌入式 / Linux 应用岗面试中的整体形态。

（一）手撕是常规环节，而非加分项

116/134 份样本存在手撕或笔试编程题，出现率 86.6%。这一数字显著高于项目既有八股池中"手撕约 21%"的历史记录，原因是口径差异：既有样本库以八股问答为主要记录对象，手撕题只在面经作者顺带提及时才被记下；本轮为手撕专题采集，凡有写码环节即完整记录。两个数字共同指向的结论是：手撕在嵌入式 / Linux 应用岗面试中接近标配，且大量存在于一面。

在 18 份"无手撕"样本中，比亚迪、紫光展锐、瑞芯微、兆易创新、宇视、荣耀、商汤、美的、格力、海信、影石等占多数，集中在 SoC 原厂与部分家电车企，这类公司更偏向八股加项目深挖。

（二）环节形式与时长

现场手撕的具体形态包括四种：面试官口述题目、候选人投屏或共享屏幕写码（最常见）；纸上手写（多见于老牌厂与线下场）；本地 IDE 写码后讲解（大疆、Momenta、TP-Link 等）；发送 LeetCode 链接在线编程（蔚来提前批、蚂蚁等）。笔试编程则是独立的前置门槛，小米、华为、大疆、荣耀、乐鑫、海尔等均有"选择题 + 2 道编程题"的牛客体系笔试记录，采用核心代码模式（只写功能函数，不管输入输出）。单场手撕时长从 10 分钟到 45 分钟不等，联发科曾有"42 分钟手撕三道题"的记录，CVTE 二面为"写半小时代码"。

（三）考察方式的三段式特征

从样本原文看，手撕环节普遍遵循"写代码 → 讲思路 → 追问"的三段式：写完后面试官要求口述时间 / 空间复杂度；追问边界条件（空链表、单节点、内存重叠、溢出）；追问优化或场景变体（如大疆问"窗口扩大到很大怎么优化""浮点累加精度问题怎么办"，华为问"中断里写、任务里读怎么保证数据不乱"）。这意味着手撕题的评分标准不仅是"写对"，还包括复杂度表述、边界意识与工程变体应答。

（四）难度分层

样本中的手撕题可清晰分为三档。基础档（占绝大多数）：单链表反转、strcpy / memcpy 手写、冒泡 / 快排、大小端判断、宏定义等，要求一遍写对并讲清复杂度。进阶档：两个栈实现队列、LRU、生产者消费者、线程安全单例、IP 转换、TopK、层序遍历、LCA 等 LeetCode 中等题。冲刺档（出现于消费电子与互联网对口岗）：JSON 字符串转对象（小米）、扫雷随机布雷（小米）、132 模式（小米汽车）、字符串乘法（CVTE）、无锁 SPSC 环形缓冲区（微软）、最小覆盖子串（微软）等。样本中未出现 LeetCode hard 级别的死磕型题目，"写得对 + 边界清 + 复杂度说得准"是普遍预期。

（三）题型分布的结构性特征

第一梯队（出现于 35% 以上样本）只有两类：链表操作与字符串 / 库函数手写，且两者高度同源——链表题考指针操作与边界，库函数题考内存模型与边界。第二梯队（20%—26%）为数组矩阵、嵌入式特色题、位运算、排序、C++ 类、C 语言基础，构成"广度扫盲"层。第三梯队（10%—17%）为动态规划、二叉树、数学题、并发、代码改错，属于区分度层。栈与队列、图与几何占比最低，说明纯算法竞赛型题目在嵌入式岗位面经中密度很低。

四、高频考点考法解析

以下对 Top 10 考点给出典型原题、考察意图与常见丢分点。

单链表反转（26 次，绝对第一）。典型原题："手撕：反转单链表，要求递归和非递归都写"（小鹏、蔚来、腾讯等多家）。考察意图：指针操作基本功、空链表与单节点边界、递归深度意识。丢分点：头结点更新丢失、递归写法对长链表可能栈溢出（嵌入式场景下面试官可能因此更推荐迭代写法）。

链表判环与找入口（15 + 4 次）。典型原题："判断链表有环，并找入环节点"（小米、大疆、滴滴）。考察意图：快慢指针、Floyd 算法变体。丢分点：只会判断有环不会找入口；说不清快慢指针的相遇数学原理。

环形缓冲区 / 循环队列（11 次，嵌入式特色题首位）。典型原题："写一个固定大小的环形缓冲区，不允许动态申请内存，要支持写入、读取，还要能判断空和满"（华为终端 BG）；"实现一个环行 BUFFER，包含初始化，读，写函数"（多家题库）。考察意图：嵌入式内存受限思维、读写指针回绕、空 / 满判定（牺牲一个槽位或维护计数）、中断与多线程下的并发安全（volatile、原子操作、单生产单消费者是否加锁）。丢分点：取模写法正确但不解释空满二义性；不谈并发安全。

strcpy 手写（10 次）。典型原题："不用 C/C++ 字符串库函数，编写函数 strcpy()"（大华笔试）；"strcpy 的返回值是什么？如果让你实现 strcpy(char *src, char *dest, size_t t)，如何实现"。考察意图：字符串结尾处理、返回值语义、参数顺序与 const 正确性。丢分点：忘记返回目标指针；不检查内存重叠（strcpy 本身不保证重叠安全，面试官常追问与 memmove 的对比）。

memcpy / memmove 手写（9 次）。典型原题："用 C 实现自己的 memcpy() 函数？写出来后让再换一种高级写法"（CVTE）；"一道改错题：memcpy()、数组变量作返回值"（乐鑫）。考察意图：内存重叠判断（目标在源之后且区间相交时须反向拷贝）、按字优化、void 指针算术。丢分点：只写正序拷贝不讲重叠；不知道 memmove 与 memcpy 的区别正是重叠安全。

冒泡与快速排序（9 + 8 次）。典型原题："在纸上写下快排，再讲下快排思路"（联发科）；"写一个快排。能否用非递归方式实现；什么时候复杂度最大"（腾讯企业微信）。考察意图：排序手写是基础验收，快排还考分区逻辑、稳定性认知、最坏复杂度与避免手段。丢分点：快排分区写错；答不出快排不稳定的原因。

合并两个有序链表 / 数组（9 次）。典型原题："手撕：合并两个有序链表（手撕完继续八股拷打）"（海康实习）；"合并两个排序数组并去重"（字节）。考察意图：双指针协同、虚拟头结点技巧、从后往前填充的变体。丢分点：边界处理（其中一条先走完）；不会 O(1) 辅助空间的写法。

大小端判断 / 字节序转换（9 次）。典型原题："大端小端是啥？让我当场写段代码判断机器是大端还是小端"（地平线）；"写一个函数判断大小端，或者写一段代码把一个 32 位整数的字节顺序反转"（多份题库）。考察意图：联合体法、指针强转法、网络字节序转换的工程动机（多传感器数据总线上传）。丢分点：只会一种写法；说不清为什么通信协议要约定字节序。

链表插入 / 删除（8 次）。典型原题："会什么数据结构（二叉树、链表、队列、栈），手写链表的插入，中间插入"（海康）；"实现单链表的插入和删除"（华为 C++ 岗）；"双链表节点插入：插在指定节点前面 / 后面"（联发科）。考察意图：双链表 prev / next 双向维护、O(1) 删除的拷贝值技巧。丢分点：双链表插入漏掉一侧指针；不知道"删除节点可用后结点值前移"的 O(1) 变体。

MAX / MIN / SWAP 宏（7 + 4 次）。典型原题："手写一个宏求两数最大值。考虑过宏的副作用吗？"（小鹏）；"写一个宏定义 swap(x,y) 交换两个变量的值，不使用第三个变量"（多家）；"MIN(a++, b) 这种用法有什么问题吗"。考察意图：宏参数括号完整性、副作用、异或交换的局限（同一变量会归零）。丢分点：宏体不加括号；不知道 a++ 传参会被多次求值。

五、结论与备考建议

本章汇总五条核心结论，给出 P0 / P1 / P2 分级练习清单、四步验收标准，并与项目既有手撕训练序列做对照校准。

（一）核心结论

  1. 结论一：手撕代码是嵌入式 / Linux 应用岗面试的常规环节。出现率 86.6%，一面标配，部分二面、三面与笔试同样存在，必须以"必考项"而非"加分项"投入准备。
  2. 结论二：考点结构呈"两超多强"格局。链表（43.1%）与字符串 / 库函数手写（38.8%）为超级大类；数组、嵌入式特色题、位运算、排序、C++ 类、C 语言基础六个大类各占两成上下，构成一面广度扫盲的主体。二者共同指向同一能力内核：C 语言层面的指针与内存掌控。
  3. 结论三：嵌入式岗位有区别于通用软开的"签名题型"。环形缓冲区、滑动平均滤波、状态机、Makefile、socket 通信流程、协议解析等嵌入式特色手撕占 23.3%，其中环形缓冲区（11 次）与滑动窗口滤波（大疆三连问）最具岗位辨识度，且追问全部落在"不用动态内存、并发安全、大窗口优化"等工程约束上。
  4. 结论四：难度预期以"基础档一遍过"为主。Top 30 题目绝大多数不超出链表、字符串、排序、位运算、宏的基础组合；动态规划与 LeetCode 中等题占 16.4%，是冲击消费电子与互联网对口岗时的区分度来源，但并非嵌入式主战场的门槛。
  5. 结论五：存在明显的公司分层。终端与消费电子类（华为、大疆、小米、vivo、海康）手撕密度最高且题型最全；SoC 原厂与部分家电车企（比亚迪、展锐、瑞芯微、兆易、美的、格力等）样本中过半无手撕，以八股与项目深挖为主。投递结构决定了练习深度：主战安防与终端厂，基础档必须熟练到条件反射；若兼投互联网对口岗，需追加进阶档题库。

（二）分级练习清单

P0（必须条件反射级，12 项）：单链表反转（迭代 + 递归）、链表判环与找入口、strcpy 安全版、memcpy / memmove（含重叠）、合并两个有序链表 / 数组、大小端判断（两种写法）、环形缓冲区（含空满判定与中断并发追问）、冒泡与快速排序、MAX / MIN 宏与 swap 宏（含副作用）、置位 / 清零 / 翻转某位、二进制中 1 的个数（两种写法）、定长滑动平均滤波（不用动态内存）。

P1（应会，讲清思路并能写主体，10 项）：两个栈实现队列、层序遍历、LCA、生产者消费者、线程安全单例、IP 地址与整数互转、TopK、平方根（不用库函数）、LRU Cache、socket TCP 通信流程（函数序列）。

P2（冲刺档，按投递目标选修，6 项）：动态规划基础族（最大子数组和、爬楼梯、01 背包变形）、字符串进阶（最长无重复子串、最小覆盖子串、大数运算）、String / vector / 智能指针仿写、JSON 解析、无锁环形缓冲区（SPSC）、二叉树序列化。

（三）练习方法与验收标准

每题按四步验收：其一，白纸或纯文本编辑器一遍写对，不依赖 IDE 补全；其二，主动口述时间与空间复杂度，不等面试官问；其三，主动处理边界（空链表、单节点、内存重叠、整数溢出、并发访问）；其四，准备一个变体追问的应答（如"窗口很大怎么优化""中断里写任务里读怎么保证安全""不能用临时变量怎么交换"）。样本反馈显示，面试官对"写对但讲不清边界"的候选人给分明显低于"写法普通但边界完整"的候选人。

（四）与既有备考计划的对照

  项目既有手撕训练序列（strcpy 安全版 → memmove 重叠 → 链表反转 → 大小端，外加判环、循环队列、位操作、TopK）全部落在本报告的高频区内，方向正确。基于本轮数据建议两处调整：将"环形缓冲区"与"置位 / 清零"从应会提升为必会（华为、大疆、科大讯飞均有实测原题）；若投递大疆飞控类岗位，追加"定长滑动平均滤波"一题（该题在三份独立样本中重复出现，且追问链完整，属岗位强信号题）。
